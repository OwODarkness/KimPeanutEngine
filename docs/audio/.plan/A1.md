# A1 — Callback-safe audio foundation

Status: proposed. Parent: [audio roadmap](../TODO.md). Baseline:
[audio module](../audio_module.md). Open source findings:
[A1 review](../.review/A1.md).

## Scope and design

Keep the existing `Audio` target and miniaudio backend. Define one control
owner for player creation, playback commands, and destruction. The audio
callback reads only stable voice slots or a published immutable snapshot;
commands take effect at documented callback boundaries. A stop acknowledgment
or equivalent retirement epoch guarantees that a voice and its PCM remain
alive until the callback no longer references them. A handle's generation must
reject stale commands and a reused slot must create a fresh player state.
The public API should carry handles and copied state, not mutable
`AudioPlayer*` ownership across worker/UI threads. Migrate the current TTS
example through a temporary adapter and remove that adapter after A2.

Mix in blocks rather than doing a dry-stream lock and refill per output frame.
Use preallocated scratch and bounded command/telemetry buffers; no callback
logging, allocation, file/network I/O, or unbounded wait. Explicitly upmix
mono and handle supported channel/rate conversions once at a stated boundary.
Choose a fixed device format initially, and report actual device format and
latency. Speech and music have independent gain/mute and a master gain. A
short gain ramp handles start/stop/duck. Publish a played-frame cursor for
each voice and compact bus-level telemetry without blocking the callback.

`AudioStream::Finish` and every read/write/state transition must be
synchronized. A stream can be `Open`, `ProducerFinished`, `Cancelled`, or
`Drained`; temporary empty data is `Buffering`, not `Finished`. The consumer
must not silently drop queued speech. Overflow is an explicit result to the
producer, enabling A2 backpressure.

## Acceptance and validation

- [ ] Mono and stereo fixtures yield correct channels, gain, pause, seek,
  loop, and end states without out-of-bounds reads.
- [ ] Concurrent create/command/destroy with callback mixing passes the
  available sanitizer or stress harness, including slot reuse and shutdown.
- [ ] A dry stream yields silence with bounded callback work, then resumes
  from the next sample; producer completion drains queued frames exactly once.
- [ ] Callback work has a measured upper bound for the chosen voice count and
  buffer size; diagnostics identify underruns, overflow rejection, and actual
  played frames outside the callback.
- [ ] `cmake --build build --config Debug --target AudioUnitTest` and
  `ctest --test-dir build -C Debug -R AudioUnitTest` pass. Device smoke runs
  through the approved visible execution path, with clean stop/uninit.

No music library, TTS protocol, or UI behavior belongs in A1.
