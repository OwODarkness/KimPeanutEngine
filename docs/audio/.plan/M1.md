# M1 — Native music asset, import, and reimport

Status: active (M1.1 complete; M1.2–M1.4 pending). Parent: [audio roadmap](../TODO.md). Architecture:
[conversational audio](../PLANS.md) and [Asset plan](../../asset/PLANS.md).
P1 may keep its direct-file preview path while M1 is built; switching the
library to native products requires a bounded music decode path.

## Outcome and current boundary

An authored audio file and optional timed subtitle file become one immutable,
versioned native Audio product in the Asset archive. A project can address it
by a stable logical source path, inspect import status, reimport changed inputs,
and play a long track without retaining its entire decoded PCM. The player
shows subtitles from the actual played-frame clock. TTS network streams remain
independent of this product.

Today `AssetManager::LoadSync` selects `KPAT_Audio` for WAV/MP3/FLAC/OGG and
`MiniAudio_AudioLoader` decodes the whole file to an `AudioClip`. The player
controller calls that path, owns a session queue and waveform, and passes the
clip to a buffered Audio voice. `KimPeanutAssetTool import|reimport` currently
registers a model provider only. `ImportProviderRequest` carries one source
path; `ArchiveProductType` has Model, Material, and Texture, and the archive
probe names its source schema field `native_model_version`. No native Audio
product, subtitle association, or cooked music reimport exists yet.

## Ownership and lifecycle

| Owner | M1 responsibility |
|---|---|
| Asset import library and tool | Validate project-relative inputs, decode/inspect source on a worker, parse subtitles, cook waveform/metadata, write and reimport the native product. No `AssetManager` or audio device is needed to run the tool. |
| Asset archive and runtime loader | Own logical source identity, source/dependency hashes, import settings, immutable product location, product validation, and a lightweight loaded Audio resource. |
| Runtime Audio | Own a bounded file-backed decode worker, playback buffer, voice, Music bus, and authoritative source-frame cursor. It receives an immutable source descriptor and lifetime token, not an `AssetManager` pointer. |
| Player/Editor or conversation UI | Select assets, show import errors and copied waveform/cues, and render text. It never parses source files or reads callback-owned buffers. |

Source files remain editable under the Asset root. Archive products are derived,
content-addressed, and immutable. The active voice pins its source backing until
the Audio system acknowledges retirement; reimport publishes a new product for
the next play and never replaces memory or a file mapping under the callback.
Garbage collection cannot remove a product still pinned by a reader.

## Import command and request

The proposed CLI extends the existing command instead of adding a second
unrelated audio tool:

```text
KimPeanutAssetTool import --source music/theme.flac --importer audio \
  --subtitle subtitles/theme.en.srt --subtitle-language en
KimPeanutAssetTool reimport --source music/theme.flac
KimPeanutAssetTool reimport --source music/theme.flac --clear-subtitle
KimPeanutAssetTool status --source music/theme.flac
```

`--source` is required and Asset-root-relative. `--importer audio` is optional
once the audio provider owns the source suffix. On first import, omitted
`--subtitle` means no text. Verified v1 audio codecs are WAV, MP3, and FLAC;
OGG is deferred until the decoder build has a passing Vorbis fixture. The
product accepts one explicit UTF-8 SRT, WebVTT, or LRC track;
`--subtitle-language` defaults to `und` when text is present. LRC lyric lines
end at the next distinct timestamp (or the decoded duration); multiple
translations at the same timestamp share that interval.
Recognized LRC metadata tags are not rendered as lyric cues.
Do not infer a subtitle from a matching basename. A later multi-language
request can add repeatable track arguments after the current option parser is
changed to retain repeated values.

`reimport --source` reuses the recorded subtitle path, language, and cook
settings. `--subtitle` replaces that association; `--clear-subtitle` removes
it. Those two options are mutually exclusive. The current parser requires a
value after every option, so it must be extended for this explicit flag. A
missing previously associated subtitle is an error and leaves the last ready
product intact; it is not silently omitted. Record the association in archive
import options as well as in the dependency list so a later command can recover
it. Reject absolute paths, traversal, paths outside the Asset root, unsupported
extensions, duplicate/conflicting options, and oversized inputs before decode.
An external Editor file may remain a session preview until it is explicitly
copied into the project Asset root and imported.

Extend the provider request with typed audio options rather than storing
audio-specific strings in a generic map. Add `ImportProviderKind::Audio` and
register a provider for only codecs proven by decode fixtures. Return
`Imported` or `UpToDate`, normalized source identity, product hash/path, and
diagnostics. The Asset tool and an Editor import action call the same service;
the Editor dispatches it off the ImGui frame.

## Native product v1

Use a distinct `.audio` product under the content-addressed archive. The
canonical little-endian container has a magic, version, required-feature bits,
declared length, integrity digest, and a bounded chunk directory. Required
chunks are audio payload/codec metadata and duration/format; waveform peaks
are an import-time generated chunk. A timed-text chunk is optional and may be
absent. Reject overlapping/out-of-range chunk spans, duplicate required
chunks, unsupported required features, truncation, integer overflow, invalid
UTF-8, and invalid cue ranges before allocating their payloads. Unknown
optional chunks may be skipped; unknown required chunks fail.

The initial cook policy preserves a verified source encoding in a payload
that supports bounded range reads and seeking. Do not serialize a full float
`AudioClip` for music. Generate 384 min/max waveform buckets in a streaming
decode pass; cache them in the product and do not scan the song in ImGui.
Parse subtitles into ordered, half-open `[start_frame, end_frame)` cues in the
normalized 48 kHz playback timeline, with plain UTF-8 text and language tag.
Reject negative/reversed times and cues outside the verified decoded duration;
allow overlapping cues with deterministic ordering. Import must account for
codec delay/trim so waveform, duration, seek, and cues share one origin. If a
codec cannot meet that timing contract, leave it unsupported until verified.

Set explicit v1 bounds and test them: source at most 512 MiB, subtitle source
at most 8 MiB, duration at most four hours, at most 50,000 cues, and decoded
playback buffering at most 8 MiB per music voice. The importer must stream its
analysis and keep its working memory bounded independently of song duration;
adjust limits only with documented fixture evidence. Product serialization is
deterministic for equal inputs, settings, importer version, and schema version.

## Archive identity and reimport transaction

The logical key is the normalized audio source path, not a queue row or
product hash. Add `ArchiveProductType::Audio` to product paths, archive
validation, catalog mapping, status, diagnostics, and integrity checks. Evolve
the archive's model-named source schema field into a generic native-product
schema contract through a backward-compatible migration or a scoped audio
record; do not silently store an Audio version as a model version. Preserve
existing Model/Material/Texture archive records.

The import key covers the audio source hash, optional subtitle path/content
hash, language, codec/cook settings, importer ID/version, and native Audio
schema version. A normal `import` or `reimport` first checks recorded
dependencies and product metadata. An unchanged valid product returns
`UpToDate` without decoding or rewriting it. A source, subtitle, setting,
importer, schema, or missing/corrupt-product change triggers recook. A
subtitle-only edit may reuse a validated encoded-audio chunk and waveform,
but this optimization comes after the full recook path is correct.

Stage new bytes in a temporary product, validate and hash them, publish the
immutable hash-named file, then atomically replace the archive source,
dependency, options, and product associations. A crash, cancellation, decoder
error, or invalid supplied subtitle leaves the previous Ready association
playable and reports that the source needs attention. `status` distinguishes
`UpToDate`, changed input, missing input, missing/corrupt product, and failed
last attempt. Store failed-attempt diagnostics separately from the Ready
association so a failed import does not erase the playable product. Old
unreferenced products are reclaimed separately after active
readers have released them. Reimport never mutates a live product in place.

## Runtime and player migration

The native loader verifies the container off the audio thread, exposes a
lightweight Audio resource with copied metadata, waveform, and cues, and
hands Audio an immutable encoded-source descriptor plus a lifetime token.
Register `.audio` in the Asset type registry and resolve a logical music key
through the archive to this loader; raw source suffixes remain on the direct
preview path during migration.
Full product integrity verification runs on a worker before the asset becomes
Ready; a fast archive metadata probe alone is not reported as byte-verified.
The music decode worker reads bounded encoded ranges, converts to the mixer
format, and fills a bounded ring ahead of the callback. The callback performs
only bounded memory copies. Seek invalidates old queued frames, repositions
the worker, and resumes from the requested source frame without publishing
stale samples; pause does not advance the clock. Loop and 0.5–2.0x rate use
the same source-frame convention as timed text. On underrun, report Buffering
and retain the current cue until consumed playback advances or stops.

Keep the existing direct-file/fully buffered player as an explicit preview
and short-clip compatibility path during migration. Project music library
entries use the stable logical Asset key and native product after the runtime
path passes validation. Queue selection and reimport do not own or destroy
the active voice; the controller retires the handle before dropping its source.
TTS streams and their cancellation path are unchanged.

## Implementation order and gates

1. **M1.1 — import contract:** Add typed audio request/provider, CLI options,
   source validation, subtitle parser, codec fixtures, and deterministic native
   serializer/deserializer. Prove malformed-product and malformed-subtitle
   rejection before archive publication.
2. **M1.2 — archive/reimport:** Add Audio product type, recorded import options,
   dependency hashing, no-op probe, staging/atomic publication, `status`, and
   integrity/catalog support. Prove an interrupted or failed reimport retains
   the last Ready product and does not rewrite it on a no-op.
3. **M1.3 — bounded playback:** Add native runtime loader and seekable decode
   worker, source lifetime pinning, cache/clock contract, and cue query. Prove
   memory independent of duration and callback safety in offline tests.
4. **M1.4 — Editor migration:** Add Import/Reimport and subtitle selection to
   the library, show product/source state, consume cached waveform and cues,
   and keep external-file preview distinct. Test long-track, active reimport,
   device shutdown, and visible playback with subtitles.

## Acceptance and validation

- [ ] Import with and without subtitles produces one validated Audio product;
  optional text is absent when not supplied, and explicit invalid text fails.
- [ ] Reimport with no changes returns `UpToDate` with the same product hash and
  no decode/write. Changing either input or settings recooks and updates the
  dependency record; the product hash changes when the cooked bytes change.
  `--clear-subtitle` removes only the optional track.
- [ ] Missing input, corrupt product, cancellation, and fault-injected commit
  failure preserve the previous Ready association and expose a useful status.
- [ ] Old Model/Material/Texture archives remain readable after the schema
  extension; catalog and integrity checks recognize Audio products.
- [ ] A long fixture plays, seeks, pauses, loops, and changes rate with bounded
  memory; its waveform and cue transitions follow the played source frame.
  Reimport during playback does not replace the active source or leak a voice.
- [ ] Asset import/serialization/reimport tests and Audio clock/lifetime tests
  pass. Because archive schema, public Asset types, and tool wiring change,
  run a full Debug build and CTest suite. Launch the matching Debug Vulkan
  editor outside the sandbox on the Default desktop for visual and audible
  evidence; use RelWithDebInfo only for import/playback performance figures.

No implementation or validation is claimed by this proposed stage plan.
