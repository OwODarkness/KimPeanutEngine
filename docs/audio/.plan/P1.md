# P1 — Standalone cyberspace audio player

Status: active. Parent: [audio roadmap](../TODO.md). Foundation: [A1](A1.md).
The integrated conversation demo also depends on [C1](C1.md). Visual reference:
[audio_gui.png](../../../save/audio_gui.png).

## Goal and current boundary

Make `--mode audio-player` a useful local audio player in the Editor. Follow
the draft's six dock-window structure: Library and Playlists on the left,
Now Playing and Queue in the center, and Info and Spectrum on the right. Use
the Editor dock host to manage and rearrange the six windows. Keep the Editor's
window chrome and omit the draft's standalone branding header.

The mode now has an `AudioPlayerHost`, `AudioPlayerEditor`, and a separate
Audio-module controller. It imports local tracks, manages a session queue,
plays and seeks buffered audio, and draws a measured waveform from decoded
PCM. The six dock windows include an explicit static waveform preview when no
track is loaded; preview controls remain disabled. Remaining P1 work includes
broader playback/device verification and the separate Speech status/ducking
integration.

## Ownership and component contract

| Owner | Responsibility |
|---|---|
| Asset | Validate local paths and decode supported files into CPU `AudioClip` data; report format and decode failures. |
| Runtime Audio | Own device, voice slots, callback-safe commands, played-frame clock, buses, and telemetry. |
| `engine/module/audio` | Own a reusable playback component: voice handle, immutable clip reference, controls, copied state; own the standalone ImGui player view. |
| Editor | Host the mode and ImGui frame; own presentation-only state such as search and pane layout. |
| TTS / conversation | Supply speech clips or stream handles and display metadata; own provider jobs, turn IDs, and cancellation. |

The proposed playback component accepts a decoded clip plus title, source
label, and Audio bus. It exposes Play, Pause, Resume, Stop, Seek, volume, and
a `PlaybackSnapshot` containing state, played time, known duration,
seekability, and error. A component instance represents one voice. The
standalone player uses a Music instance; the future conversation surface uses
a separate Speech instance, so speech never replaces the local track. The
component destroys its handle before releasing the clip and before device
shutdown. The UI never reads callback-owned PCM or retains a raw player
pointer. This is a design contract, not a prescribed C++ signature.

## Layout and interaction

| Region | Content |
|---|---|
| Library | Real categories and counts, visible Add File/Add Folder actions, and recent items only after they are tracked. |
| Playlists | Session queue entry; do not imply persistent playlists before they exist. |
| Now playing | Art placeholder, title/source, decoded format, waveform, played cursor, elapsed/total, previous, play/pause, next, stop, seek, and volume/mute. |
| Queue | Search, selected row, duration/source, double-click to play, remove, clear, and empty/filter feedback. Clip hundreds of rows with `ImGuiListClipper`. |
| Info | Selected track metadata, output device details, Music/Speech status, and actionable errors. |
| Spectrum | Show measured spectrum data only when Audio exposes bounded telemetry; never draw synthetic levels. |

Place import actions in Library, queue actions and status in Queue, and loop
and shuffle controls with Now Playing. Do not add a separate header or footer
window to the six dock regions.

Use centralized dark navy surfaces, high-contrast cyan for selection and
playback, and amber for the played position and warnings. Keep the draft's
spacing and hierarchy without decorative controls that have no behavior.
Scope the Audio Player palette and monospace content font to each panel body;
keep the shared Editor window frames, tabs, and dock host on their existing
theme. The Spectrum body may map normalized source FFT bins to a relative dB
display, but must not label its short analysis window as calibrated device
output or imply unsupported low-frequency resolution.
The art placeholder may use an ImGui draw list. Build the waveform once from
a bounded reduction of decoded PCM on the control side. Defer a spectrum
display until Audio provides bounded, downsampled telemetry; never animate
fake levels or inspect the callback buffer. Display original bit depth only
if the importer preserves it; the current loader decodes to float PCM.

## State rules

| State | Required behavior |
|---|---|
| Empty queue | Explain import; disable transport and seek; label any static layout sample as a preview, never as measured track data. |
| Importing/decoding | Show progress or busy state; keep ImGui responsive; reject oversized inputs before decode. |
| Ready/paused | Show selection and known duration; Play/Resume is keyboard reachable. |
| Playing | Cursor follows the played-frame clock after seek and loop; Music volume affects only the Music voice. |
| Buffering/unknown duration | Show the real state and disable seeking for unseekable sources. |
| Finished/cancelled | Keep the last track inspectable; apply queue mode once. |
| Device/decode error | Show a reason near the failed action and allow retry without losing the queue. |

Open files and folders through a native picker or Editor-owned dialog, with a
text path as fallback. Do not decode large files on the ImGui frame. The
first supported formats can be WAV, MP3, OGG, and FLAC if each is verified
against the existing miniaudio loader. Keep the queue session-local for P1.
“Play once” stops at the end, “loop track” repeats only the selected clip,
and “shuffle” avoids an immediate repeat when more than one track exists.

## Implementation sequence

1. Add the playback controller and copied snapshot in `engine/module/audio`.
   Keep the existing `EditorAudioComponent` available as diagnostics.
2. Add bounded Asset-backed import, Music bus playback, transport, seeking,
   volume/mute, and device recovery. Prove these before styling.
3. Build the ImGui workspace and queue from the draft with unique IDs,
   keyboard navigation, visible focus, responsive layout, and empty/error
   states. Add the precomputed waveform.
4. Attach a separate Speech source for C1/TTS. Duck Music only while Speech
   is audibly consumed and recover with a measured ramp, preserving the
   user's Music gain and mute choice.
5. Validate runtime and teardown on the visible desktop. Defer persistent
   library and remote streaming until local playback and speech coexist.

## Acceptance and validation

- [ ] Import, decode failure, empty/filter state, selection, removal, and
  clear behave predictably with long names and hundreds of rows.
- [ ] Playback, pause/resume, seek, volume/mute, end, loop, shuffle, reload,
  and device shutdown leave no stale handle or audible click.
- [ ] Speech and Music remain independently controllable; interruption clears
  speech without replacing the selected local track.
- [ ] Ducking begins with audible Speech and recovers after silence, pause,
  cancel, or completion without changing stored Music volume.
- [ ] Visual review at narrow/expanded widths and 100–200% scaling shows
  readable labels, focus, disabled controls, and accurate progress. Compare
  with the [draft](../../../save/audio_gui.png) and record deliberate simplifications.
- [ ] Debug editor and focused Audio tests pass. Launch the matching Debug
  executable with Vulkan validation enabled outside the sandbox on the
  Default desktop, verify the GLFW30 foreground window, capture under
  `save/screenshots/validation/`, and test audible playback with a known
  fixture. Record graphics API, validation state, working tree, and device
  state in the journal.

No playlist database, remote stream, or persistent library is required for
P1.
