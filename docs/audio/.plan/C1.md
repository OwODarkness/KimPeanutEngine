# C1 — Conversation and speech session

Status: proposed. Parent: [audio roadmap](../TODO.md). Dependency:
[A2](A2.md).

## Session boundary

The application composition layer owns `ConversationSession`, not Runtime
Audio or Live2D. A replaceable `IResponseSource` takes a typed user turn and
emits ordered text deltas, optional emotion intent, completion, or failure.
Start with an in-process deterministic fake/script source. A later remote LLM
adapter implements the same contract and owns its connection, credentials,
history limits, and content policy. Keep transcript storage opt-in and outside
Audio/TTS. The UI sees a copied session snapshot and events on its own thread.
Its first Editor surface has a scrollable transcript, text entry, Send/Stop,
a voice preset selector, and explicit thinking/speaking/buffering/error
states. Provider reference paths and prompts stay in preset configuration,
while the panel displays only voice names.

Each turn receives a generation ID. The session appends response deltas to
visible text, splits only at stable sentence/punctuation boundaries, and
queues segments to TTS in order with bounded lookahead. At response end it
flushes the trailing segment. Avoid speaking an unstable partial token that
might change. The current segment can play while later text is generated, but
newer audio never overtakes older audio. If segmentation stalls, a bounded
length/time rule flushes a phrase with a diagnostic. A turn owns the set of
speech job/voice tokens; interruption cancels that set and resets subtitle,
mouth, and emotion presentation for the old generation.

Expose user-facing states `Idle`, `Thinking`, `Speaking`, `Buffering`,
`Interrupted`, `Completed`, and `Failed`; map lower-level provider states to
these consistently. Text-only mode remains useful if TTS fails. Without
Live2D, voice output and the player panel continue. The application passes
only a narrow `SpeechPresentationFrame` (turn, audible time, envelope, state,
text/emotion intent) to optional Live2D/UI adapters.

## Acceptance and validation

- [ ] Deterministic reply source demonstrates text arriving before final
  response, ordered speech segments, one coherent transcript, and usable
  Send/Stop/voice selection controls.
- [ ] New-turn/barge-in tests inject late text/TTS events and prove no old
  subtitle, voice, emotion, or mouth event becomes visible or audible.
- [ ] TTS failure preserves readable text and clear status; response-source
  failure ends the turn without leaked voice/worker state.
- [ ] A single visible demo joins text, TTS, Audio, optional Live2D, and the
  player; record first-text and first-audio latency under stated conditions.

Microphone/STT and a particular LLM are separate adapters, not C1 gates.
