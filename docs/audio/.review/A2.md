# A2 baseline review — TTS and streaming decode

- Review date: 2026-10-01
- Baseline: `fd1b163` plus the current working tree; no TTS or Audio source
  changes were present in `git status --short` at review time.
- Scope: `engine/module/tts`, `AudioStreamDecoder`, TTS example and tests,
  against the [A2 design](../.plan/A2.md) and [A1 review](A1.md).
- Method: static source and call-path inspection. No provider/server request
  or audible runtime run was made. Findings are open until exercised and fixed.

## Findings, in repair order

### A2-F01 [P0, open] TTS worker lifetime is not RAII-safe

`Initialize` starts a `std::thread` before returning the provider's result at
[`tts_system.cpp:40–65`](../../../engine/module/tts/tts_system.cpp#L40).
`~TTSSystem` does nothing at
[`lines 196–198`](../../../engine/module/tts/tts_system.cpp#L196).
Destroying an initialized system without explicit `ShutDown` leaves a
joinable thread and calls `std::terminate`. If provider initialization fails,
`initialized` and the worker remain active despite `Initialize` returning
false. Make initialization transactional and destruction idempotently stop and
join the worker. Test failed initialization, normal destruction, and repeated
shutdown.

### A2-F02 [P0, open] Fragmented WAV headers can be read beyond received data

`ParseHeader` checks only that a chunk's eight-byte header is present at
[`audio_stream_decoder.cpp:97–124`](../../../engine/runtime/audio/audio_stream_decoder.cpp#L97).
It reads 16 bytes of `fmt ` payload without checking that those bytes have
arrived. HTTP can split inside that chunk. Integer fields are read by
`reinterpret_cast` from byte storage, which also assumes alignment and native
endianness. Require a complete bounded chunk before parsing, read little-endian
fields safely, validate `fmt` length/ranges, and distinguish `NeedMoreData`
from `InvalidData`. Test every split point through the header and malformed
chunk sizes.

### A2-F03 [P1, open] Failed streaming HTTP responses are reported as success

The receiver forwards body bytes before response validation at
[`gpt_sovits_tts.cpp:92–104`](../../../engine/module/tts/gpt_sovits_tts.cpp#L92).
The following `if (response)` always calls `OnFinish` and returns true at
[`lines 106–120`](../../../engine/module/tts/gpt_sovits_tts.cpp#L106),
including non-200 responses. The status check below it is unreachable for a
non-null response. An error body can enter the WAV decoder and the job is
marked successful. Validate status/content type before publishing audio (or
quarantine bytes until headers are available), report bounded error details,
and test non-200/JSON responses.
The vendored cpp-httplib exposes a response-header callback for `Get`, but
its streaming `Post` overload at
[`httplib.h:2203`](../../../third_party/httplib/include/httplib/httplib.h#L2203)
does not take one. A repair must select a supported header-first request path
or quarantine the received body; do not assume the current `Post` overload
can validate headers before invoking its content receiver.

### A2-F04 [P1, open] Decode and callback failures are discarded

The TTS streaming callback ignores `decoder.Feed` and always returns true at
[`tts_system.cpp:135–140`](../../../engine/module/tts/tts_system.cpp#L135).
`Feed` returns false both for a valid incomplete header and an invalid one at
[`audio_stream_decoder.cpp:39–63`](../../../engine/runtime/audio/audio_stream_decoder.cpp#L39).
The provider ignores `OnData`'s bool at
[`gpt_sovits_tts.cpp:92–97`](../../../engine/module/tts/gpt_sovits_tts.cpp#L92),
and buffered synthesis ignores its `OnData` result at
[`lines 76–82`](../../../engine/module/tts/gpt_sovits_tts.cpp#L76).
A malformed/unsupported stream can therefore return success with silence;
failure does not reliably mark the stream terminal. Use a tri-state decoder
result, propagate abort/failure, close or cancel the stream on every exit,
and distinguish network EOF from audible completion.

### A2-F05 [P1, open] Decoder does not preserve channel frames or resample phase

`DecodePCM` groups complete **samples**, not complete channel frames, at
[`audio_stream_decoder.cpp:170–211`](../../../engine/runtime/audio/audio_stream_decoder.cpp#L170).
If a stereo HTTP chunk ends after one channel sample, it erases that sample
but pushes only whole frames, shifting all later channels. `ResampleLinear`
operates on the interleaved sample vector and restarts its phase for every
chunk at [`lines 7–36`](../../../engine/runtime/audio/audio_stream_decoder.cpp#L7),
mixing channels and losing/gaining time at chunk boundaries. The TTS path
always constructs a mono output stream at
[`tts_system.cpp:120–127`](../../../engine/module/tts/tts_system.cpp#L120),
so it never verifies that decoded channels match the destination. Preserve
partial frames and per-channel resampler phase; explicitly convert channels
to the chosen output format. Test mono/stereo, rate conversion, and arbitrary
chunk partitioning against one-shot decode.

### A2-F06 [P1, open] A cancelled or failed response can block the worker

There is no per-job cancellation, the task queue is unbounded at
[`tts_system.cpp:182–194`](../../../engine/module/tts/tts_system.cpp#L182),
and shutdown drains queued tasks before breaking at
[`lines 91–111`](../../../engine/module/tts/tts_system.cpp#L91).
`ShutDown` joins the worker before calling `provider_->ShutDown` at
[`lines 67–88`](../../../engine/module/tts/tts_system.cpp#L67),
so the provider is not asked to interrupt an active HTTP read before join.
With the configured read timeout, shutdown and a new conversational turn may
wait for old synthesis. Add job tokens, queue limits, provider abort, and a
shutdown order that stops work promptly; test cancel during connect/receive
and with pending tasks.

### A2-F07 [P1, open] Audio dependency and result validity are unchecked

`audio_system` is an uninitialized public pointer at
[`tts_system.h:51–53`](../../../engine/module/tts/tts_system.h#L51),
then dereferenced before any guard at
[`tts_system.cpp:115–132`](../../../engine/module/tts/tts_system.cpp#L115).
The returned player is `dynamic_cast` without checking it, and synthesis may
run before `Initialize` or after `ShutDown`. `TTSResult::error_code` is not
initialized at [`types.h:38–44`](../../../engine/module/tts/types.h#L38),
and error callbacks only log, so `success` describes the provider call rather
than a playable voice. Require an initialized Audio binding and a valid
provider/job state, propagate typed failures, and return an invalid handle
on failure.

### A2-F08 [P2, open] TTS example is not a lifecycle or integration check

The example uses an absolute machine-local reference path and spins forever
after synthesis at [`tts_example.cpp:16–46`](../../../engine/example/tts/tts_example.cpp#L16).
There are no TTS unit tests, and the current audio test does not decode or
play a fixture. Replace this example's validation role with a fake-provider
contract suite and a bounded visible smoke run; retain any manual demo as an
explicitly optional tool. Avoid committing personal voice data as a fixture.

## Coverage and disposition

No build, CTest, live HTTP request, or engine launch was run for this static
review. Fix F01/F02 before any repeated or malformed-stream testing, then
F03–F07 before integrating conversation or Live2D. An A2 implementation
review should record actual fake-provider tests, real-service compatibility
against a pinned GPT-SoVITS revision, audible drain, and shutdown evidence.

## A2 implementation follow-up — 2026-10-01

The provider API now carries a job token and cancellation predicate. GPT-SoVITS
uses a request-local HTTP client tracked as the sole active job; `Cancel(token)`
stops that client, and callbacks reject bytes after cancellation. `TTSSystem`
returns a token from `AsyncSynthesize`, exposes `Cancel`, copied event draining,
and active/recent telemetry, and monitors Audio playback independently of the
serialized synthesis worker. `Completed` follows `AudioState::Finished`; a
successful network-finished event precedes it. `InitializeWithProvider` enables
deterministic contracts without the live service.

Validation: Debug `TTS`, `TTSExample`, and `TTSUnitTest` targets build. Both
`TTSSystemTest` cases pass: active plus queued cancellation each produce one
callback and one Cancelled event, and a buffered fake WAV emits Completed only
after mixer drain, after NetworkFinished. No visible runtime/service playback
was performed; broader HTTP status/media, malformed stream, flow-control, and
late-callback stress contracts remain open.
