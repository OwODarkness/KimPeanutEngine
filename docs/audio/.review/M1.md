# M1 review — project music discovery from Content

- Review date: 2026-10-02
- Baseline: `53a731e` plus the current working tree. The existing P1 review and
  progress-bar work were left intact.
- Scope: `KimPeanutAssetTool import --source ...`, Audio import publication,
  Content catalog capture, and standalone Audio Player library/queue behavior.
- Parent: [M1 plan](../.plan/M1.md), [audio roadmap](../TODO.md), and
  [Asset architecture](../../asset/PLANS.md).
- Method: static source-path and ownership review, plus read-only inspection of
  the project `content/` layout. The review was followed by implementation;
  affected RelWithDebInfo targets compile. CTest and visible runtime acceptance
  remain pending.

## Assessment

The native Audio product is already placed **inside** Content's derived archive:
the tool defaults to `content/.archive`, and an Audio product has the path
`content/.archive/audio/<hash>.audio`. That does not make it a discoverable
project music entry. The Content catalog enumerates visible `.kpmeta` records,
skips `.archive`, and the Audio import path does not write an Audio content
record. The player currently searches only its session queue and cooks chosen
external files into `save/audio_player/`. The requested flow therefore needs
an Asset-owned publication/discovery bridge and a project-music Library view.

The authored source and derived product have distinct homes. The current CLI
requires `--source` to be relative to `asset/`: for example, an authored
`asset/music/theme.flac` is imported with `--source music/theme.flac`. Import
does not copy an arbitrary `D:\music\...` file into the project. A visible
Content entry should be a `content/audio/...kpmeta` record that points to the
immutable `.audio` product; the product itself remains in `.archive`.

## Recommended first slice

```text
asset/music/theme.flac  [authored source]
  -> KimPeanutAssetTool import --source music/theme.flac --importer audio
  -> content/.archive/audio/<hash>.audio + archive source record
  -> content/audio/music/theme.flac.kpmeta  [stable ContentID -> product hash]
  -> Asset-owned catalog snapshot -> Audio Player Project Library
  -> select/queue -> AssetManager loads native product -> Music voice
```

The exact Content path should follow the existing deterministic Model naming
rules and remain stable across reimport. Import/reimport must report an error
if Content metadata publication fails and leave a recoverable state; a Ready
metadata record must never point at a missing product. On no-op, verify the
metadata still matches the archive product rather than assuming it exists.

At player startup, show project music discovered from the Asset snapshot even
when the session Queue is empty. Searching the Library filters project entries;
searching the Queue filters queued items. Selecting a Library item may enqueue
it, but discovery itself does not start playback or fill the Queue. External
file imports remain explicitly session-scoped. Runtime Audio receives a
validated product descriptor and voice; it does not scan Content or own Asset
catalog queries.

## Acceptance checks for implementation

1. Import `asset/music/theme.flac` via the tool, restart the player, and see
   one named Project Library entry without selecting a raw file or decoding it
   on the ImGui frame.
2. Queue/play that entry from the published `.audio` product. No duplicate
   `save/audio_player` import is created; external Add File still works.
3. Reimport after source/subtitle change keeps the same ContentID, updates the
   product hash, and lets an active voice finish against its pinned old product.
4. Missing metadata, stale/missing product, invalid source, and import failure
   produce actionable Library diagnostics without adding a broken queue item.
5. An explicit Refresh sees a CLI import made while the player is open; any
   automatic notification is tested separately and does not scan per frame.
6. Asset/Content tests cover metadata and catalog publication; player tests
   cover selection and queue identity. Visible Vulkan playback is validated
   outside the sandbox after implementation.
