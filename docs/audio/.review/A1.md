# A1 baseline review — Runtime Audio

- Review date: 2026-10-01
- Baseline: `fd1b163` plus the current working tree; no Audio source changes
  were present in `git status --short` at review time.
- Scope: `engine/runtime/audio`, audio data types and loader handoff, the
  existing audio unit test, and the [A1 design](../.plan/A1.md).
- Method: static source and call-path inspection. No code was changed and no
  executable or device was launched. Findings are open; impact is inferred
  from the cited paths, not measured runtime evidence.

## Findings, in repair order

### A1-F01 [P0, open] The playback device outlives its owner

[`MiniAudioSystem::Initialize`](../../../engine/runtime/audio/miniaudio_audio_system.cpp#L39)
initializes and starts `ma_device`, but `ShutDown` and the destructor at
[lines 58–60 and 136–138](../../../engine/runtime/audio/miniaudio_audio_system.cpp#L58)
are empty. A callback holds `this` in `pUserData` and calls `Mix` at
[lines 16–30](../../../engine/runtime/audio/miniaudio_audio_system.cpp#L16).
Destroying the system therefore leaves device/callback lifetime unresolved;
reinitialization also has no state guard. Add explicit stop/uninit, a single
idempotent lifecycle, and callback retirement before destroying mixer/player
storage. Test repeated initialize/shutdown and destruction while active.

### A1-F02 [P0, open] Mixer and control threads share mutable player storage

`Mix` iterates `players_` and reads player state at
[`miniaudio_audio_system.cpp:72–96`](../../../engine/runtime/audio/miniaudio_audio_system.cpp#L72).
`CreateAudioPlayer` can grow that vector and `DestroyAudioPlayer` resets a
player at [`audio_system.cpp:26–51`](../../../engine/runtime/audio/audio_system.cpp#L26).
`Play`, `Stop`, `SetVolume`, and `current_frame_` use ordinary fields at
[`audio_player.cpp:9–53`](../../../engine/runtime/audio/audio_player.cpp#L9).
The TTS receiver calls `player->Play()` from its worker path. Concurrent
create/control/mix can invalidate vector iteration or race on player fields.
Define one callback-safe command/voice-retirement boundary; a mutex around
some fields alone does not resolve pointer lifetime or callback timing.

### A1-F03 [P1, open] Mono data is read as stereo

The mixer branches on `out_channels` (fixed at 2), then reads `data[1]` at
[`miniaudio_audio_system.cpp:104–115`](../../../engine/runtime/audio/miniaudio_audio_system.cpp#L104).
The TTS stream is mono, and `GetFrameData` returns one mono frame. At a ring
boundary this can read beyond the valid sample; otherwise the right channel
is the next sample. Branch on **input** channels, explicitly upmix mono, and
validate a complete frame before returning data. Cover mono, stereo, and
last-frame fixtures.

### A1-F04 [P1, open] Stream frame pointer escapes its lock

`StreamAudioPlayer::GetFrameData` returns a pointer into `ring_buffer_.data`
after releasing `buffer_mutex_` at
[`stream_audio_player.cpp:23–41`](../../../engine/runtime/audio/stream_audio_player.cpp#L23).
`Play` and `SetStream` can reassign that vector at
[`lines 52–105`](../../../engine/runtime/audio/stream_audio_player.cpp#L52),
while `Mix` uses the pointer later. This is a possible stale pointer or
use-after-free even if the registry itself is synchronized. Keep sample
storage stable for the callback's read epoch or copy a bounded block under a
clear ownership rule. Also synchronize access to `stream_` in
`GetAudioFormat`/`GetStream`.

### A1-F05 [P1, open] Stream overflow silently removes speech and EOF races

`AudioStream::PushFrames` discards the oldest samples when full at
[`audio_stream.cpp:21–49`](../../../engine/runtime/audio/audio_stream.cpp#L21).
The producer receives no overflow result, so fast synthesis can silently
remove the beginning or middle of an utterance. `Finish` and `IsFinished`
read/write `is_finished` without the stream mutex at
[`lines 150–158`](../../../engine/runtime/audio/audio_stream.cpp#L150),
while producer and callback can run concurrently. Return explicit capacity/
backpressure outcomes and synchronize stream terminal state. Cover fast
producer, partial capacity, and EOF/drain transitions.

### A1-F06 [P1, open] Player destruction does not retire its handle

`DestroyAudioPlayer` calls only `Reset` at
[`audio_system.cpp:43–51`](../../../engine/runtime/audio/audio_system.cpp#L43).
It never calls `handle_system_.Destroy`, removes the player, or releases its
clip/stream. A supposedly destroyed handle remains valid and repeated TTS
jobs accumulate player slots and source memory. Retire the generation, stop
callback reads, then release the player; verify stale-handle rejection and
slot reuse without stale type/state.

### A1-F07 [P1, open] Callback work is unbounded under starvation

`Mix` calls `FillBuffer` on every missing frame at
[`miniaudio_audio_system.cpp:95–101`](../../../engine/runtime/audio/miniaudio_audio_system.cpp#L95).
That path takes the ring mutex, then the stream mutex; `ReadFrames` logs while
holding its mutex at [`audio_stream.cpp:93–145`](../../../engine/runtime/audio/audio_stream.cpp#L93).
The callback also logs when a voice finishes through `AudioPlayer::Stop`.
One dry voice may make thousands of lock attempts per callback block, while
producer logging/copying may delay it. Move refill to bounded block work and
publish diagnostics outside the device callback. Measure worst-case callback
time with multiple dry voices and a busy producer.

### A1-F08 [P2, open] Empty clips and unsupported format edges lack a contract

`BufferAudioPlayer::Play` checks only for a null clip at
[`buffer_audio_player.cpp:49–57`](../../../engine/runtime/audio/buffer_audio_player.cpp#L49).
An empty clip enters `Playing`, `Mix` sees no frame and never advances to a
terminal state; `ResolveFrame` also computes `frame_count - 1` at
[`lines 74–94`](../../../engine/runtime/audio/buffer_audio_player.cpp#L74).
The common mixer advances one source frame per output frame without rate
conversion, so a caller-supplied non-48 kHz clip plays at the wrong speed.
Reject empty/invalid formats and define conversion or a fixed-format input
invariant. Test seek/loop at zero and non-device sample rates.

## Coverage and disposition

[`audio_decode_test.cpp`](../../../engine/test/unit/audio/audio_decode_test.cpp)
contains a tautological test and a commented-out playback body. It provides
no evidence for mixer, stream, device lifetime, or concurrent control.
No `AudioUnitTest` execution was needed for this static review; running the
current tests would not exercise these findings. A1 should start with F01–F04
and F06, then F05/F07 before connecting live TTS. Review resolution requires
focused offline contracts and the approved visible device lifecycle smoke;
source edits or a build alone do not close the findings.
