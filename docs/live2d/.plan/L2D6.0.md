# L2D6.0 — Playback Contract Freeze

- Status: complete (2026-09-12) — [journal](../../../.spec/journal/2026-09-12-live2d-l2d6-0.md)
- Parent: [L2D6 — Authored Motion and Expression Playback](L2D6.md)
- Depends on: L2D5 acceptance evidence (L2D5 evidence remains incomplete; see
  the journal's remaining-work section)

## Goal

Freeze the authored-data, ownership, time, priority, fade, event, expression,
and parameter-update rules before changing the native product or constructing
SDK motion objects.

## Required investigation

1. Characterize the current V1 product codec/importer with a fixture containing
   two motion groups, model3 fade overrides, two named expressions, and one
   optional sound reference.
2. Record exactly which metadata survives today and prove that
   `optional_chunks` cannot recover typed identity without source knowledge.
3. Inspect the pinned R5 manager, queue, motion, expression, and update-scheduler
   source linked by the parent plan.
4. Run a small official-Framework probe for priority rejection, replacement
   fade, natural completion, cancellation, user-event ordering, expression
   transition values, and zero/large delta behavior.
5. Compare the probe with the checked-in Hiyori package and document which
   required cases need a synthetic redistributable fixture.

## Decisions to freeze

- Product V2 field bounds, deterministic order, V1 compatibility, and reimport
  diagnostic.
- Bounds and absence representation for opaque sound bytes retained directly
  by a motion definition; no Audio API is introduced.
- Positive priority domain, strict greater-than reservation, and force start.
- Exactly-once meanings of completed, interrupted, and cancelled.
- Maximum overlapping motion fades, expression transitions, pending events,
  and the non-mutating behavior at capacity.
- One primary motion channel and one logical expression channel.
- Expression restart/clear semantics and official blend calculations.
- Caller-supplied time validation and one-shot-only L2D6 behavior.
- Direct parameter-write checkpoint behavior and the canonical update order.
- Instance-local parsed SDK objects and destruction order.

## Deliverables

- A table of official input sequences and expected parameter/event outputs in
  the L2D6 implementation journal.
- Synthetic fixture requirements and redistribution status.
- Final public value/API sketch and product V2 limits.
- No production-code edit beyond test/probe scaffolding needed to close the
  semantic questions.

## Gate

Every parent-plan rule is either backed by pinned R5 source/probe evidence or
explicitly identified as KimPeanutEngine policy. No ownership, time, priority,
terminal-event, expression, product-compatibility, or update-order question
remains open before L2D6.1.
