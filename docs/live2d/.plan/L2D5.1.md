# L2D5.1 — Generic Host Capture View

- Status: complete (2026-09-12) — [journal](../../../.spec/journal/2026-09-12-live2d-l2d5-1.md)
- Parent: [L2D5 — V1 Evidence Completion and Viewer Closeout](L2D5.md)
- Depends on: [L2D5.0](L2D5.0.md)

## Goal

Close V1 acceptance item 8 by removing the Live2D name from Render's generic
capture contract, without introducing a host-view registry.

## Contract

- Rename `CaptureView::Live2D` to a role-named value for the standalone host's
  own output target, resolved by the host's capture-target resolver; it is never
  a deferred view and never resolved by the deferred pass sequence.
- Add a positive `IsDeferredCaptureView(CaptureView)` covering `SceneColor` and
  every diagnostic view. Replace the negative predicate at
  [`deferred_renderer.cpp:611-614`](../../../engine/runtime/render/deferred_renderer.cpp#L611-L614)
  with it, so adding a host view cannot silently change capture behavior.
- Keep the capture-target resolver seam unchanged: a host still supplies the
  handle for its own view, and Render still never learns what produced it.
- Update the Live2D viewer host's resolver and startup capture request to the
  new value. The viewer's behavior is unchanged.
- Apply L2D5.0's tooling-string decision to
  [`screenshot_command_provider.cpp:73`](../../../engine/runtime/screenshot/screenshot_command_provider.cpp#L73)
  and the command enum descriptor.
- No Live2D include, name, or branch may remain in
  `engine/runtime/render/` or `engine/runtime/graphics/`.

## Tests

- A Render-side test asserts every diagnostic view is deferred and that host
  views are not, so the predicate is pinned independently of any module.
- An existing capture test proves a host view still resolves through the host
  resolver and a deferred view still resolves through the pass sequence.
- A repository grep for a Live2D name under `engine/runtime/render/` and
  `engine/runtime/graphics/` returns zero matches.
- Existing Render, capture, and editor debug-view tests stay green.

## Gate

V1 acceptance item 8 passes; the Render and Graphics trees contain no Live2D
name; the viewer's capture behavior is unchanged on both backends. Only then may
L2D5.2 capture through this contract.
