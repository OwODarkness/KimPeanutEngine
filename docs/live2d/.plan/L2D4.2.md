# L2D4.2 — SDK-Free Model Extraction

- Status: landed (2026-09-10) — [journal](../../.spec/journal/2026-09-10-live2d-l2d4-2.md)
- Parent: [L2D4 — Live2D Planning and Generic Render Submission](L2D4.md)
- Depends on: [L2D4.0](L2D4.0.md)
- May run independently of: [L2D4.1](L2D4.1.md)

## Goal

Turn an evaluated `Live2DModelInstance` into validated, immutable semantic
values that the Live2D render planner can consume without calling Cubism or
AssetManager. This stage does not emit generic GPU commands.

## Data contracts

Add SDK-free types under `engine/module/live2d/runtime/`:

- `Live2DCanvasInfo` — width, height, origin, pixels-per-unit;
- `Live2DDrawableStatic` — vertex/index ranges, texture index, and canonical
  mask-source drawable indices;
- `Live2DStaticModelData` — topology revision, concatenated UVs/UInt16 indices,
  drawables, mask contexts, maximum position bytes, feature report;
- `Live2DDrawableState` — current flags/order/opacity/culling/blend/colors;
- `Live2DFrameSnapshot` — matching topology revision, monotonically increasing
  frame sequence, concatenated float2 positions, and drawable states.

Use owning `std::vector` and value types. Do not return Core arrays, `span`-like
views into the model, or references whose validity ends at the next Update.

## Instance creation and texture retention

1. Resolve dependencies in the product's ordered texture list.
2. Require each dependency to be a live built-in Texture asset.
3. Store `shared_ptr<const asset::TextureResource>` in the instance in exactly
   that order; never store raw `Asset*`.
4. Validate dependency count and every drawable texture index during static
   extraction.
5. Expose the retained list through a const SDK-free accessor suitable for
   transactional proxy creation.

This does not change Asset ownership rules. The payload `shared_ptr` preserves
CPU data lifetime; GPU copies become the render proxy's responsibility.

## Extraction algorithm

- Build static data once after Core model creation.
- Canonicalize equal mask-source lists to one mask context while preserving
  source order for mask drawing.
- Concatenate each drawable's UVs and indices without rewriting its local
  indices; record `vertex_offset` and `first_index`.
- After each successful `Update`, copy all drawable positions. Do not make V1
  correctness depend on `VertexPositionsDidChange`; that flag may support a
  later upload optimization.
- Copy current drawable properties and render-order values without sorting;
  `Live2DRenderPlanner` owns stable ordering in L2D4.3.
- Validate counts, finite values, local index bounds, texture indices, and
  mask-source indices before returning success.
- Reject R5 offscreen/blend-group usage and mask over-capacity before renderer
  creation.

## Concurrency and failure

The instance owner serializes parameter mutation, `Update`, and extraction.
Extraction builds into local temporaries and swaps into `out` only on success,
so failure cannot expose a partial snapshot. Renderer code may read the
resulting value concurrently only after the owner transfers or otherwise
synchronizes its lifetime; L2D4 does not add a queue or mutex.

The snapshot may name Live2D concepts because it is module-private semantic
input. Those concepts must disappear when L2D4.3 compiles the plan into
`render::RenderSubmission`; generic Render never consumes this type.

Diagnostics include drawable/context index and violated bound without leaking
raw SDK pointers.

## Tests

- two instances from one asset retain the same immutable payloads but yield
  independent parameters and position snapshots;
- static UV/index/range data is deterministic across instances;
- frame snapshots change after a parameter/update that deforms the fixture;
- equal render-order values are copied exactly for the planner's ordering test;
- invalid synthetic ranges, texture indices, NaN state, revision mismatch, and
  unsupported features fail atomically;
- destroying/unregistering the Asset wrapper after instance creation does not
  invalidate retained model/Texture payloads;
- public headers compile in a translation unit with no Cubism include path.

## Gate

`Live2DCoreTest` proves snapshot validity and instance isolation. No Graphics
handle or Cubism/native API type appears in the new public structures. Only
then may L2D4.3 consume them.
