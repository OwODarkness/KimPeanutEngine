# L2D6 — Authored Motion and Expression Playback

- Status: proposed
- Parent roadmap: [Live2D Module Roadmap](../TODO.md)
- Module architecture: [Live2D Module Plans](../PLANS.md)
- Execution spec: [Live2D Authored Playback](../../../.spec/specs/live2d-authored-playback.md)
- Entry gate: L2D5 has proved one loaded model through update, snapshot,
  submission, presentation, capture, resize, and clean shutdown

## Outcome

Load the motions and expressions authored beside a `.model3.json` source into
the native `.live2d` product, instantiate independent playback state for every
`Live2DModelInstance`, and expose deterministic, SDK-free control for motion
priority, cross-fades, cancellation, completion, expression transitions, and
motion events.

Playback changes Cubism model parameters only. It does not load files, select
render pipelines, emit render submissions, choose emotions, play audio, or
depend on Render, Graphics, Editor, Gameplay, or TTS.

```text
immutable Live2DModelResource
  motion/expression bytes + authored metadata
                 |
                 v
Live2DModelInstance (owner thread)
  instance-local SDK clips + managers + playback tokens
                 |
                 v
AdvancePlayback(delta_seconds)
  restore -> base writes -> motion -> save -> expression -> model update
                 |
                 v
existing SDK-free frame snapshot -> L2D4 render planning
```

## Design question

What is the smallest playback contract that preserves Cubism R5 motion and
expression semantics while keeping immutable Asset data shareable, mutable SDK
objects instance-local, time caller-controlled, and future L2D7–L2D9 parameter
contributors deterministic?

The answer is a versioned typed animation library in the Live2D product, an
instance-owned playback controller hidden behind the existing
`Live2DModelInstance` implementation, opaque value tokens, and one canonical
ordered parameter-update transaction. It is not a generic engine animation
system and does not expose Cubism motion pointers or queue-entry handles.

## Current-state delta

The existing product has exact MOC bytes, ordered Texture dependencies, and
named `optional_chunks`. The importer recursively treats miscellaneous string
values as source references. That representation cannot faithfully distinguish
motion group/index, expression name, file bytes, optional sound, and numeric
fade overrides. L2D6 must introduce a new product version with typed authored
animation descriptors; it must not infer semantics from optional-chunk names at
runtime.

The existing model instance owns only `CubismMoc`, `CubismModel`, static render
data, and a frame sequence. `SetParameterValue`, parameter queries, `Update`,
and frame extraction are already SDK-free public operations. L2D6 extends that
owner; it does not create a second model object or modify the L2D4 submission
boundary.

## Scope

In scope:

- deterministic import and native serialization of `.motion3.json` and
  `.exp3.json` files referenced by `model3.json`;
- motion group/index identity and unique expression-name identity;
- model3-authored motion fade-in/fade-out overrides;
- preservation, but not playback, of an optional authored motion sound;
- per-instance SDK motion/expression objects and managers;
- one primary motion channel with official priority reservation semantics;
- replacement cross-fades, explicit cancellation, completion, and authored
  motion-event delivery;
- bounded transition entries and pending event storage;
- one logical expression channel with official additive, multiply, overwrite,
  and transition behavior;
- caller-supplied deterministic time and a frozen parameter-update order;
- compatibility with direct parameter access and existing snapshot/rendering;
- malformed-product, isolation, lifecycle, and deterministic numeric tests.

Out of scope:

- random idle selection, automatic group selection, emotion/body-language
  mapping, behavior trees, or scheduling policy;
- physics, pose, eye blink, breath, gaze, hit areas, and user-data behavior
  beyond motion-event strings (L2D7);
- audio playback, lip sync, TTS, and interpreting motion sound files (L2D9);
- Editor controls, Gameplay components, scene integration, hot reload, and
  reimport UX (L2D10);
- arbitrary independent expression layers or a general animation blend graph;
- programmatic looping, reverse playback, seeking, time scaling, async clip
  parsing, and shared mutable SDK motion objects;
- any Render, Graphics, shader, or RHI change.

## Frozen architecture

### 1. Typed immutable product data

Add product-version-2 values equivalent to:

```cpp
struct Live2DMotionDefinition
{
    std::string group;
    std::uint32_t index = 0;
    std::vector<std::byte> motion_bytes;
    std::optional<float> fade_in_seconds;
    std::optional<float> fade_out_seconds;
    std::vector<std::byte> optional_sound_bytes;
};

struct Live2DExpressionDefinition
{
    std::string name;
    std::vector<std::byte> expression_bytes;
};

struct Live2DParameterGroupDefinition
{
    std::string name;
    std::vector<std::string> parameter_ids;
};

struct Live2DProductData
{
    // Existing fields remain.
    std::vector<Live2DMotionDefinition> motions;
    std::vector<Live2DExpressionDefinition> expressions;
    std::vector<Live2DParameterGroupDefinition> parameter_groups;
};
```

Names are UTF-8 byte strings and must be non-empty, bounded, and NUL-free.
Motion identity is `(group, index)` because `model3.json` does not author a
separate motion name. Motion-group object keys are serialized in canonical
bytewise order, while each group's motion array retains authored order.
Expression names are unique and expressions retain authored array order.
Parameter groups preserve their authored array order, `Target == "Parameter"`,
name, and ordered IDs so motion model curves can receive authored
EyeBlink/LipSync effect IDs now and L2D7/L2D9 need no source-file access later.

The importer validates every referenced file before publishing any Texture or
root product. It rejects path escape, missing or empty files, wrong JSON shape,
non-finite/negative authored fade overrides, duplicate expression/group names,
unrepresentable counts/sizes, and malformed motion/expression data. The
offline provider performs bounded structural JSON validation without linking
Cubism into AssetImport; instance creation performs the second, SDK-level
consistency check. Live2D remains responsible for both adapters.

Product V1 remains parseable as a model with an empty typed animation library.
It is never heuristically upgraded from `optional_chunks`; authored playback
requires reimport to V2 at a new explicit output path because L2D6 preserves
the existing immutable-product collision rule. In-place replacement remains
L2D10 work. V2 round trips byte-identically for a fixed input and retains
unknown optional chunks under the existing bounded rules.

### 2. Immutable bytes, instance-local SDK objects

`Live2DModelResource` shares immutable motion/expression bytes and metadata.
Each `Live2DModelInstance::Impl` transactionally creates its own
`CubismMotion`, `CubismExpressionMotion`, motion manager, expression manager,
queue entries, callbacks, and event scratch state.

SDK motion objects are not shared across instances. The official implementation
stores callbacks, last weight/model opacity, and fired-event scratch state on
the motion object, so sharing a parsed object would introduce races and
cross-instance mutation even when the source bytes are immutable.

L2D6 preloads all parsed clips during instance creation. A single invalid clip
fails creation without publishing the instance and destroys the complete
staged SDK closure. Lazy parsing and shared immutable curve IR require measured
evidence and remain later optimization work.

### 3. SDK-free public control contract

Add public value types equivalent to:

```cpp
struct Live2DMotionKey
{
    std::string group;
    std::uint32_t index = 0;
};

struct Live2DPlaybackToken
{
    std::uint64_t instance_serial = 0;
    std::uint64_t sequence = 0;
};

enum class Live2DMotionStartMode { RespectPriority, Force };
enum class Live2DStopMode { AuthoredFadeOut, Immediate };
enum class Live2DPlaybackEventKind
{
    MotionCompleted,
    MotionInterrupted,
    MotionCancelled,
    MotionUserEvent
};

struct Live2DPlaybackEvent
{
    Live2DPlaybackEventKind kind;
    Live2DPlaybackToken token;
    std::string value;
};

struct Live2DPlaybackUpdateResult
{
    std::vector<Live2DPlaybackEvent> events;
    bool motion_parameters_updated = false;
};
```

Required operations are equivalent to:

```cpp
bool PlayMotion(const Live2DMotionKey& key, std::int32_t priority,
                Live2DMotionStartMode mode, Live2DPlaybackToken& token,
                std::string& diagnostic);
bool StopMotion(Live2DPlaybackToken token, Live2DStopMode mode,
                std::string& diagnostic);
void StopAllMotions(Live2DStopMode mode) noexcept;
bool SetExpression(std::string_view name, std::string& diagnostic);
bool ClearExpression(Live2DStopMode mode, std::string& diagnostic);
bool AdvancePlayback(float delta_seconds,
                     Live2DPlaybackUpdateResult& result,
                     std::string& diagnostic);
```

Final names may follow repository conventions. Public headers contain no
Cubism type. `Live2DSystem` assigns every instance a non-zero serial and each
instance monotonically issues its token sequence. Tokens are never
pointer-derived, foreign-instance tokens are detectable, and all tokens become
invalid after instance destruction. Serial or sequence exhaustion is a stable
failure and never wraps. `{0, 0}` is the invalid token representation.

Control functions and `AdvancePlayback` run on the instance-owner thread. They
do not invoke user callbacks. Events are returned as owned values from the
advance call, preventing callback reentrancy and unbounded internal event
queues. Synchronous control events are staged until the next advance in fixed,
preallocated storage. Motion entries, expression-transition entries, and
pending events have limits frozen by L2D6.0; a control call that would exceed a
limit fails before mutating an SDK manager.

Completed, interrupted, and cancelled events carry their valid motion token.
The pinned R5 event callback supplies only the manager and authored string, not
the firing queue entry. `MotionUserEvent` therefore carries an invalid token in
L2D6; its string and callback order remain exact. Do not guess the current token
during a replacement fade or fork the SDK to manufacture source identity.

### 4. Motion semantics

Priorities are positive signed integers; zero means no active/reserved motion.
`RespectPriority` succeeds only when the requested priority is strictly greater
than both current and reserved priority. `Force` bypasses that comparison. A
rejected request changes no manager state and returns no token.

Starting a motion applies its model3 fade overrides when present, issues one
token, and triggers authored fade-out on all prior primary-channel entries.
Those prior tokens become `MotionInterrupted` when their fade-out finishes; the
new token becomes `MotionCompleted` only on natural non-looping completion.
Explicit stop yields `MotionCancelled`, after the authored fade or immediately
according to the requested mode. Each terminal event is emitted exactly once.

The SDK may overlap old and new queue entries during a cross-fade, but the
public abstraction remains one logical primary channel. L2D6 does not expose
queue-entry count or pointer identity. Authored motion-event strings are
delivered in SDK evaluation order without fabricated source-token identity.

### 5. Expression semantics

There is one logical expression channel. `SetExpression(name)` begins the new
expression and lets the official expression manager cross-fade the previous
entry. Multiple SDK queue entries may exist only as transition state; this is
not an arbitrary public layer stack.

Expression parameters retain official `Add`, `Multiply`, and `Overwrite`
behavior and authored/default fade times. Setting the already-current name is
defined as a restart, not a no-op. `ClearExpression(AuthoredFadeOut)` transitions
to the neutral contribution; immediate clear removes all expression entries.
Unknown names fail without disturbing the current expression.

### 6. Canonical update transaction

`AdvancePlayback` validates that delta time is finite and non-negative. It does
not read a clock, silently clamp, choose an idle motion, or introduce a fixed
step. L2D6 supports authored one-shot behavior only; loop policy is deferred.

Each successful call performs:

```text
1. LoadParameters()                         previous persistent checkpoint
2. apply pending direct/base parameter writes
3. motion manager UpdateMotion(delta)
4. SaveParameters()                         persist base + primary motion
5. expression manager UpdateMotion(delta)   non-persistent relative layer
6. CubismModel::Update()
7. collect exactly-once playback/user events
```

This ordering matches the official sample's motion checkpoint followed by
late expression evaluation and leaves one explicit insertion region between
steps 5 and 6 for L2D7/L2D9 contributors. Later stages must extend the ordered
transaction rather than independently calling `CubismModel::Update()`.

The existing `SetParameterValue` remains immediate for current tools/tests and
also records the latest pending base write. The next `AdvancePlayback` reapplies
that value after `LoadParameters` and persists it at step 4. Multiple pending
writes to one parameter collapse to the latest value. Parameter range checks
remain unchanged. Instance construction allocates one value/dirty slot per
parameter, so the existing `noexcept` setter performs no new allocation.

The existing zero-argument `Update()` remains the low-level no-playback path.
It returns failure while a motion or expression transition is active, preventing
a caller from bypassing time advancement or losing returned events. Viewer and
future behavior code use `AdvancePlayback` once authored playback begins.

Snapshot extraction remains a separate operation after a successful update.
It never advances playback and repeated extraction never changes parameters or
emits events.

### 7. Failure and lifetime

- Every public failure leaves output values cleared and current playback usable.
- Invalid/non-finite delta time changes no clock, queue entry, parameter, token,
  or event state.
- Transition/event capacity exhaustion rejects the initiating control call and
  never drops or overwrites an accepted playback event.
- Before mutating the SDK, `AdvancePlayback` prepares enough temporary output
  slots and string capacity for the bounded active entries and authored event
  data. The SDK callback only fills reserved storage and cannot throw through C
  callback code; the completed temporary result moves into the caller output.
- Instance creation, clip parsing, and manager setup publish atomically.
- Destruction stops queues before deleting instance-local motions/expressions,
  then destroys the Cubism model/MOC under the existing lifecycle lease.
- Resource unload cannot invalidate bytes retained by an existing instance.
- Two instances created from one resource share immutable bytes only; all
  clocks, tokens, priorities, fades, parameters, callbacks, and events differ.
- Playback code never calls AssetManager, Render, Graphics, Editor, audio, or
  application services.

## Expected implementation ownership

- `engine/module/live2d/runtime/live2d_product.*` — versioned typed values and
  bounded serialization; no Cubism types;
- `engine/module/live2d/runtime/live2d_import.*` — model3 motion/expression
  metadata and transactional source validation;
- `engine/module/live2d/runtime/live2d_model_resource.h` — immutable shared
  product access only;
- `engine/module/live2d/runtime/live2d_model_instance.*` — instance-local SDK
  objects, public playback values, tokens, update order, and event adaptation;
- `engine/module/live2d/runtime/live2d_system.*` — lifecycle/composition only;
- `engine/test/unit/live2d/` — codec, import, numeric, isolation, and lifecycle
  tests;
- standalone viewer/runtime smoke — integration evidence only, no selection
  policy or Editor UI.

Do not add playback to Render, Graphics, Asset core, `RenderSubmission`, or the
viewer host as a second controller.

## Acceptance criteria

- [ ] Product V2 preserves ordered motion groups, motion bytes, finite authored
  fades, unique named expressions, parameter groups, and optional sound bytes
  deterministically.
- [ ] Product V1 still loads with an empty animation library; playback reports
  that reimport is required instead of decoding optional-chunk names.
- [ ] Animation/source-closure validation completes before publication and any
  import failure leaves the requested root absent; content-addressed dependency
  publication keeps its existing root-last transaction rules.
- [ ] Public playback headers contain no Cubism type or pointer-derived handle.
- [ ] Every instance owns its parsed SDK clips/managers and releases them before
  its Cubism model/lifecycle lease.
- [ ] Respect-priority rejection, force start, replacement fade, authored fade,
  immediate/faded cancellation, and natural completion match frozen R5 cases.
- [ ] Motion lifecycle events are token-associated and exactly once; authored
  user-event strings are value-owned and ordered with an explicitly invalid
  source token, without user callback reentrancy.
- [ ] Repeated starts/stops without advancement hit a tested capacity failure;
  accepted events are never lost and storage cannot grow without bound.
- [ ] Expression Add/Multiply/Overwrite and cross-fade numeric goldens match R5.
- [ ] Time is caller supplied; negative/NaN/infinite delta fails atomically.
- [ ] Direct parameter writes, playback checkpointing, expression evaluation,
  model update, and snapshot extraction follow the documented order.
- [ ] Two instances sharing one resource produce independent parameters,
  priorities, tokens, transitions, and events under interleaved updates.
- [ ] Existing static rendering is unchanged when the product has no animation
  or no playback is active.
- [ ] Live2D playback has no Render/Graphics/Editor/Audio/TTS dependency.
- [ ] L2D7 can insert secondary updaters into one documented update transaction
  without changing product identity, playback tokens, or render submission.

## Reference findings

- The pinned R5 `CubismMotionManager` accepts only priorities greater than both
  current and reserved priority; force behavior is application policy above it.
- Starting a queue motion marks existing entries for their authored fade-out,
  and queue update both evaluates parameters and reports authored user events.
- The R5 manager event callback omits queue-entry identity, so source-token
  attribution cannot be promised during overlapping replacement fades.
- `ACubismMotion` and `CubismMotion` contain mutable callback, fade, last-weight,
  model-opacity, and fired-event scratch state. Immutable bytes may be shared;
  parsed SDK motion objects may not be shared safely across model instances.
- R5 expressions use additive, multiply, and overwrite contributions with
  transition weights, and R5's update scheduler assigns expression a defined
  late-update order before look, breath, physics, lip sync, and pose.
- The official sample performs `LoadParameters -> motion -> SaveParameters ->
  late updaters -> model Update`. Its random-idle selection, wall-clock access,
  and audio start are application policy and are not adopted.
- Sakura separates asynchronously loaded motion/expression resources from the
  mutable model update, which supports the resource/instance split. Its code
  also shares parsed motion objects with instance playback; KimPeanutEngine
  does not adopt that shortcut because the SDK objects contain mutable state.

## Stop conditions

Stop and revise the plan if:

- correct behavior requires sharing mutable SDK motion/expression objects;
- product V2 cannot preserve typed authored identity without Asset-core changes;
- `AdvancePlayback` cannot fail invalid input without partially mutating model
  or queue state;
- event delivery requires invoking arbitrary user code from an SDK callback;
- correct behavior starts depending on guessed user-event source tokens;
- L2D7 would need a second independent call to `CubismModel::Update()`;
- playback needs Render, Graphics, Editor, Audio, TTS, or native backend types;
- the only passing evidence depends on random selection or wall-clock timing.
