# L2D2 — Live2D Asset Integration

- Status: active implementation; L2D2.0–L2D2.4 landed 2026-09-08
- Parent roadmap: [Live2D Module Roadmap](../TODO.md)
- Module architecture: [Live2D Module Plans](../PLANS.md)

## Outcome

Connect Live2D to the generic Asset extension contract after AX1 lands. This
stage defines only the Live2D-specific payload, native product loader, and
offline importer registration that the module supplies. It does not redesign
Asset or add any Live2D case to Asset source.

The Asset module owns the extension mechanism. The Live2D module owns the
meaning and lifetime of `Live2DModelResource`, the `.live2d` product format,
the `.model3.json` importer, and the Cubism-specific decode/validation work.

## Boundary

```text
Asset AX1
  -> generic AssetType registry, IAssetPayload, loader/importer contracts

Live2D L2D2
  -> Live2D type registration
  -> Live2DModelResource : IAssetPayload
  -> .live2d native loader
  -> .model3.json offline importer provider

AssetManager
  -> identity, cache, dependency graph, rollback, observation, unload
```

Live2D must not own or duplicate:

- `AssetType` identity allocation or registry sealing;
- top-level `AssetPayload` storage or type-erasure policy;
- `AssetID` creation, path deduplication, or cache records;
- loader lock/state lock policy;
- dependency registration, owned-child binding, rollback, or unload;
- generic source-suffix matching or importer registry infrastructure.

The authoritative design for those concerns is [AX1](../../asset/.plan/AX1.md).

## Live2D payload contract

The Live2D module provides an immutable CPU payload with the generic interface:

```cpp
struct Live2DModelResource final : asset::IAssetPayload
{
    AssetType GetAssetType() const noexcept override;

    // Versioned native product data, layout metadata, and ordered texture
    // dependency descriptions. No GPU objects or mutable instance state.
};
```

The payload must satisfy these rules:

- `GetAssetType()` returns the type value registered for Live2D.
- The product stores only data that can be shared by multiple instances.
- Cubism model parameters, motion state, deformed vertices, mask state, and
  frame-local draw data are not stored in the shared payload.
- The payload owns no `AssetManager`, Render, Graphics, OpenGL, Vulkan, or
  proprietary Core object.
- `Asset::GetResource<Live2DModelResource>()` is the only typed access needed
  by the Live2D runtime integration.

`Live2DModelResource` is a Live2D type, not an Asset type. Asset knows only the
base interface and the registered descriptor.

## Registration supplied by Live2D

The exact registry names and descriptor fields are defined by AX1. The Live2D
module supplies equivalent registration calls at the composition root:

```text
RegisterLive2DAssetType(asset_type_registry)
  -> stable Live2D type value
  -> canonical name
  -> native suffix: .live2d
  -> payload contract: Live2DModelResource
  -> native product loader

RegisterLive2DImporter(asset_importer_registry)
  -> provider name
  -> compound source suffix: .model3.json
  -> deterministic native product writer
```

Registration is explicit and occurs before the first relevant runtime load or
tool dispatch. Live2D does not use a global constructor, patch a built-in
extension switch, or register generic `.json`.

The type value is selected and collision-checked by Asset's registry. The
Live2D plan records the assigned value when implementation begins, but does not
define a second type namespace or a Live2D-specific allocation policy.

## Runtime loading

The native loader follows the generic Asset loader contract:

1. Read and validate a `.live2d` product using Live2D product code.
2. Construct one `shared_ptr<Live2DModelResource>`.
3. Return ordinary `AssetRegisterInfo` with the Live2D type and ordered native
   Texture dependency requests.
4. Let `AssetManager` resolve dependencies and publish the root transaction.

The loader does not allocate IDs, insert into caches, call `LoadSync` for
dependencies, create Cubism instances, or expose GPU resources. A malformed
product, wrong payload type, missing texture, or dependency failure must abort
the normal Asset transaction with no partial root publication.

Runtime data flow:

```text
.live2d
  -> Live2D native loader
  -> shared Live2DModelResource
  -> AssetManager validates type and commits AssetRegisterInfo
  -> Live2DSystem::CreateInstance(asset id)
  -> mutable Live2DModelInstance
```

## Offline importer

The importer provider consumes a `.model3.json` source closure and publishes a
deterministic `.live2d` product through the existing offline AssetImport
boundary. It remains usable while the engine application is closed.

The provider owns Live2D-specific work:

- parse and validate the source closure and relative paths;
- validate `.moc3` compatibility with the selected Cubism Core;
- preserve ordered texture references and required layout metadata;
- preserve supported optional chunks without executing them in V1;
- write, re-read, and integrity-check deterministic product bytes.

AssetImport owns generic provider selection and product transaction boundaries.
The runtime Asset module never opens `.model3.json`, imports source files, or
writes the archive.

## Implementation sequence

### L2D2.0 — Verify AX1 handoff (landed)

- Confirm AX1 exposes the polymorphic payload, type registry, runtime loader,
  and offline importer contracts required by Live2D.
- Confirm Asset tests cover payload lifetime, wrong-type access, registration
  collisions, and transaction rollback.
- Record the final registration function signatures in this plan before code.

Gate: Live2D can compile against generic Asset interfaces without a Live2D
branch in Asset.

### L2D2.1 — Register the Live2D runtime type (landed)

- Assign one stable type value through the Asset-owned registry.
- Register canonical name, `.live2d` suffix, payload type, and loader.
- Keep registration in the Live2D module/application composition root.

Gate: registry collision and late-registration tests pass; Asset core remains
free of Live2D names and includes.

### L2D2.2 — Load the immutable Live2D payload (landed)

- Implement `Live2DModelResource : IAssetPayload`.
- Parse the versioned native product and return ordinary `AssetRegisterInfo`.
- Declare ordered Texture dependencies without taking ownership of their IDs.
- Exercise cache hits, dependency failure, rollback, unload, and stale IDs.

Gate: a valid `.live2d` root and its Texture dependencies use the same
AssetManager transaction as built-in assets.

### L2D2.3 — Register the offline importer (landed for the V1 source subset)

- Register `.model3.json` with the generic offline importer registry.
- Import a licensed test package into deterministic `.live2d` bytes.
- Reject path escape, malformed JSON, missing `.moc3`, missing textures, and
  unsupported required features without publishing a partial product.

Gate: importer tests run without the engine runtime and repeated imports have
identical output and dependency ordering.

### L2D2.4 — Handoff to runtime instances (landed)

- Make `Live2DSystem::CreateInstance` consume the Asset ID/resource contract.
- Prove that two instances share immutable payload data but keep independent
  Cubism parameter and deformation state.
- Keep rendering and frame-safe geometry work in L2D4; do not add renderer
  policy to the Asset loader.

Gate: runtime instance tests pass with no mutable state stored in
`Live2DModelResource`.

## Failure and ownership matrix

| Case | Required result |
| --- | --- |
| AX1 not registered | Live2D configuration fails clearly before load/tool dispatch |
| Live2D disabled | No type, loader, importer, or Cubism dependency is registered |
| Duplicate Live2D type/suffix/name | Asset registry rejects registration before mutation |
| Wrong `GetAssetType()` | Asset rejects the payload before cache publication |
| Malformed `.live2d` | Native loader fails with no root cache/path entry |
| Missing Texture dependency | Asset transaction rolls back the Live2D root |
| Two loads of one `.live2d` path | Existing Asset deduplication returns one identity |
| Unload with live references | Existing Asset ownership/refusal policy applies |
| `.model3.json` path escape | Offline importer rejects before product publication |
| Generic `.json` source | Live2D importer does not claim it |
| Two instances from one Asset | Payload is shared; instance state is isolated |

## Acceptance criteria

- [x] Live2D uses `Live2DModelResource : IAssetPayload` and no top-level
  variant alternative is added for it.
- [x] Asset source contains no Live2D name, include, suffix, or loader branch.
- [x] Live2D registers its type, `.live2d` loader, and `.model3.json` importer
  through the generic Asset-owned contracts.
- [x] Native loading uses ordinary `AssetRegisterInfo` and existing Asset
  cache/dependency/rollback/observation/unload semantics.
- [x] Product/import failures publish no partial root or archive state.
- [x] Two instances from one immutable payload have isolated mutable state.
- [x] Live2D-off builds and ordinary Asset tests remain valid.

## Validation plan

The landed implementation evidence is:

```powershell
.\tools\kp.ps1 build AssetUnitTest
.\tools\kp.ps1 test Asset
cmake --build build-live2d --config Debug --target Live2DCoreTest -- /m:2
ctest --test-dir build-live2d/engine/test -C Debug -R Live2D --output-on-failure
cmake --build build-live2d --config Debug --target KimPeanutEngine -- /m:2
cmake --build build-live2d-off --config Debug --target KimPeanutEngine -- /m:2
```

L2D2.4 is covered by `Live2DAssetTest.LoadsImportedProductThroughAssetManagerDependencies`,
which creates two Cubism-backed instances from one Asset and verifies shared
immutable resource identity plus isolated parameter state. Tests must continue
to cover payload type agreement, product failure rollback, dependency failure,
repeated import determinism, cache deduplication, unload, and Live2D-off
composition.

## Non-goals

- designing or implementing Asset's generic extension system;
- preserving the closed Asset payload variant through a Live2D-specific
  compatibility alternative;
- changing built-in Asset type values or cache semantics;
- generic archive/database redesign;
- Cubism motion policy, gameplay integration, editor authoring, or rendering
  passes (owned by later Live2D stages).
