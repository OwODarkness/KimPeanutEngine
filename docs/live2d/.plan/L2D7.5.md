# L2D7.5 — Live2D Runtime Debug Tools

- Status: implementation baseline (2026-09-13) — [journal](../../../.spec/journal/2026-09-13-live2d-l2d7-5.md)
- Parent: [L2D7 — Secondary Model Behavior](L2D7.md)
- Depends on: L2D7.2, L2D7.3, and L2D7.4

## Goal

Add an interactive debugging layer to `Live2DViewerHost` so runtime behavior
can be observed and driven without coupling Live2D Runtime to ImGui, window
input, Render, Graphics, or application policy.

The first vertical slice is a `Follow Mouse` tool: the viewer converts its
local mouse position to a normalized model-local gaze target and supplies that
value through `Live2DFrameInput`. The runtime continues to receive values only
and remains responsible for smoothing and model parameter evaluation.

## Scope

The viewer-side tool list contains value-oriented controls:

- Neutral gaze;
- Follow Mouse;
- Fixed Gaze Target;
- Pause, Resume, and Step One Frame;
- Reset Parameters;
- current behavior-mask and update-sequence readout;
- optional drawable bounds and hit-area overlays once L2D7.3 is available.

Tools are available only in the standalone Live2D viewer. They are a debug
adapter over existing runtime contracts, not a second behavior controller.

## Ownership and data flow

```text
Live2DViewerHost tool state
  -> viewer-local mouse/viewport conversion
  -> Live2DFrameInput { gaze_target, delta, gravity, wind }
  -> Live2DModelInstance::AdvanceFrame
  -> SDK-free frame/result snapshot
  -> viewer panels and existing Live2D renderer
```

`Live2DViewerHost` owns tool selection, mouse capture, viewport/DPI conversion,
pause/step policy, and debug overlays. `Live2DModelInstance` owns behavior
mathematics, smoothing, playback, controller state, and the single model update.
The tool layer never stores Cubism pointers, renderer handles, GPU resources,
or mutable asset data.

The viewer creates the instance with gaze enabled once, then sends `{0, 0}` for
Neutral and the converted target for Follow Mouse. This avoids recreating the
instance when a tool is toggled. Fixed Target uses the same input path and
therefore exercises the same runtime behavior as mouse following.

## Invariants

- Runtime remains UI- and input-device-free.
- Mouse coordinates are converted before entering `Live2DFrameInput`; Runtime
  sees only finite normalized model-local values in `[-1, 1]`.
- Pause does not mutate the model; Step One Frame advances exactly one validated
  frame through `AdvanceFrame`.
- Reset is implemented through an explicit runtime reset/debug contract or a
  documented host-owned recreation boundary; it does not access SDK state from
  the UI.
- Existing OutputLog, Performance Profiler, renderer, and deferred/PBR scene
  paths remain unchanged.
- Debug overlays consume copied snapshots and do not alter render submission.

## Exit gate

- Follow Mouse visibly changes the character gaze in the standalone viewer.
- Neutral and Fixed Target produce deterministic, distinguishable gaze input.
- Pause and Step One Frame preserve and advance `update_sequence` as specified.
- Behavior-mask, parameter, drawable, and hit-area diagnostics identify whether
  a failure is in input conversion, Runtime behavior, or rendering.
- OpenGL and Vulkan viewer smoke both pass with the tool layer enabled, and the
  existing Live2D tests plus viewer shutdown/lifetime checks remain green.
- No L2D7.5 semantic branch is added to Asset, Render, Graphics, Editor, or the
  deferred/PBR renderer.

## Deferred work

State-machine graphs, emotion/body-language policy, transition reasons, and
agent-readable state history remain L2D8. Production Gameplay/editor input
integration, packaging, and persistent tool settings remain L2D10.
