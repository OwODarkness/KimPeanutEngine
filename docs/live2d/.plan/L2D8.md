## Goal

Provide the missing high-level emotion layer: map application intent to
authored motion/expression combinations, keep selection deterministic, and make
the current state observable without exposing Cubism or UI types.

## Stage split

### L2D8.0 — vocabulary and authored bindings — complete

Define the semantic emotion/body-language vocabulary, intent inputs, authored
clip references, fallback idle behavior, and invalid-binding diagnostics.

Acceptance: the versioned, data-driven contract validates state uniqueness,
idle fallback, complete bindings, Product V2 compatibility, and references only
behaviors already available through the L2D6/L2D7 product and instance APIs.

### L2D8.1 — deterministic resolver — complete

Resolve intent into a desired behavior using explicit priority, interruption,
blend, retrigger, and fallback rules. Selection policy stays in the instance
controller; shared product data remains immutable.

Implemented as an SDK-free `Live2DEmotionResolver` that owns only
instance-local state and emits authored motion/expression references for the
existing L2D6 playback API. Acceptance: identical request sequences produce the
same selected states, transition sequence, priority decisions, fallback use, and
blend mode without mutating shared product data.

### L2D8.2 — runtime observability

Expose SDK-free snapshots and transition records containing the current semantic
state, active motion/expression tokens, transition reason, and completion or
cancellation result. Keep records value-owned and bounded.

Acceptance: callers and diagnostics can inspect state without Cubism pointers,
render dependencies, or UI coupling.

### L2D8.3 — viewer validation

Add a viewer diagnostic view for the state graph and a scripted replay covering
idle fallback, transition, interruption, and recovery. The viewer reads copied
runtime snapshots and never becomes part of Runtime.

Acceptance: the replay is deterministic on OpenGL and Vulkan, and SDK-off
configuration/build remains valid.

## Non-goals

- Speech-bubble layout or rendering; see the companion plan.
- Audio amplitude/phoneme lip-sync or TTS integration (L2D9).
- Gameplay/editor ownership and scene composition (L2D10).
- Performance specialization before profiling (L2D11).
