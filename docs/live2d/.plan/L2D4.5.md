## Goal

Close lifetime, failure, parity, and integration risks so the dedicated viewer
can remain a composition task instead of discovering renderer architecture
defects.

## Hardening matrix

| Scenario | Required evidence |
| --- | --- |
| Repeated update/render | More than `2 * frames-in-flight` distinct frames; no stale positions |
| Hidden/all-zero model | Transparent target, no invalid draw/binding |
| Target resize | Replacement outside active frame; old target released only after safe wait |
| Failed resize | Existing valid proxy/target remains usable |
| Missing/invalid Texture payload | Proxy creation fails with zero leaked handles |
| Injected buffer/texture/pipeline/target failure | Transaction rolls back every earlier handle |
| Snapshot revision/topology mismatch | Live2D publishes no generic submission |
| Generic uniform/binding exhaustion | Executor records zero passes and leaves the frame bracket valid |
| Structurally invalid generic work | Executor fails before preparation or recording |
| Unexpected RHI recording rejection | Active target closes, frame result fails, partial output is not presented |
| Offscreen or mask over-capacity | Stable unsupported diagnostic; zero GPU publication |
| Shutdown after submitted frame | Safe idle, reverse-order release, zero module GPU handles |
| Live2D disabled | Existing engine/Graphics build and smoke remain unchanged |

## Cross-backend comparison

Run identical static/synthetic inputs, dimensions, clear values, transforms,
and parameter revisions on OpenGL and Vulkan. Normalize readback orientation
through the existing Graphics readback seam. Compare:

- non-edge opaque pixels;
- partial-alpha overlap for all blend modes;
- transparent background;
- ordinary/inverted mask interior;
- documented filtered-edge regions separately.

Store capture metadata and hashes in the implementation journal. Do not check
in a licensed model image until fixture redistribution is approved. Any
backend-specific tolerance must have a measured reason; it cannot hide a
coordinate, gamma, blend, or mask-polarity mismatch.

## L2D5 handoff contract

L2D5 receives only:

- initialized `Live2DSystem` and one loaded native asset;
- one `Live2DModelInstance`, its snapshots, and retained Texture payloads;
- `Live2DRenderResourceSet`/`Live2DRenderProxy` with transactional create,
  resize, and destroy;
- `Live2DRenderPlanner` producing a `Live2DRenderSubmission` whose `work` is an
  ordinary `render::RenderSubmission`;
- the generic `RenderSubmissionExecutor`;
- one ordinary active `render::FrameContext` for the current backend slot;
- a sampled offscreen color target plus renderer diagnostics/counters.

The viewer sequences Update → snapshot → Live2D planning → generic execution.
It must not supply Cubism pointers, interpret drawable/mask semantics, choose
pipelines, directly record mask/model commands, bind native resources, or
enforce GPU lifetime. If it must do any of those, L2D4 is not complete.

## Gate

Every L2D4 acceptance item is green, Level 4 passes, both backend images meet
the frozen tolerances, and the L2D5 handoff can be expressed only through
Live2D submission plus common Render/Graphics types. Then mark L2D4 landed and
begin viewer work.
