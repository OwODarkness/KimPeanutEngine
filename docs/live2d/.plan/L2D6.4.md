# L2D6.4 — Playback Hardening and L2D7 Handoff

- Status: implementation baseline (2026-09-12) — [journal](../../../.spec/journal/2026-09-12-live2d-l2d6-4.md)
- Parent: [L2D6 — Authored Motion and Expression Playback](L2D6.md)
- Depends on: [L2D6.3](L2D6.3.md)

## Goal

Close compatibility, lifetime, failure, and integration risks so L2D7 can
add secondary behavior by extending one update transaction rather than
redesigning motion playback.

## Hardening matrix

| Scenario | Required evidence |
| --- | --- |
| Product V1 | Loads static model; playback reports reimport-required |
| Product V2 no animations | Existing parameter/update/snapshot/render behavior unchanged |
| Invalid V2 closure | Import/runtime fail without partial root or instance publication |
| Multiple instances | Shared bytes, isolated SDK objects/clocks/tokens/events |
| Priority rejection | No token, queue, clock, parameter, or event mutation |
| Replacement/cancellation | Correct terminal reason after immediate or faded end |
| Invalid delta | Atomic failure and unchanged next valid result |
| Direct parameter writes | Latest pending value persists at the documented checkpoint |
| Expression transition | Relative values do not accumulate across frames |
| Asset wrapper unload | Existing instance continues from retained immutable product |
| Instance destruction mid-fade | Queues stop before clips/model/lifecycle release |
| SDK off | Ordinary engine build contains no playback implementation dependency |
| Viewer smoke | Authored clip advances for its full duration and shuts down cleanly |

## Dependency audit

- Asset core contains no Live2D product, group, expression, or playback branch.
- `Live2DProduct` and importer public values contain no SDK type.
- Public playback values contain no SDK pointer, callback, or queue handle.
- Runtime playback includes no Render, Graphics, Editor, Gameplay, Audio, or
  TTS header.
- Render submission and renderer diffs are empty except fixture evidence if a
  visual regression is intentionally added.
- `Live2DSystem` owns only lifecycle and instance-serial allocation; it does not
  become a global playback scheduler.

## L2D7 handoff contract

L2D7 receives:

- immutable typed parameter-group metadata, including authored EyeBlink and
  LipSync IDs;
- one instance-local model and playback controller;
- a persistent checkpoint after direct writes and primary motion;
- one expression contribution phase after that checkpoint;
- one documented late-update insertion region before `CubismModel::Update`;
- caller-controlled delta time and value-owned update results/events.

L2D7 may add ordered eye blink, look, breath, physics, and pose contributors in
that insertion region. It must not add another clock, call motion/expression
managers independently, save expression output into the persistent checkpoint,
or move model update/snapshot ownership.

L2D9 later adds lip-sync input through the same ordered transaction. Motion
sound bytes remain opaque until an Audio-owned consumer and synchronization
contract exist.

Every parent acceptance item is green; focused import/codec/runtime tests pass;
the standalone viewer completes an authored motion and clean shutdown; no
cross-module dependency boundary changes; and L2D7 can be expressed solely as
new ordered late-update contributors. Then mark L2D6 landed and begin L2D7
planning.
