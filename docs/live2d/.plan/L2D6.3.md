# L2D6.3 — Deterministic Playback Transaction

- Status: implementation baseline (2026-09-12) — [journal](../../../.spec/journal/2026-09-12-live2d-l2d6-3.md)
- Parent: [L2D6 — Authored Motion and Expression Playback](L2D6.md)
- Depends on: [L2D6.2](L2D6.2.md)

## Goal

Expose SDK-free motion/expression control and advance it through one
deterministic parameter transaction with observable, exactly-once outcomes.

## Motion controller

Implement the parent-plan token and control API with these rules:

- allocate a token only after key lookup and priority acceptance succeed;
- `RespectPriority` requires a positive priority strictly greater than current
  and reserved values;
- `Force` bypasses comparison but still requires a valid positive priority;
- starting a replacement marks existing entries as interrupted and uses their
  authored fade-out behavior;
- natural end, replacement end, and explicit stop map to completed,
  interrupted, and cancelled respectively;
- immediate stop removes the selected entry without advancing time;
- authored-fade stop remains active until the fade completes;
- terminal events occur exactly once and release the internal token mapping;
- a start that would exceed the frozen transition or pending-event capacity is
  rejected before manager mutation;
- unknown, stale, foreign-instance, or already-terminal tokens fail without
  affecting the current channel.

Adapt the SDK's internal callbacks into a temporary instance-owned event sink.
Never call application code while the SDK is evaluating a queue. Preserve
authored user-event order and copy strings immediately. Because R5 does not
identify the firing queue entry, publish those events with an invalid token;
only lifecycle terminal events are token-associated.

## Expression controller

- Maintain one logical current expression name.
- Starting any expression, including the same name, creates a new transition.
- Let the R5 expression manager evaluate Add/Multiply/Overwrite contributions
  and cross-fade queue entries.
- Unknown names are non-mutating failures.
- Faded clear transitions contributions to neutral; immediate clear removes
  all entries and current identity.
- Do not expose internal transition entries as public layers.
- Reject a restart/replacement before mutation when expression-transition or
  pending-event capacity is exhausted.

## Update transaction

Build each update in temporary result/event storage and validate delta time
before mutation. Execute exactly:

```text
LoadParameters
apply pending direct/base writes
UpdateMotion
SaveParameters
UpdateExpression
CubismModel::Update
publish result/events
```

`SetParameterValue` remains immediately observable and records the latest
pending write by parameter index. Applying a pending write consumes it only
after the update succeeds. Expressions remain after the saved checkpoint so
their relative effects do not accumulate into the next frame. The pending
write table is fixed to `ParameterCount()` during instance construction, so the
existing `noexcept` setter does not allocate.

Before SDK mutation, reserve and initialize temporary event/result storage for
the configured active-entry bound and the fixture/product's maximum authored
event bytes. The SDK callback copies only into prepared slots and never lets an
allocation failure or exception cross its C callback boundary.

No clock, random-number generator, idle fallback, audio service, render object,
or asynchronous callback participates. `ExtractFrameSnapshot` reads the result
but never advances it.

The zero-argument legacy `Update` continues to support models with no active
playback controller. Once a motion/expression is active, it fails rather than
bypassing advancement or discarding events. The standalone viewer migrates to
`AdvancePlayback` when demonstrating authored playback.

## Contract tests

Use a deterministic synthetic fixture and caller-provided delta sequence:

- priority none/current/reserved/equal/lower/higher and forced replacement;
- fade-in, authored fade override, parameter-specific fade, replacement
  cross-fade, natural fade-out, immediate/faded cancellation;
- completion versus interruption versus cancellation, exactly once;
- multiple authored events within one update interval, invalid source tokens,
  overlapping replacement fades, and empty intervals;
- expression Add/Multiply/Overwrite, restart, replacement, clear, and neutral
  restoration;
- direct writes before playback, during playback, same-index collapse, and
  expression non-accumulation;
- zero delta, large finite delta, negative, NaN, positive/negative infinity;
- repeated snapshot extraction and interleaved two-instance updates;
- token monotonicity, stale/foreign token rejection, and injected exhaustion;
- repeated start/stop/restart calls without advancement reach deterministic
  capacity failures without dropping accepted events;
- products with no animation and no active playback preserve existing results.

Compare selected parameter values, model opacity, event sequence, and resulting
drawable positions against the frozen official probe within documented float
tolerances. Avoid assertions based only on manager booleans.

## Gate

All semantic and isolation tests pass with no SDK type in the public API, no
user callback reentrancy, no wall-clock/random policy, and no change to
Render/Graphics. L2D6.4 starts only after the canonical update order is proven
through observable parameters and events.
