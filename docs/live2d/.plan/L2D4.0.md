# L2D4.0 — Render Contract and Conformance Freeze

- Status: landed (2026-09-09)
- Parent: [L2D4 — Live2D Planning and Generic Render Submission](L2D4.md)
- Depends on: L2D2 and L2D3 landed

## Goal

Remove semantic uncertainty before changing Graphics or writing shaders. This
subtask produces executable CPU expectations and a feature-policy gate; it
does not create GPU resources.

## Tasks

1. Record the exact R5 Core/Framework version and inspect the pinned official
   OpenGL and Vulkan render paths for:
   - render-order sorting and equal-order behavior;
   - visibility, opacity, culling, multiply color, and screen color;
   - RGB/alpha factors for normal, additive, multiplicative, and mask blends;
   - ordinary versus inverted mask sampling;
   - atlas clear value, channel order, region subdivision, bounds margin, and
     maximum contexts per atlas;
   - sRGB texture decode, linear shader math, premultiplied output, and final
     target encoding.
2. Capture or generate one official R5 still for the approved local model with
   transparent background. Record SDK renderer settings, target format,
   viewport, parameter values, and capture tool. If the fixture cannot exercise
   every blend/mask case, add synthetic CPU cases; do not mutate the licensed
   model merely to manufacture coverage.
3. Add an SDK-free `Live2DRenderContractTest` data table that evaluates the
   frozen color/blend equations against hand-computed pixels. Include zero and
   partial alpha, multiply/screen colors, every blend mode, and inverted mask.
4. Define numeric policy:
   - CPU equation tolerance for float tests;
   - per-channel backend parity tolerance;
   - edge-region tolerance for filtered masks;
   - transparent-pixel RGB handling so invisible RGB does not cause false
     failures.
5. Define and test `Live2DRenderFeatureReport`, populated during static model
   extraction. V1 accepts ordinary drawables and packed clipping; it rejects
   offscreen/blend groups, topology change, invalid indices, unknown blend
   modes, and excess active mask contexts.
6. Record fixture license/redistribution status. Local-only fixtures may drive
   manual evidence, but CI/goldens cannot depend on them until redistribution
   is explicitly approved.

## Outputs

- a decision table in the L2D4 journal when implementation starts;
- pure color/blend/mask equation tests with no Graphics backend;
- a machine-readable feature report and stable diagnostic strings;
- official-reference capture metadata or an explicit licensing/access blocker.

## Gate

L2D4.0 is complete when no later task must guess an alpha convention, blend
factor, mask polarity/capacity, coordinate orientation, or unsupported-feature
behavior. If official OpenGL and Vulkan behavior differs, choose and document
one engine contract before L2D4.1; do not encode backend-specific Live2D policy.
