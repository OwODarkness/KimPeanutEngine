  fixture blocker documented in the closeout journal — [journal](../../../.spec/journal/2026-09-16-live2d-l2d7-closeout.md)

- Acceptance authority: [L2D7 acceptance](../TODO.md#l2d7-acceptance)

## Outcome

Add the authored and procedural model behavior that belongs between L2D6's
motion/expression checkpoint and the existing `CubismModel::Update()` call:
physics, pose, deterministic automatic eye blink, configurable breath,
caller-driven gaze, immutable user-data queries, and model-local hit areas.

The native product remains immutable and shareable. Every controller with a
clock, random state, filter, physics accumulator, or pose fade belongs to one
`Live2DModelInstance`. Rendering continues to consume only the SDK-free frame
snapshot produced after the complete model update.

```text
immutable Live2DModelResource
  Product V3 behavior bytes + parameter groups + hit/user metadata
                         |
                         v
Live2DModelInstance (one owner thread)
  L2D6 playback + blink/gaze/breath/physics/pose mutable state
                         |
                         v
AdvanceFrame(input)
  one clock + one ordered parameter transaction + one Core update
                         |
                         v
existing SDK-free snapshot -> L2D4 renderer
```

## Design question

What is the smallest extension of the L2D6 transaction that preserves Cubism
R5 behavior order, keeps replay deterministic, exposes no SDK types, and does
not move application policy, input-device mapping, or hit-test transforms into
the shared asset or renderer?

The answer is a Product V3 typed behavior catalog, instance-local controllers,
one value-only frame input, one canonical `AdvanceFrame` transaction, and
read-only metadata/geometry queries. It is not a generic animation graph, a
second system clock, an Editor input path, or a Render feature.

## Entry gates and current mismatch

Implementation starts only after L2D6.4 closes its aggregate acceptance gate.
L2D7 consumes L2D6's typed parameter groups, instance-local playback state,
caller-controlled delta time, persistent base/motion checkpoint, value-owned
events, and late-update transaction.

One L2D6 handoff detail must be corrected before L2D6.3 becomes implementation:
the current handoff describes one insertion region *after* expression update,
but pinned R5 assigns automatic eye blink order 200 and expression order 300.
Putting every L2D7 contributor after expression cannot reproduce the official
order. L2D7.0 therefore requires the internal transaction to expose named
phases while preserving L2D6's public playback contract. No public Cubism
updater interface is required.

The L2D5 viewer and renderer remain validation consumers. Existing unresolved
L2D5 reference-image or cross-backend issues are not absorbed into L2D7; they
must be dispositioned by their owning stage.

## Scope

In scope:

- typed import and serialization of one optional physics file, one optional
  pose file, ordered hit-area definitions, and immutable user-data entries;
- Product V1/V2 compatibility with explicit behavior-unavailable reporting;
- per-instance physics, pose, blink, breath, and gaze state;
- caller-supplied delta, normalized gaze target, gravity, and wind;
- fixed R5-compatible parameter contribution order;
- deterministic per-instance automatic-blink randomness;
- model-local hit testing against current deformed drawable bounds;
- SDK-free capability, input, result, user-data, and hit-area values;
- import, codec, runtime, ordering, determinism, lifecycle, and viewer evidence.

Out of scope:

- random idle selection, emotion interpretation, body-language choice, or
  mapping application intent to motions/expressions (L2D8);
- lip-sync, motion-sound playback, phonemes, Audio, or TTS coupling (L2D9);
- mouse/controller/window coordinate conversion, Gameplay components, Editor
  inspectors, hot reload, reimport UX, or command authoring (L2D10);
- replacing Cubism physics/pose algorithms, authoring new physics rigs, or a
  general procedural-animation graph;
- async model mutation, cross-thread controller calls, fixed-step simulation,
  interpolation, rewind, save-game serialization, or network replication;
- changes to Asset core, Render, Graphics, shaders, or GPU ownership.

## Frozen architecture

### 1. Product V3 owns typed immutable behavior inputs

L2D6 introduces Product V2 for motions, expressions, and parameter groups.
L2D7 extends that value schema to Product V3 with fields equivalent to:

```cpp
struct Live2DHitAreaDefinition
{
    std::string name;
    std::string drawable_id;
};

struct Live2DUserDataEntry
{
    std::string target_type;
    std::string target_id;
    std::string value;
};

struct Live2DSecondaryBehaviorData
{
    std::vector<std::byte> physics_bytes;
    std::vector<std::byte> pose_bytes;
    std::vector<Live2DHitAreaDefinition> hit_areas;
    std::vector<Live2DUserDataEntry> user_data;
};
```

Empty physics or pose bytes mean the authored reference is absent; an authored
reference to an empty or malformed file is an import failure. Hit areas retain
authored array order. Names are non-empty and unique, drawable IDs are
non-empty, and every string is bounded and NUL-free. User-data entries retain
authored order and preserve target type, target ID, and value without executing
callbacks or interpreting application meaning.

The importer reads `HitAreas`, the L2D6 `Groups`, and the `Physics`, `Pose`, and
`UserData` file references deliberately. It must not recover semantics from
`optional_chunks` role strings. It validates the complete closure before root
publication. Physics and pose retain their exact bounded JSON bytes for the
pinned Framework parser; user-data JSON is structurally validated and
normalized into SDK-free product values because it is immutable query data.

Product V1 parses as render-only and Product V2 parses as render plus authored
playback. Both expose empty L2D7 behavior data. Requesting authored secondary
behavior from either version reports that reimport is required; runtime never
heuristically upgrades old `optional_chunks`. Product V3 preserves L2D6's
motion/expression identity and byte ordering exactly and keeps unknown optional
chunks under the existing bounds.

The Product target remains independent of Cubism, AssetManager, Render, and
Graphics. Asset core remains unaware of all Product V3 fields.

### 2. Mutable state is instance-local and transactionally constructed

`Live2DModelResource` exposes immutable Product V3 values. A staged
`Live2DModelInstance::Impl` creates and owns:

- one `CubismPhysics` when physics bytes are present;
- one `CubismPose` when pose bytes are present;
- one engine-owned automatic-blink state machine and integer RNG;
- one `CubismTargetPoint` and `CubismLook` for smoothed gaze;
- one `CubismBreath` with an instance-owned channel profile;
- resolved parameter and drawable indices used by the controllers and queries;
- L2D6's already instance-local clips, managers, tokens, clocks, and events.

All staged behavior objects and ID/index resolutions must succeed before the
instance is published. A malformed SDK behavior file, duplicate hit-area name,
unknown hit-area drawable ID, invalid configured parameter ID, or failed
allocation destroys the staged closure and leaves no live model lease.

Two instances may share product bytes, Texture payloads, user data, hit-area
definitions, and other immutable metadata. They never share controller objects,
clocks, RNG state, smoothed gaze, physics accumulators, pose fades, playback
queues, or mutable Cubism model state.

Destruction stops L2D6 queues first, then releases secondary controllers, then
the Cubism model/MOC under the existing lifecycle lease. No controller outlives
the model it mutates.

### 3. SDK-free configuration and frame input

Add value contracts equivalent to:

```cpp
struct Live2DBlinkSettings
{
    bool enabled = false;
    std::uint64_t seed = 1;
    float interval_seconds = 4.0f;
    float closing_seconds = 0.1f;
    float closed_seconds = 0.05f;
    float opening_seconds = 0.15f;
};

struct Live2DSecondaryBehaviorConfig
{
    Live2DBlinkSettings blink;
    bool gaze_enabled = false;
    bool breath_enabled = false;
    bool physics_enabled = true;
    bool pose_enabled = true;
};

struct Live2DFrameInput
{
    float delta_seconds = 0.0f;
    Live2DVector2 gaze_target{};       // normalized model input, [-1, 1]
    Live2DVector2 gravity{0.0f, -1.0f};
    Live2DVector2 wind{};
};

struct Live2DFrameUpdateResult
{
    Live2DPlaybackUpdateResult playback;
    std::uint64_t update_sequence = 0;
    std::uint32_t applied_behavior_mask = 0;
};
```

Final names may follow repository conventions. Public values contain no
Cubism ID, pointer, manager, callback, or queue handle. The configuration is
validated before instance publication. The frame input is validated completely
before any clock, controller, parameter, part opacity, playback entry, or event
state changes: delta must be finite and non-negative; gaze, gravity, and wind
must be finite; gaze must lie in `[-1, 1]` on both axes.

The existing `CreateInstance(asset_id)` preserves current behavior by creating
an instance with procedural blink, breath, and gaze disabled. Add an overload
that accepts `Live2DSecondaryBehaviorConfig`; viewers or later policy layers
must opt in explicitly. Physics and pose still require both an authored file
and an enabled configuration flag. Missing optional authored behavior is a
reported capability absence, not an instance-creation failure.

`AdvanceFrame(input, result, diagnostic)` becomes the complete update entry
point. L2D6's `AdvancePlayback(delta, ...)` remains as a compatibility wrapper
that supplies neutral frame input and preserves the existing playback result.
The low-level zero-argument `Update()` retains L2D6's restriction and cannot
bypass active playback or enabled secondary controllers.

### 4. One deterministic update transaction

Every successful `AdvanceFrame` performs exactly this order:

```text
1.  LoadParameters()                         previous persistent checkpoint
2.  apply pending direct/base parameter writes
3.  L2D6 primary motion manager update
4.  SaveParameters()                         persist base + primary motion
5.  automatic eye blink, only if step 3 did not update motion parameters
6.  L2D6 expression manager update           non-persistent relative layer
7.  gaze target smoothing and look contribution
8.  breath contribution
9.  physics evaluation
10. reserved L2D9 lip-sync contribution
11. pose/linked-part opacity update
12. CubismModel::Update()                     exactly once
13. publish update sequence and value-owned playback events
```

No individual controller calls `LoadParameters`, `SaveParameters`, or
`CubismModel::Update`. There is no second save after step 4: blink,
expression, gaze, breath, physics, and future lip sync are late, non-persistent
contributions recomputed from the saved checkpoint each frame. Pose remains
last because it resolves part opacity after all parameter contributors.

The internal implementation may use private named phase functions or the
pinned Framework scheduler, but public code does not expose a registration API
or arbitrary execution-order integers. A plugin scheduler is unjustified for
one fixed Cubism semantic sequence.

`motion_parameters_updated` retains the pinned R5 meaning: any successful
primary motion update suppresses automatic blink for that frame, even if the
motion does not visibly target an eye parameter. L2D7 does not reinterpret the
motion's curves to make a policy guess.

### 5. Deterministic blink, breath, and gaze

The pinned `CubismEyeBlink` algorithm uses process-global `rand()`, which makes
two instances and replay order interfere. L2D7 implements the small blink state
machine in module-private code using the same interval/closing/closed/opening
shape but a specified per-instance integer generator. The generator state and
integer-to-unit-float conversion are fixed by tests; `std::rand`,
`std::random_device`, wall-clock reads, and shared global RNG state are
forbidden. Identical product, config seed, and frame-input sequence must produce
the same blink parameter sequence on the same pinned SDK build.

Eye parameter IDs come only from the authored `EyeBlink` parameter group
preserved by L2D6. No group means automatic blink is unavailable. Duplicate or
missing model parameters are diagnosed during instance construction rather
than synthesized by name.

Breath and gaze use explicit instance configuration over conventional Cubism
parameter IDs. The default profiles, when enabled, match the pinned R5 sample
mapping and remain inspectable value data:

- gaze: `AngleX = 30x`, `AngleY = 30y`, `AngleZ = -30xy`,
  `BodyAngleX = 10x`, `EyeBallX = x`, `EyeBallY = y`;
- breath: the R5 sample channels for `AngleX`, `AngleY`, `AngleZ`,
  `BodyAngleX`, and `Breath`, including their authored sample cycles/weights.

The exact channel structs and defaults are frozen in L2D7.0 before code lands.
A missing conventional parameter disables only that channel and appears in a
capability report; it must not create a virtual parameter silently. L2D8 may
choose gaze targets or enable profiles, but it does not own these mathematical
parameter mappings.

Gaze input is normalized model input, not pixels. `AdvanceFrame` supplies the
target every frame; `{0, 0}` is neutral. The instance-owned target-point filter
uses only caller delta and previous instance state. Window, viewport, DPI, mouse, and controller conversion remain outside
Live2DRuntime. L2D7.5 may implement a viewer-local debug conversion adapter;
production input integration remains a later L2D10 concern.

### 6. Physics and pose

Physics and pose bytes are parsed by the pinned backend-neutral Framework during
instance construction. Live2D adds only the exact Framework translation units
required by these features to the audited CMake source list; it does not build
an official OpenGL/Vulkan renderer or glob the SDK tree.

Before physics evaluation, the instance applies the frame input's gravity and
wind through `CubismPhysics::Options`. Physics state advances once with the
same validated delta used by playback and every other controller. L2D7 does not
introduce an independent fixed step, accumulator, clamp, or clock above the
Framework implementation. Zero delta remains valid and negative/non-finite
delta is rejected before mutation, matching L2D6.

Pose evaluates last and owns only instance-local part-opacity transition state.
Linked parts remain an internal Framework concern. Static/shared asset data is
never mutated by pose evaluation.

An absent optional file is a valid no-op. An authored file that fails offline
structural validation or runtime Framework parsing fails the import or staged
instance construction respectively; it never produces a partially enabled
instance.

### 7. User data and hit areas are read-only queries

User data is immutable model metadata. `Live2DModelResource` exposes an ordered
SDK-free view of `Live2DUserDataEntry` values and lookup by target type/ID.
L2D7 does not fire callbacks, parse commands from values, or attach gameplay
meaning. Motion user-event strings remain owned by L2D6's playback result and
are not merged with model user data.

Hit-area definitions are immutable product metadata, while their geometry is
instance state. Instance construction resolves each authored drawable ID to a
stable drawable index. Hit testing runs on the instance-owner thread against
the current deformed vertex positions after the most recent successful model
update.

Public hit-test input is a finite point in Cubism model-local coordinates.
Each area uses the inclusive axis-aligned bounds of its target drawable,
matching the official R5 `CubismUserModel::IsHit` shape. Results retain authored
hit-area order. Empty geometry, unknown area names, or non-finite input return a
stable negative result/diagnostic without mutation. Visibility, model opacity,
window transforms, and application interaction policy are intentionally not
folded into the geometric query; the caller owns those decisions and L2D10
owns screen-to-model conversion.

### 8. Thread, failure, and lifetime rules

- Instance construction, control calls, `AdvanceFrame`, snapshot extraction,
  and hit testing all run on the instance-owner thread.
- The complete frame input and bounded L2D6 event capacity are prepared before
  any SDK mutation. A preflight failure clears output and leaves the next valid
  update observationally identical to a run that omitted the failed call.
- After preflight, the private controller calls form one non-throwing mutation
  sequence; code must not advertise rollback after partially evaluating Cubism.
- Update sequence increments only after the one Core update succeeds. Snapshot
  extraction remains read-only and retains its separate frame sequence.
- No controller retains an `Asset*`, `AssetManager*`, renderer, GPU handle,
  backend object, window, input device, Audio service, or application callback.
- Product unload cannot invalidate bytes or metadata retained by a live
  instance. Cubism lifecycle shutdown remains blocked while any instance lease
  is alive.

## Expected implementation ownership

- `engine/module/live2d/runtime/live2d_product.*` — Product V3 values and
  bounded, backward-compatible serialization; no SDK types;
- `engine/module/live2d/runtime/live2d_import.*` — deliberate model3 behavior
  metadata and user-data parsing under the existing root-last transaction;
- `engine/module/live2d/runtime/live2d_model_resource.h` — immutable user-data,
  hit-area, capability, and product access only;
- `engine/module/live2d/runtime/live2d_model_instance.*` — instance-local SDK
  controllers, resolved indices, deterministic state, complete update order,
  and current-geometry queries;
- optional focused `runtime/live2d_secondary_behavior.*` — private controller
  state/math when separating it keeps `Live2DModelInstance::Impl` readable;
- `engine/module/live2d/CMakeLists.txt` — explicit audited Framework source
  additions only;
- `engine/test/unit/live2d/` — SDK-free codec/import/query contracts and
  SDK-gated live-model ordering/lifecycle tests;
- `Live2DViewerHost` — deterministic integration inputs, evidence, and the
  L2D7.5 debug tool adapter; it does not own behavior mathematics or a second
  controller.

Do not add L2D7 branches or types to Asset, Render, Graphics, Editor, Gameplay,
Audio, TTS, `RenderSubmission`, or backend code.

## Validation ladder

L2D7 changes persistent product bytes, CMake source wiring, and mutable model
evaluation, but not RHI contracts. Each subtask runs the narrow tests named in
its exit gate. The aggregate gate is:

```powershell
.\tools\kp.ps1 validate engine/module/live2d/runtime/live2d_product.cpp
.\tools\kp.ps1 validate engine/module/live2d/runtime/live2d_import.cpp
.\tools\kp.ps1 validate engine/module/live2d/runtime/live2d_model_instance.cpp
cmake --build build --config Debug --target Live2DCoreTest
ctest --test-dir build -C Debug -R Live2D --output-on-failure
cmake --build build --config Debug --target KimPeanutAssetTool
cmake --build build --config Debug --target KimPeanutEngine
```

Runtime evidence uses one locally provisioned Product V3 model with physics,
pose, EyeBlink IDs, user data, and at least one hit area. Feed the same seed,
delta sequence, gaze, gravity, wind, model, dimensions, and capture frame to
OpenGL and Vulkan viewer runs. Compare the resulting SDK-free parameter/
drawable reports first, then inspect/cross-compare the captures. Rendering
differences remain owned by the existing L2D4/L2D5 tolerances rather than being
hidden by a new L2D7 tolerance.

Also run:

```powershell
cmake -S . -B build-nolive2d -G "Visual Studio 17 2022" `
  -DKPENGINE_ENABLE_LIVE2D=OFF
cmake --build build-nolive2d --config Debug --target KimPeanutEngine
cmake --build build --config Debug
ctest --test-dir build -C Debug
```

Minimum aggregate evidence is Level 4 because the native product version,
public Live2D runtime contract, SDK source list, application viewer path, and
resource lifetime all change. A compile-only or single-backend result cannot
close the stage. Record external fixture licensing, exact SDK revision,
commands, first failures, captures, skipped checks, and remaining risks in a
dated L2D7 journal only after implementation begins.

## Reference findings

The behavior subsystem question is update ownership and ordering, not how to
copy a sample application.

- Pinned Cubism Framework R5
  [`ICubismUpdater.hpp`](https://github.com/Live2D/CubismNativeFramework/blob/145155d2c5bdd8d23475cef9cc3ab46d3220190c/src/Motion/ICubismUpdater.hpp)
  assigns EyeBlink 200, Expression 300, Look 400, Breath 500, Physics 600,
  LipSync 700, and Pose 800. The pinned Native sample
  [`LAppModel.cpp`](https://github.com/Live2D/CubismNativeSamples/blob/b8024738f108e6003e4925193e8d5ec04cd18196/Samples/OpenGL/Demo/proj.win.cmake/src/LAppModel.cpp)
  restores and saves the motion checkpoint, runs the late-update scheduler,
  then calls Core update once. KimPeanutEngine adopts that semantic sequence
  inside one instance-owned transaction.
- R5
  [`CubismEyeBlink.cpp`](https://github.com/Live2D/CubismNativeFramework/blob/145155d2c5bdd8d23475cef9cc3ab46d3220190c/src/Effect/CubismEyeBlink.cpp)
  uses process-global `rand()` to schedule intervals. That is unsuitable for
  isolated deterministic instances, so L2D7 adopts the state-machine envelope
  but owns a specified per-instance RNG rather than modifying Framework source.
- R5
  [`CubismUserModel.cpp`](https://github.com/Live2D/CubismNativeFramework/blob/145155d2c5bdd8d23475cef9cc3ab46d3220190c/src/Model/CubismUserModel.cpp)
  performs hit detection from current drawable vertex AABBs after inverse model
  transformation. L2D7 adopts the geometry rule and keeps the public point in
  model-local space so window/view conversion stays with the caller.
- Sakura at
  [`c0fdb2bb`](https://github.com/SakuraEngine/SakuraEngine/blob/c0fdb2bb30074058cb98df98b8134559d13d67b0/engine/modules/render/live2d/src/l2d_model_resource.cpp)
  loads physics/pose/user data with the model and evaluates motion, blink,
  expression, look, breath, physics, and pose before model update. The ordering
  evidence applies, but Sakura's source-file runtime I/O and mutable model
  resource do not: KimPeanutEngine already owns offline native products and
  separates immutable resource data from per-instance model state.

The reference gate changes the L2D6 handoff from one anonymous insertion slot
to named private phases. It does not justify a public updater scheduler, SDK
renderer, shared mutable resource, or runtime source loader.

## Stop conditions

Stop and revise the plan instead of expanding scope when:

- L2D6 lands a monolithic `AdvancePlayback` that cannot place blink before
  expression or calls `CubismModel::Update` before secondary contributors;
- Product V3 behavior requires decoding V1/V2 `optional_chunks` heuristically;
- any mutable controller, RNG, clock, filtered target, or physics/pose state is
  placed in `Live2DModelResource`;
- correct behavior appears to require a second time source, backend object,
  renderer callback, or cross-thread model mutation;
- automatic blink requires process-global randomness or depends on instance
  scheduling order;
- hit testing needs GPU readback, window coordinates, or Render knowledge;
- Asset, Render, Graphics, Editor, Audio, or TTS must include a Live2D behavior
  type to complete this stage;
- the only available fixture cannot legally be used for the required runtime
  evidence.

## Later-stage handoff

L2D8 receives public motion/expression controls, `Live2DFrameInput`, capability
reports, user-data/hit queries, and one deterministic update result. It may
choose authored behavior and gaze targets but cannot reorder model evaluation
or mutate shared product data.

L2D9 receives the reserved lip-sync phase between physics and pose. It supplies
owned numeric input through the same frame transaction and must not add an
audio clock or call `CubismModel::Update` independently.
