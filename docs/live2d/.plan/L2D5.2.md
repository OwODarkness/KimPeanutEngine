## Goal

Close V1 acceptance item 10 — "the dedicated viewer resizes, captures a stable
frame, and exits without Graphics validation errors, leaked Cubism objects, or
live GPU handles" — with evidence a build would fail without.

Today `Live2DRenderer::ResizeOutput` is called every frame but has never seen a
changed extent, and the shutdown counts are observed in a log rather than
asserted anywhere.

## Renderer contract

`Live2DRenderer::ResizeOutput` is already transactional; this stage covers it
rather than changing it. The test drives it through the existing graphics
backend test double:

- a different non-zero extent creates a replacement, releases the previous
  target only after `WaitIdle`, and leaves the renderer usable;
- a backend that fails to create the replacement returns `false`, leaves the
  previously valid target and view untouched, and keeps the renderer usable;
- a zero extent is rejected without touching the current target;
- the same extent is a no-op and destroys nothing.

If the existing `FakeBackend` cannot mint the pipeline, texture, and sampler
handles `Live2DRenderer::Initialize` requires, extend or share it deliberately
rather than weakening the test. The renderer-level test lives in the
SDK-enabled test target because `Initialize` needs a real MOC.

## Viewer runtime evidence

Per L2D5.0's resize decision, add the launch option that changes the viewer's
window extent once during a run, driving the same programmatic resize the
graphics example already uses, then:

- run the viewer on each backend with a resize, a capture after the resize, and
  clean exit;
- confirm the log reaches a clean Cubism disposal and the capture is a stable
  frame at the post-resize extent;
- assert the live GPU handle count and live model instance count are zero after
  shutdown, per L2D5.0's assertion-surface decision.

Captures go under `save/screenshots/validation/` as `.png` and must not disturb
captures from other tasks. `tools/compare_capture_regions.py` requires equal
dimensions, so comparisons pair each extent against the other backend at that
same extent, never pre-resize against post-resize.

Also cover the two carried items: the missing-`.moc3` and invalid-MOC import
branches get direct tests, and the `--capture-alpha` blend factor gets a
regression test.

## Tests

- `ResizeOutput` coverage for the four cases above.
- Direct import tests for the missing-`.moc3` and invalid-MOC branches, each
  asserting no partial root is published.
- A `--capture-alpha` regression test that fails if the transparent-clear blend
  factor reverts.
- Both viewer runs recorded in the journal with their commands and results.

## Gate

V1 acceptance item 10 passes with runtime evidence on both backends, the
shutdown counts are asserted rather than inferred, and the carried import and
alpha tests are green. Compilation or a clean log alone does not close this.
