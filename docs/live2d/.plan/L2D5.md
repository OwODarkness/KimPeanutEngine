## Design question

What is the smallest set of changes that turns each remaining V1 item into
evidence a build would fail without — rather than an observation in a log
someone read once?

Two items need a contract change, and both are the same shape: a *module name*
in generic code, and a *test-only surface* that has to exist for the evidence
to be producible at all.

## Scope

In scope:

- retiring the module name from Render's generic capture enum;
- a generic, host-resolved capture-view contract that does not grow a module
  registry before a second host exists;
- backend-driven `Live2DRenderer::ResizeOutput` coverage and a viewer run that
  actually changes its output extent;
- an assertable shutdown handle/model-instance count;
- a redistributable fixture and synthetic blend-mode coverage;
- official-reference comparison: built, or dispositioned;
- a Live2D rule in `tools/kp.ps1` so Live2D changes stop falling through to a
  full build.

Out of scope:

- any authored motion/expression playback (L2D6);
- physics, pose, breath, gaze, hit areas (L2D7);
- Editor/Gameplay integration, reimport UX, packaging (L2D10);
- changing the frozen L2D4.0 capture tolerances;
- in-place product replacement or reimport (L2D6.1 / L2D10).

## Frozen contracts

### 1. Capture views are deferred or host-resolved

`CaptureView` currently mixes two kinds of value: deferred diagnostic views that
the deferred renderer services through its own `FixedRenderPassId::CaptureView`
pass, and host-resolved views (`EngineWindow`, `Live2D`) whose target is
supplied by the host's `CaptureTargetResolver`.

[`deferred_renderer.cpp:611-614`](../../../engine/runtime/render/deferred_renderer.cpp#L611-L614)
expresses that split by exclusion, which is why a module name had to appear in
Render at all. Replace the exclusion with a positive predicate over the views
the deferred renderer converts, and rename the module-named host view to a
generic one:

```cpp
// True only for the views the deferred renderer produces in its own CaptureView
// pass. SceneColor is excluded because it is read back directly without
// conversion, and host views are excluded because the host resolves them.
inline constexpr bool RequiresCaptureViewConversionPass(CaptureView view) noexcept;
```

The generic host view is named for its role, not for its producer. A host
registry is deliberately **not** introduced: one host has one such view, so a
registry would be an abstraction with no second consumer yet.

### 2. Resize is a launch-time sequence, not a new runtime channel

The viewer window extent is hard-coded and the command transport is refused in
`live2d-viewer` mode, so nothing can currently change the output extent without
a user dragging the window. A validation-only launch option follows the
precedent and the recorded justification of `--exit-after-capture`
([`launch_options.h:41-44`](../../../engine/runtime/launch_options.h#L41-L44))
and drives the same programmatic resize the graphics example already uses
([`rhi_example.cpp:734`](../../../engine/example/graphics/rhi_example.cpp#L734)).

## Expected implementation ownership

- `engine/runtime/render/render_capture_service.*` — the generic capture-view
  value and the deferred predicate; no Live2D name;
- `engine/runtime/render/deferred_renderer.*` — consume the predicate;
- `engine/runtime/screenshot/` — capture-view string mapping;
- `engine/runtime/launch_options.*` and `engine/module/live2d/live2d_viewer_host.*`
  — the resize sequence and the shutdown count;
- `engine/module/live2d/render/live2d_renderer.*` — resize and handle-count
  behavior only; no new rendering capability;
- `engine/test/unit/live2d/`, `engine/test/unit/render/` — resize and capture
  coverage; a shared backend test double if one is justified;
- `tools/kp.ps1`, `tools/` — a Live2D validation rule;
- `asset/` — a redistributable fixture, once its terms are approved.

Live2D must not gain Render, Graphics, or Editor dependencies, and Render must
not gain a Live2D name.

## Validation ladder

L2D5 changes a Render contract and runtime launch options but no shader or RHI
behavior. Aggregate evidence is:

```powershell
cmake --build build --config Debug
ctest --test-dir build -C Debug
```

Runtime evidence uses the standalone viewer, which is a host mode of
`KimPeanutEngine.exe` and **not** a separate binary:

```powershell
KimPeanutEngine.exe --mode live2d-viewer --graphics-api <opengl|vulkan> \
  --capture save/screenshots/validation/<name>.png --capture-view live2d
```

Captures must stay under `save/screenshots/validation/`, end in `.png`, and not
disturb captures from other tasks. Cross-backend comparison uses
`tools/compare_capture_regions.py` with the frozen L2D4.0 tolerances; it requires
equal dimensions, so captures taken before and after a resize are compared
against the other backend at the same extent, never against each other.

Run the established SDK-off configure/build path from L2D1 as a separate gate.
If the capture-view change reaches a common Asset/AssetImport contract despite
the planned Render-only boundary, also build and run the Asset suite.

Record commands, fixture and license status, reference revisions, and the
first/final failures in the L2D5 implementation journal.

## Stop conditions

Stop and revise the plan if:

- the generic capture view cannot be introduced without a Render-side registry
  or a module-owned type in a common contract;
- resize evidence can only be produced by a mechanism that changes the viewer's
  production behavior;
- a redistributable fixture cannot be produced or licensed, so item 9 or 10
  cannot be evidenced;
- closing item 11 would require publishing or redistributing a licensed asset
  in a way its terms do not permit;
- the official-reference comparison passes only by loosening the frozen L2D4.0
  tolerances.
