# L2D6.1 — Typed Animation Product and Import

- Status: proposed
- Parent: [L2D6 — Authored Motion and Expression Playback](L2D6.md)
- Depends on: [L2D6.0](L2D6.0.md)

## Goal

Replace ambiguous optional-chunk interpretation with a bounded, deterministic
Product V2 representation for authored motions and expressions while retaining
V1 read compatibility and Asset-core independence.

## Import contract

Parse only the relevant `model3.json` structure:

- `FileReferences.Motions[group][index].File`;
- optional finite, non-negative `FadeInTime` and `FadeOutTime` overrides;
- optional `Sound`, preserved opaquely for later Audio integration;
- `FileReferences.Expressions[index].Name` and `.File`;
- parameter-target entries under top-level `Groups`, including EyeBlink and
  LipSync IDs.

Resolve every path through the existing asset-root containment checks. Group
and expression names are data, never paths. Reject duplicate expression names,
empty/NUL names, invalid scalar types, sparse/non-array motion groups, path
escape, missing/empty files, oversized counts/data, and malformed referenced
JSON. Validate the whole source closure before publishing Texture products or
the root product.

The offline validator checks the bounded motion/expression JSON structure
without exposing Cubism through AssetImport. The SDK parser performs a second
consistency check transactionally during instance creation in L2D6.2.

## Product and codec

- Increment `product_version`; do not reinterpret V1 bytes.
- Increment the Live2D import-provider version so source/import metadata cannot
  accept a stale V1 result as a V2 no-op hit.
- Serialize explicit counts and bounded byte lengths with checked arithmetic.
- Canonically sort motion-group object keys bytewise; preserve motion-entry,
  expression, and parameter-group array order.
- Store motion identity as group plus array index.
- Store model3 fade presence separately from its value so absent overrides use
  the motion file/default behavior.
- Store optional sound bytes directly on the motion definition; do not create
  an Audio asset or infer playback policy.
- Preserve ordered parameter groups and reject duplicate group names, duplicate
  IDs within a group, unsupported targets, and invalid IDs.
- Reject duplicate motion keys during parse.
- Parse into temporary data and publish only after the entire object validates.
- V1 parses to empty motion/expression vectors and retains its optional chunks.
- Preserve the existing immutable-output collision rule. Upgrading an existing
  V1 root requires a new explicit output path; in-place replacement/reimport UI
  remains L2D10 work.

## Tests

- V1 golden bytes still parse and reserialize under their documented version.
- V2 golden bytes round trip deterministically.
- Reimporting the same source produces identical root bytes and dependencies.
- Provider-version metadata distinguishes V1 and V2 imports; an existing V1
  output is never overwritten implicitly.
- Canonical motion-group order, authored array order, names, fade-presence bits,
  exact clip bytes, parameter groups, and optional sound bytes survive round
  trip.
- Truncation at every field boundary, count/size overflow, duplicate keys,
  empty/NUL or over-limit names, NaN/infinite/negative fades, bad JSON, wrong
  referenced extension, missing files, and traversal fail without publication.
- A V1 resource reports an empty authored library and a stable reimport-required
  diagnostic when playback is requested.
- Asset and AssetImport common targets gain no Live2D type, include, or branch.

## Gate

Product/import focused tests pass, existing L2D import tests remain green, V1
compatibility is proven, animation/source-closure validation fails before any
new product publication, and every failure leaves the requested root absent.
Only then may runtime SDK clip construction depend on the new typed library.
