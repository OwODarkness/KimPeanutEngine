# L2D9 — Speech-driven Live2D behavior

Status: proposed. Parent: [Live2D roadmap](../TODO.md). Cross-module design:
[Conversational Audio](../../audio/PLANS.md). Dependencies: Audio
[A2](../../audio/.plan/A2.md) for a played-frame speech envelope and session
[C1](../../audio/.plan/C1.md) for the end-to-end turn loop.

## Input and update order

Extend `Live2DFrameInput` with a copied, SDK-free speech sample: turn/voice
generation, played-frame timestamp or presentation time, normalized 0..1
mouth-open value, and a validity/speaking state. The application adapter
samples the Audio telemetry on the game thread and owns smoothing and latency
calibration; Live2D never reads an `AudioPlayer` or TTS provider. Use a
documented timeout: a stale, missing, paused, cancelled, or underrun sample
decays to closed instead of freezing the mouth.

The imported product already preserves the model's `LipSync` effect IDs. At
instance creation resolve only valid parameter IDs; a model without them
continues to animate with a nonfatal capability diagnostic. Apply speech
contribution in the existing canonical `AdvanceFrame` transaction after
primary motion/expression and before `UpdateModel`, with a documented
blend/priority rule. It must not overwrite unrelated mouth expression
parameters or shared asset data. Character replacement clears the old
generation. The speech bubble displays text from the session and may stay
available when audio/SDK is absent.

Start with amplitude/RMS-derived opening from actually played speech. A
later viseme source can replace the scalar if its timestamp uses the same
playback clock and the selected model provides suitable authored shapes.
Audio-derived RMS cannot identify phonemes. Keep SDK-specific parameter
resolution inside Live2D Runtime and generic envelope transport outside it.

## Acceptance and validation

- [ ] Deterministic frame tests prove motion, expression, blink/physics,
  speech contribution, and final model update order with bounded 0..1 input.
- [ ] Missing lip-sync metadata, paused/underrun/stale speech, turn cancel,
  and model replacement close or retain the mouth according to the contract.
- [ ] A measured audible-to-visual offset is recorded with fixture, device,
  frame rate, and latency assumption. A visible Live2D viewer demonstrates
  speech-driven movement and a text bubble on OpenGL and Vulkan.
- [ ] SDK-off builds do not gain an Audio, TTS, or Cubism dependency in common
  Runtime; Live2D remains optional and no provider type enters its headers.

Implementation evidence belongs in a dated `.spec/journal/` entry, not here.
