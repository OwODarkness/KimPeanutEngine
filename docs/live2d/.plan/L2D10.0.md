# L2D10.0 — Viewer host decomposition and core math convergence

- Status: **in progress**
- Parent: [PLANS.md](../PLANS.md) · [TODO.md](../TODO.md)
- Prerequisite for: [L2D10 engine/editor integration](../TODO.md)
- Related: [L2D7.5 viewer debug tools](L2D7.5.md) and
  [L2D8 semantic behavior](L2D8.md)

## Goal

Reduce `Live2DViewerHost` to a lifecycle and scheduling coordinator, then move
Live2D-specific editor UI into `engine/module/live2d/editor/` and semantic
emotion decisions into `engine/module/live2d/emotion/`.
During the same migration, replace module-local geometric types with the
canonical types from `engine/runtime/core/math` without changing the public
Runtime/Render ownership boundaries.

## Current state

The first extraction pass now places copied viewer state and ImGui rendering in
`editor/`, command registration in an editor bridge, and deterministic emotion
planning plus callback orchestration in `emotion/`. The next pass moved bubble
presentation into `editor::Live2DViewerBubble` and semantic replay/orchestration
into `Live2DEmotionRuntime` under `emotion/`; the host now schedules those collaborators
instead of storing their state. The host still owns GPU resource lifetime,
frame scheduling, input routing, and the model renderer while the preview-session
split is intentionally deferred until those boundaries have more coverage.
Runtime model data and render planning now use
`kpengine::Vector2f`; SDK-native vectors remain at the Cubism boundary.

## Scope

1. Keep the host responsible for `IApplicationHost` lifecycle, event routing,
   frame scheduling, and shutdown ordering only.
2. Add an editor-side preview/session adapter that owns UI-facing state and
   translates editor actions into SDK-free Runtime calls.
3. Extract control, diagnostics, and optional bubble presentation into focused
   editor components. UI code may depend on `EditorUILib` and ImGui; Runtime
   and Render must not acquire those dependencies.
4. Extract emotion vocabulary, preset resolution, and future decision-model
   integration into `emotion/`. This layer must be UI-free and consume/produce
   SDK-free intent and action values.
5. Isolate host command registration behind an editor/command bridge so the host
   does not contain command descriptors or presentation formatting.
6. Replace `Live2DVector2` with `kpengine::Vector2f` in product-independent
   runtime/render data. Convert to and from `Cubism::Core::csmVector2` only at
   the SDK boundary. Review other two-component arrays by semantic meaning;
   keep `graphics::Extent2D` for pixel extents and `ImVec2` at the ImGui edge.
6. Add explicit layout/serialization assertions or packing conversions where
   vector data is uploaded to GPU buffers; do not rely on a math type's ABI by
   accident.

## Proposed ownership and data flow

```text
Live2DViewerHost
  ├─ Live2DPreviewSession       (model/input/playback orchestration)
  ├─ Live2DEditorUI              (ImGui panels and layout)
  ├─ Live2DEmotionController     (intent and decision-model seam)
  └─ Live2DEditorCommandBridge   (command registration and result formatting)
       │
       └─ Live2D Runtime / Render contracts
```

`Live2DViewerHost` may own these collaborators, but it must not expose ImGui
types or editor state through Runtime headers. The preview session owns mutable
preview intent and delegates model updates to `Live2DModelInstance`; immutable
product data remains Asset-owned and GPU objects remain Render/Graphics-owned.

## Migration stages

### 1. Boundary inventory

List host methods and fields by lifecycle, rendering, UI, input, commands, and
emotion/bubble policy. Add focused tests around behavior that must remain
unchanged before moving code.

### 2. Host orchestration split

Create the preview session and editor collaborators behind narrow interfaces.
Move one responsibility at a time, preserving initialization order, render
thread ownership, capture behavior, and reverse-order GPU shutdown.

Completed increment: bubble presentation is isolated behind
`editor::Live2DViewerBubble`, and emotion/replay state is isolated behind
`Live2DEmotionRuntime` in `emotion/`. The remaining increment is a
`Live2DPreviewSession` that owns model asset loading, `Live2DSystem`, and
`Live2DRenderer` behind the same lifetime contract.

### 3. Editor UI extraction

Populate `engine/module/live2d/editor/` with the control, diagnostics, and
preview panels. The panels consume copied Runtime snapshots and issue commands
through the session; they do not access Cubism objects or backend handles.

### 4. Emotion decision seam

Move preset labels, authored candidate selection, fallback ordering, and bubble
tokens out of the host. The first implementation remains deterministic and
table-driven; a later decision model can replace the resolver without adding a
UI or Cubism dependency.

### 5. Math type convergence

Replace `Live2DVector2` usages in model snapshots, canvas metadata, hit tests,
mask planning, and render extraction with `kpengine::Vector2f`. Update access
sites for its value API and add conversion helpers at Core/GPU boundaries.
Keep SDK-native `csmVector2` local to Cubism integration code.

### 6. Cleanup and compatibility check

Remove obsolete host helpers and the module-local vector type, update CMake
targets, and verify SDK-on/off builds. No behavior or file-format version
change is allowed in this stage.

## Invariants

- Runtime and Render remain free of ImGui, `EditorUILib`, and editor panel
  ownership.
- `emotion/` remains UI-free and does not depend on a decision-model provider;
  provider integration is an injectable seam for a later stage.
- The Cubism framework lifetime and GPU destruction ordering do not change.
- Live2D product serialization remains byte-compatible; math-type migration is
  an in-memory/API cleanup only.
- `graphics::Extent2D`, `ImVec2`, and `csmVector2` remain at their respective
  subsystem boundaries rather than being replaced indiscriminately.
- Viewer emotion, bubble timing, command results, captures, and OpenGL/Vulkan
  output retain their existing semantics.

## Acceptance criteria

- [x] Host orchestration no longer contains direct ImGui panel implementations,
  emotion preset tables, or command descriptor construction.
- [x] `engine/module/live2d/editor/` has explicit CMake sources and focused
  ownership for preview/editor UI.
- [x] `engine/module/live2d/emotion/` owns deterministic preset resolution and
  has no ImGui or Cubism dependency.
- [x] No product-independent public API exposes `Live2DVector2`; canonical
  `kpengine::Vector2f` is used where a geometric two-component value is meant.
- [x] SDK and GPU boundary conversions have tests or compile-time layout checks.
- [ ] Live2D focused tests, SDK-off build, and Debug Vulkan validation remain
  green; viewer capture/shutdown behavior is preserved on OpenGL and Vulkan.

## Non-goals

- No new emotion vocabulary, speech integration, asset database, or gameplay
  composition.
- No dynamic module loader or broad EditorUI redesign.
- No performance claim based solely on the refactor; measure separately under
  L2D11 conditions.
