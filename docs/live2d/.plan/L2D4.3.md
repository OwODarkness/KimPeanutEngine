# L2D4.3 — Transactional Unmasked Renderer

- Status: proposed
- Parent: [L2D4 — Model Snapshot and Common Renderer](L2D4.md)
- Depends on: [L2D4.1](L2D4.1.md), [L2D4.2](L2D4.2.md)

## Goal

Create `Live2DRender` and render all non-clipped drawable behavior correctly
before introducing a mask pass.

## API and ownership

Introduce:

```cpp
struct Live2DRenderCreateInfo;
struct Live2DRenderFrameInfo;
class Live2DRenderProxy;
class Live2DRenderer;
```

`Live2DRenderer` borrows `RenderBackend`, creates/destroys proxies, and owns the
processed-shader pipelines and common sampler transaction.
`Live2DRenderProxy` is move-only and owns model-specific GPU handles. Renderer
create info supplies processed shader data and target formats. Proxy create info
supplies validated static data, retained Texture payloads, target extent, and
mask size; neither contains file paths. Frame info supplies the matching
snapshot, transform, and model color/opacity. Each render call also receives
the active `render::FrameContext` selected for the backend's current frame
index; the renderer does not create a second uniform or descriptor lifetime
system.

Renderer initialization stages every pipeline and sampler before publication.
Proxy creation separately stages UV/index/position buffers, textures, and
targets. Any failure destroys that transaction's complete staged closure.
Proxies die before the renderer; destroy/resize are forbidden inside an active
frame and wait at the owning integration safe point.

## Render data

- binding 0: per-frame float2 positions;
- binding 1: immutable float2 UVs;
- immutable UInt16 index buffer;
- one `FrameContext::AllocateUniform` allocation per draw containing transform,
  base/model color, multiply color, screen color, and mask fields reserved for
  L2D4.4;
- one `FrameContext::AllocateResourceBindingSet` binding per submitted draw,
  with later stable-binding reuse allowed only after profiling.

Use existing `PipelineDesc`, `ResourceBindingSetDesc`, and render-target
compatibility validation. Shader source is processed through the existing
Resource path and supplied as `data::ShaderData`; `Live2DRender` does not read
or compile files through Graphics.

## Pipeline matrix

Create only required variants:

| Axis | Values |
| --- | --- |
| Pass | model |
| Blend | normal, additive, multiplicative |
| Culling | none, back |
| Mask | disabled (enabled in L2D4.4) |

Depth test/write are disabled. The target contract is one transparent
`RGBA8_SRGB` color attachment. Blend factors and premultiplication are exactly
those frozen by L2D4.0; do not infer them from engine material defaults.

## Submission

Before recording any draw, validate the entire snapshot and write its complete
position vector. Stable-sort drawable indices by the extracted order table,
skip invisible/zero-opacity/zero-index drawables, select the blend/cull
pipeline, bind the drawable texture and uniform range, bind the explicit
geometry view, and issue its indexed range/base vertex.

Return a structured result containing success/diagnostic and counters for
uploaded bytes, considered/submitted/skipped drawables, pipeline binds, and
binding allocations. Counters support tests and later profiling; they do not
become Gameplay policy.

## Tests

Build a CPU draw-list oracle from synthetic snapshots and compare renderer
recording against it for order, skip rules, ranges, texture selection,
blend/cull pipeline, and colors. Add negative tests for revision/count/range
mismatch and injected failure after each proxy resource creation step.

Run a small unmasked render case on both native backends. Readback must cover:

- transparent background;
- overlapping draw order;
- partial opacity;
- normal/additive/multiplicative results;
- multiply and screen color;
- culling enabled and disabled;
- more than two frame-slot cycles with changed positions.

## Gate

CPU oracle, `Live2DCoreTest`, `GraphicsContractTest`, and both backend smoke
cases pass. Proxy failure/shutdown live-handle counts return to baseline. Mask
code does not land until unmasked output is independently correct.
