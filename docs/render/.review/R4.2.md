# R4.2 common Graphics RT contract review

- Status: complete — R4.3 is authorized for native owner and imported-TLAS work
- Stage: [R4](../.plan/R4.md)
- Scope: API-neutral RT contract and capability gate
- Review date: 2026-09-19

## Evidence inspected

- R4.0 consumer spec and R4.1 graph-correctness review;
- common `api.h`, `graphics_capabilities.h`, `command_recorder.h`, and
  `resource_binding.h`;
- Vulkan/OpenGL backend boundaries and the existing generational handle system;
- local Sakura and gkNextEngine graphics reference notes for opaque resource
  ownership, backend isolation, and evidence-driven fallback policy;
- focused Graphics/Render tests and two-API smoke output.

## Findings and decisions

1. **Resolved — RT handles are opaque common handles.** AS and RT-pipeline
   identity uses the existing `Handle<Tag>` generation model; native Vulkan
   objects do not appear in common contracts.
2. **Resolved — RT bindings are isolated from raster bindings.** AS and
   storage-image variants use `RayTracingResourceBinding`, leaving the current
   raster descriptor managers unable to accidentally treat them as sampled
   textures.
3. **Resolved — capability reporting is all-or-fallback.** The effective gate
   requires an explicit common-contract flag plus the relevant backend feature
   set. OpenGL and the current Vulkan backend remain false until R4.3 wires a
   complete native owner.
4. **Resolved — unsupported command behavior is explicit.** Optional recorder
   operations return false by default, so a future graph pass cannot silently
   succeed on an unsupported backend.
5. **Resolved — native lifetime is deferred but specified.** The owner seam
   requires completed-submission collection and submitted-serial retirement;
   scratch storage remains Graphics-owned and is not a Render parameter.

## Open follow-up

R4.3 must implement the Vulkan owner only when the complete extension/feature
set is enabled, then import one TLAS into the graph. It must preserve the
capability gate and OpenGL/ray-unavailable fallback rather than exposing a
partial RT path.

## Decision

R4.2 is accepted as a contract stage. No native RT operation is claimed
complete, and no unrelated render/asset/editor work is included.
