## Findings

### R4.6-F1 — Resolved 2026-09-22: null callable SBT pointer violated `vkCmdTraceRaysKHR`

Location:
`engine/runtime/graphics/backend/vulkan/vulkan_acceleration_structure_owner.cpp:582-583`

`TraceRays` passes `nullptr` as `pCallableShaderBindingTable`. The Vulkan
implicit-validity rule requires this argument to be a valid pointer to a valid
`VkStridedDeviceAddressRegionKHR`, even when the pipeline has no callable
shader. The no-callable representation is a zero-initialized region passed by
address.

The callable region is now zero-initialized and passed by address. The corrected
runtime reached and executed `vkCmdTraceRaysKHR` on the Cornell fixture, so the
original dispatch blocker is resolved. The prior root-cause explanation was
supported by the corrected run, though the historical minimal sentinel probe
and a focused assertion for all four region pointers were not recorded as
separate artifacts.

Authoritative contract:
[vkCmdTraceRaysKHR implicit valid usage](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdTraceRaysKHR.html).
The official example likewise passes the address of a zeroed callable region:
[raytracingbasic.cpp](https://github.com/SaschaWillems/Vulkan/blob/master/examples/raytracingbasic/raytracingbasic.cpp#L3304-L3356).

This resolves the implementation and evidence gap for the tested device. The

### Open findings

**R4.6-S1 [P1] — RT is automatically selected without a user policy.**
`deferred_renderer.cpp:534` prepares the RT pipeline from hardware capability;
`:1254` prepares AS data each frame; `:1282` chooses ray-query shadows and
`:1317` selects path tracing from availability/TLAS/scene/capacity. The inspected
configuration, bootstrap, RenderSystem, Editor, and command-provider paths have
no rendering-mode switch. Probe and fault-injection controls are diagnostics,
not an RT enable/disable policy. A capable GPU can therefore switch an ordinary
level into the experimental path tracer automatically. Status: open.

**R4.6-S2 [P1] — Sponza execution has no clean evidence; the descriptor pool
implementation remains fragile.** `vulkan_acceleration_structure_owner.cpp:457`
sizes pools from supplied binding writes, one descriptor per write, rather than
the allocated layout's descriptor counts. Partial writes or descriptor arrays
can under-budget allocation; the preceding log demonstrates that condition.
The current five-binding path may avoid the historical 32-storage request but
does not repair this general allocator defect. Size pools from the complete
layout and validate writes/types/counts independently. Vulkan requires matching
shader/layout descriptor types and defines allocation against layout demand:
[RT pipeline contract](https://docs.vulkan.org/refpages/latest/refpages/source/VkRayTracingPipelineCreateInfoKHR.html),
[descriptor allocation contract](https://docs.vulkan.org/spec/latest/chapters/descriptorsets.html).
Status: open; historical Int64/type errors require a clean rerun after Asset loads.

**R4.6-S3 [P1] — Device-address exposure violates the accepted module boundary.**
`graphics/backend/common/ray_tracing.h:208` now exposes
`GetBufferDeviceAddress`; `deferred_renderer.cpp:3211` fetches GPU addresses and
packs their words into shader records. The R4.6 spec explicitly forbids device
addresses entering Render contracts. Keep Render-owned semantic geometry and
material records, and let Graphics resolve buffer handles/offsets and encode
native shader lookup addresses. Status: open architectural regression in the
pre-existing working-tree changes; no ownership changes made by this review.

**R4.6-S4 [P2] — The shared shadow TLAS omits visible non-shadow-casters.**
`deferred_renderer.cpp:866` skips proxies with `casts_shadow=false`, even though
the same scene is used for primary and secondary path-trace rays. Such geometry
disappears from path tracing. Include visible RT surfaces independently of
shadow policy; express shadow exclusion through an explicit ray/instance policy
or separate consumer data. All currently authored Sponza objects cast shadows,
so this is a general correctness defect, not a proven cause of this run's zero
records. Status: open.

**R4.6-S5 [P2] — General scene appearance still uses Cornell assumptions.**
`deferred_renderer.cpp:103,949` resolves one scalar `base_color` per proxy;
`ray_tracing_path_tracer.rchit:103` reconstructs a flat face normal and
`:111` uses the instance color. There is no per-section textured material,
interpolated normal/UV, normal-map, roughness/metalness, or alpha-cutout shading.
The raygen miss path returns black instead of the authored environment.
`deferred_renderer.cpp:1259` infers Cornell from one mesh with 6–8 geometries,
so an unrelated scene can receive Cornell colors/emitter. In addition,
`ray_tracing_path_tracer.rgen:152` excludes secondary geometry index 0 even in
generic mode; that index can be an ordinary Sponza surface, not an emitter.
Explicit fixture/integrator selection and material/light contracts are needed.
Status: open; general Sponza shading was outside the accepted Cornell non-goals.

**R4.6-S6 [P2] — A 512-record limit is a guard, not scalability evidence.**
`deferred_renderer.cpp:64,1289` and the shader's 512-entry tables impose separate
geometry/instance caps. `PathTracingSceneGpuData` is a 32 KiB uniform block;
validate it against actual uniform-range/allocation limits. The log shows zero
records, not a count above 512, so capacity must not be claimed as the measured
failure. `vulkan_backend.cpp:563` can also return no geometries when any section
is invalid; instrument rejection reasons and loaded proxy/section counts.
Status: open diagnostic/scalability gap.

### Required optional-rendering contract (proposed; not implemented)

Use explicit user selection, independent of device capability:

| Requested mode | Required behavior |
|---|---|
| Raster / RT off (normal startup default) | Raster shadows and lighting; no RT pipeline, SBT, AS builds, bindings, history, or dispatch required. Unsupported hardware must still render. |
| Raster with ray-query shadows | Keep raster scene shading; use AS/query only for supported shadows. Do not prepare or activate the path tracer. |
| Path tracing (explicit opt-in) | Activate only with supported pipeline features, ready assets, valid scene records, and capacity. Report unavailable/failure reason explicitly. |

A master RT-disable policy must override both RT consumers. Persist/propagate
the selection through startup configuration and a render-thread-owned policy;
an Editor/Runtime control may request changes through the existing thread
handoff. Do not mutate renderer state directly from the UI or command thread.
Capability reports hardware support; requested mode and effective mode report
policy. Publish those plus a reason and sample/reset counts in stats.

When changing modes, stop scheduling disabled consumers immediately, reset
path-trace history on re-entry, and retire GPU objects only after submitted work
is safe. An interactive unsupported request may fall back with an explicit
reason; an explicitly requested validation run must not silently count raster
fallback as RT success. Graphics continues to own native GPU lifetime.

### Main current cause: the path tracer reads the fallback material

Sponza uses imported section materials. `level_loader.cpp:134` supplies the
engine error material when an extensionless model reference has no explicit
material override. `level/level_instance.cpp:472–528` fills imported material
slots while retaining the fallback; `render_scene_coordinator.cpp:120–155`
publishes both default and section handles. `render_world/mesh_proxy.h:35`
provides `GetMaterialForSection` for this distinction.

The RT scene preparation instead calls
`ResolvePathTracingAlbedo(material_system_, proxy.material)` at
`deferred_renderer.cpp:949` and stores **one color per instance**. Closest-hit
then uses `instance.albedo` for every geometry in that instance. It never looks
up the section material or samples its base-color texture.
`asset/material/error.material` has `base_color=[1,0,1,1]`; the primary-albedo
probe is uniformly magenta. Source data flow and the independent live probe
support this as the immediate cause of the wrong surface colors. Fix the
instance/geometry-to-section-material mapping, then add UV/texture evaluation;
changing exposure or adding samples cannot repair this mapping.

### Separate cause of darkness: incomplete generic-scene illumination

The authored level includes an HDR environment and a 250-intensity point fill
light. Generic RT preparation at `deferred_renderer.cpp:1265` selects only the
first directional light; raygen `DirectLight` handles that sun and primary
misses return black. Neither environment illumination nor the point fill is
evaluated. With the architecture occluding much of the directional sun, the
direct-only probe is almost black. Beauty adds only one diffuse bounce, so it
cannot reproduce the raster scene's authored illumination. Alpha-cutout support
also remains absent: BLAS geometry is flagged opaque at

### Exact blocking verification flow

1. `level_loader.cpp:507` resolves each logical model key using

   schedule its model dependencies until these resolutions finish.
3. `native_model_loader.cpp:67` reads that same model again and computes
   `Sha256WithZeroedRange`. `model_archive.cpp:453` computes two complete hashes:
   the content hash and the hash with the embedded digest field zeroed.
   Archive verification and deserialization reuse this pair, but do not reuse
   the preceding logical resolver's validation.

Therefore each of the three model products receives **three full hash passes**
before use: resolver content hash, loader content hash, loader embedded digest
hash. Across the products this processes approximately 847 MB of hash input.
The SHA-256 implementation is scalar C++ in `model_archive.cpp`.
`build/engine/runtime/asset/AssetProduct.vcxproj` confirms Debug optimization
and inlining are disabled with runtime checks enabled. This explains why the
hash loop is an expensive CPU operation in this configuration; no optimized
build comparison or CPU frequency diagnosis was performed.
