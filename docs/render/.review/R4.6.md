R4.6 is not accepted. A real `vkCmdTraceRaysKHR` call exits the process in
both the closest-hit probe and a reduced raygen/no-TLAS probe. Pipeline creation
and bind-only preparation are not rendering evidence, and the retained raster

The reduced probes move the first unresolved boundary below the Cornell scene

## Findings

### R4.6-F1 — Resolved 2026-09-22: null callable SBT pointer violated `vkCmdTraceRaysKHR`

Location:
`engine/runtime/graphics/backend/vulkan/vulkan_acceleration_structure_owner.cpp:582-583`

`TraceRays` passes `nullptr` as `pCallableShaderBindingTable`. The Vulkan
implicit-validity rule requires this argument to be a valid pointer to a valid
`VkStridedDeviceAddressRegionKHR`, even when the pipeline has no callable
shader. The no-callable representation is a zero-initialized region passed by
address.

The callable region is now zero-initialized and passed by address. The corrected
runtime reached and executed `vkCmdTraceRaysKHR` on the Cornell fixture, so the
original dispatch blocker is resolved. The prior root-cause explanation was
supported by the corrected run, though the historical minimal sentinel probe
and a focused assertion for all four region pointers were not recorded as
separate artifacts.

Authoritative contract:
[vkCmdTraceRaysKHR implicit valid usage](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdTraceRaysKHR.html).
The official example likewise passes the address of a zeroed callable region:
[raytracingbasic.cpp](https://github.com/SaschaWillems/Vulkan/blob/master/examples/raytracingbasic/raytracingbasic.cpp#L3304-L3356).

### R4.6-F2 — Resolved 2026-09-25: SBT and dispatch limits are validated

Locations:
`engine/runtime/graphics/backend/vulkan/vulkan_acceleration_structure_owner.cpp:289-343`
and `:551-584`

The Vulkan owner now calculates each SBT stride as a multiple of both handle
and base alignment, rejects unsupported handle/stride/recursion properties,
allocates base-alignment padding and aligns the SBT address inside the buffer,
checks all dispatch invocations against `maxRayDispatchInvocationCount`, and
logs one concise snapshot of the queried limits and raygen/miss/hit/callable
regions. Four focused helper tests cover layout, padded address, recursion, and
dispatch bounds.

On the RTX 4070 Laptop GPU, the live log reported handle size/alignment 32,
base alignment 64, max stride 4096, recursion 1/31, and dispatch limit
1,073,741,824. All three region addresses were 64-byte aligned with stride and
size 64; the callable region was zero. The corrected Vulkan runtime dispatched
at 1094×619, accumulated 10,636 samples, and closed after a window-close request.
The captured stdout/stderr contained no `VUID-` or `Validation Error` text.
`GraphicsContractTest.exe` passed 29/29 and full Debug CTest passed 974/974.

This resolves the implementation and evidence gap for the tested device. The
current evidence is not a multi-vendor portability matrix.

The applicable alignment and dispatch constraints are listed in the
[Khronos command reference](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdTraceRaysKHR.html).

### R4.6-F3 — Historical diagnostic gap; original crash no longer reproduces

Locations: `save/logs/r46-runtime19.stdout.log` through
`save/logs/r46-runtime35.stdout.log`, and
`engine/runtime/graphics/backend/vulkan/vulkan_device.cpp:37-56`

The reduced runs preserve neither a Windows exception/exit code nor a
submission/fence result. The later stdout files terminate in a partially
flushed startup buffer, stderr is empty, and there is no captured VUID or
`VK_ERROR_DEVICE_LOST`. Because `vkCmdTraceRaysKHR` returns `void`, logging only
after the call cannot identify whether the host died while marshalling the
command or the submitted work later faulted on the device.

The corrected runtime no longer reproduces the original exit. Preserve this
finding as historical evidence; detailed command/submit/fence markers are not
a current stage blocker. If a future failure recurs, capture the following:

- put durable markers immediately before and after command recording, command
  buffer close, queue submit, and fence wait;
- capture the process exit/exception code and the first validation callback;
- enable synchronization and GPU-assisted validation for the minimal probe
  when available, then use a GPU debugger only if the corrected API contract
  still exits without a VUID.
