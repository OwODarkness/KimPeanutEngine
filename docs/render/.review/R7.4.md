# R7.4 review — Exponential height fog

- Status: accepted on 2026-11-06.
- Scope: [R7.4](../.plan/R7.md#r74--exponential-height-fog) on `f1f2734`
  plus the existing startup/owner worktree and the R7.4 changes.
- Evidence: [validation journal](../../../.spec/journal/2026-11-06-render-r7-4-height-fog.md).

| Gate | Evidence |
| --- | --- |
| Numeric limits | GPU captures match the homogeneous, horizontal, uphill and downhill analytic limits within 0.003 linear transmittance on both APIs; increasing distance reduces transmittance. |
| Sky | Sky is white in the transmittance view with sky fog disabled; opt-in uses the finite ray cap. |
| Bypass | Zero-density scene captures are byte-identical to disabled fog in Sponza, indoor and terrain preview runs. Vulkan PT does not schedule fog. |
| HDR order and history | Graph tests prove distinct fog output feeds TAA or direct tone map. Runtime history resets on fog edit and recovers. |
| Visual and lifetime | Vulkan/OpenGL Sponza, indoor and terrain preview captures; no Vulkan validation VUIDs in the Debug runs. |
| Fog GPU cost | Vulkan RelWithDebInfo p95 0.023552 ms in all three windows; below 0.5 ms. |

Combined GPU p95 is 3.359–3.379 ms, below 8.5 ms. Combined active texture
allocation is 38,051,840 bytes (36.29 MiB), above the 32 MiB cap; resolve under
R7.5. Orthographic ray origins are defined in the shader, with no dedicated
orthographic fog capture. The baked terrain level's generated model is absent;
the procedural terrain preview exercises the same Render passes without
publishing archive products.
