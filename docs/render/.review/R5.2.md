## Findings and remediation

### R5.2-F1 — P1, open: injected failure and abort acceptance is missing

The bridge prepares native storage and temporary instance/scratch buffers before graph transitions (`vulkan_acceleration_structure_owner.cpp:980–1148`); recording consumes the token and queues buffers for retirement (`:1321–1348`), while cancellation queues unused prepared buffers (`:1151–1159`). `RetireSubmitted` assigns a submission serial and collection waits for its completion (`:1503–1538`). The fresh event history now confirms the successful cold/update/submission/retirement paths. The historical TLAS failure and untested partial-failure/abort cleanup still make the remaining work a correctness gate, not paperwork.

**Evidence:** fresh Debug Vulkan Cornell run recorded cold BLAS+TLAS on frame 3 and retired both at serial 4. A runtime transform produced a TLAS-only update on frame 5108 and retired it at serial 5109. Fresh Sponza runs recorded cold BLAS+TLAS and retired both at serials 9956 (PT) and 21367 (raster/query). All records included nonempty physical signatures and no failures. Prepared-but-never-recorded batches are immediately reclaimed; recorded batches remain queued until submission completion.

**Still required:** deterministically inject partial preparation failure, recording failure after at least one BLAS command, and abort before submission; verify required dependents, PT history and token/lease cleanup. Verify an unchanged frame performs no new preparation allocation. The event ring and ordinary successful lifecycle path alone do not close F1.

**Additional evidence (2026-09-28):** the one-shot required PT failure is now
retained in `stats --json` after the failed frame. A fresh Debug Vulkan Cornell
run retained frame 2215 with path tracing `failed`, ray-tracing tone map
`skipped_dependency`, and 8,840 path-trace samples. The failure snapshot is
`save/diagnostics/r5-2-cornell-required-failure-exact.json`; the immediately
following frame recovered. This closes the exact-frame observation gap for the
existing PT dispatch rejection, but does not replace the still-required AS
partial-prepare, partial-record, or pre-submit-abort injection.

### R5.2-F2 — P1, addressed in source: RT callbacks use declared physical bindings

BLAS/TLAS build callbacks now obtain the recorder and the target, geometry, BLAS, instance-input and scratch groups through `RenderGraphPassContext`, then validate every requested handle against those groups. PT and ray-query descriptors use the declared `SceneTlas`; address-table vertex/index buffers are explicit `SceneGeometry` reads. Cornell cold-build and update runs plus Sponza PT and raster/query runs exercised these paths. A dedicated foreign-group negative test is still desirable.

### R5.2-F3 — P2, addressed and regression-tested: external failure remains sticky

Typed external callbacks return success/failure to the cursor. Transition failure records `Failed` and its diagnostic; a rejected duplicate cannot clear it. `RenderGraphExecutorTest.ExternalTransitionFailureStaysFailedAfterDuplicateRejection` exercises failure, duplicate rejection and finalization.

### R5.2-F4 — P2, addressed and regression-tested: ignored context violation fails the pass

Context resolution records undeclared handle/role or wrong-access requests. The executor rejects a callback that ignores the violation and includes pass identity in its diagnostic. `RenderGraphExecutorTest.IgnoredUndeclaredLookupFailsTypedPassRecording` covers the ignored-lookup case; foreign-generation and wrong-intent permutations remain useful additions.

### R5.2-F5 — P2, source remediation implemented: prepared token owns a build snapshot

Prepared batches own mode, geometry and instance copies. Build validates targets, every geometry field, instance contents and the exposed instance/scratch lists against the token snapshot before recording, then records from that snapshot. Add a Vulkan-owner contract test for altered mode/count/input, token reuse and resource mismatch before calling F5 fully verified.
