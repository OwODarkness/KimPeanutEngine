## Scope and baseline

This review covers the current uncommitted R1.2 implementation: the concrete
`DeferredRenderer`, its initialization/frame/cleanup contracts, delegation from
`RenderSystem`, target and pass-private GPU ownership, capture and resize
handoffs, focused backend-probe tests, and the matching plan/spec/journal and
Render module documentation.

out of scope except where the R1.2 implementation would give those stages an

## Review round 1 — 2026-09-02

### F1 — partial fullscreen-resource creation leaks the successful handle

- Priority: P2
- Location: `engine/runtime/render/deferred_renderer.cpp:1125-1145`
- Status: addressed

`PrepareFullscreenPassResources()` returns early only when both the mesh and
sampler are valid, but otherwise recreates and overwrites both members. If mesh
creation succeeds and sampler creation fails, the next frame overwrites the
valid mesh handle without destroying it. The symmetric sampler-only success
has the same problem. A persistent partial failure leaks one GPU resource on
every retry, and `Cleanup()` can retire only the last stored handle.

`PrepareFullscreenPassResources()` now creates only the missing half of the
pair, retaining a successful mesh or sampler across retries. Failure-injection
tests cover both failure directions and verify the successful half is destroyed
once during renderer teardown.

### F2 — the ownership probe does not verify pass-private handle destruction

- Priority: P2
- Location: `engine/test/unit/render/render_system_test.cpp:49-55, 463-481, 549-555`
- Status: addressed

The backend probe records pipeline, mesh, and sampler create/destroy counts,
but the R1.2 assertions compare only render-target counts. The direct renderer
test initializes targets but never records a frame, so it creates none of the
lazy pass resources whose ownership R1.2 is meant to prove. The orchestration
test can therefore pass while a pipeline, fullscreen mesh, or sampler is
leaked, double-destroyed, or destroyed after the wrong boundary.

The orchestration test now exercises lazy preparations through normal frame
recording, compares pipeline/mesh/sampler creation and destruction counts, and
checks that the last destruction of each kind precedes `backend_cleanup`.
Dedicated injected mesh/sampler failures cover the partial-preparation paths;
resolver-owned bindings remain outside the renderer's direct handle state.

### F3 — moved pass helpers remain duplicated in the facade translation unit

- Priority: P2
- Location: `engine/runtime/render/render_system.cpp:51-262`
- Status: addressed

R1.2.E requires the moved helpers and includes to leave `render_system.cpp`, but
the file still contains the point-shadow constants, `CaptureViewGpuData`,
shadow bounds/matrix/frustum helpers, and related heavy includes. These symbols
are unused by `RenderSystem` and have second copies in `deferred_renderer.cpp`.
The facade therefore still carries pass-specific implementation text, debug
compile cost, warning/instantiation noise, and a future drift trap despite the
claimed extraction boundary.

The duplicated pass-only block and now-unused pass includes have been removed.
The facade retains only helpers needed by lifecycle and resource-ingestion code.

### F4 — `normal_recording_completed` always reports success

- Priority: P3
- Location: `engine/runtime/render/deferred_renderer.h:66-70`,
  `engine/runtime/render/deferred_renderer.cpp:399-451`
- Status: addressed

`DeferredRendererFrameResult::normal_recording_completed` defaults to `true`
and is never assigned from schedule validity, target/recorder availability, or
any pass outcome. The current facade ignores the field, but the R1.2 plan
defines it as the renderer's normal-recording result and R1.3 is expected to
build a fail-soft outcome policy on this seam. Leaving an unconditional success
value makes the contract misleading and unsafe for the next stage.

The unconditional field was removed. R1.3 will introduce the typed per-pass
outcome contract when declaration and execution are unified, avoiding a
pre-R1.3 success value that cannot describe the current fail-soft recorder list.

## Review round 2 — 2026-09-02

The four implementation findings are addressed in the current working tree:

- Fullscreen resource creation retains successful partial state across retries.
- Deferred-lighting preparation is idempotent after its pipeline and bindings
  become valid, preventing repeated frame preparation from overwriting a live
  pipeline handle.
- Normal recording and injected partial failures now exercise renderer-owned
  pipeline/mesh/sampler cleanup assertions.
- Pass-only helpers and includes no longer remain in `render_system.cpp`.
- `normal_recording_completed` is deferred until R1.3's typed outcome seam.

The focused and full validation gates have now passed, including direct
RenderSystem lifecycle execution, complete CTest, GraphicsSmoke on both APIs,
and fresh Vulkan/OpenGL startup-level captures.

## Positive observations

- `RenderSystem` remains the backend/frame-bracket and public-capability owner;
  `DeferredRenderer` neither begins nor ends backend frames.
- Targets, schedule, environment/shadow state, pass methods, and pass-private
  handles have moved to one concrete, non-polymorphic collaborator.
- Renderer initialization rolls a partial target set back before backend
  cleanup, and renderer cleanup precedes resolver and backend cleanup.
- Capture request ownership stays on `RenderCaptureService`, while target and
  diagnostic-conversion knowledge stays in the renderer.
- Common contracts expose no Vulkan or OpenGL implementation types.
