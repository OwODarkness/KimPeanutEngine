## Review round 1 — implementation self-review

The implementation-authored review recorded the following risks and
resolutions. They are preserved here as the first review round rather than
being overwritten by the independent review.

| Priority | Finding | Disposition recorded by implementation |
| --- | --- | --- |
| P1 | Source sink addresses could be invalidated if extraction replaced registries during initialization. | Fixed by making `RenderSceneCoordinator` a stable concrete `RenderSystem` member. `RenderSystemTest.KeepsSourceSinkAddressesStableAcrossRetry` covers rollback and retry. |
| P1 | A backend frame could remain open when active frame context/recorder acquisition failed. | Fixed by ending the backend frame, clearing active pointers, and remaining `Ready`; `RenderSystemTest.UnwindsBackendFrameWhenNoRecorderIsAvailable` covers it. |
| P1 | Editor recovered a Vulkan bridge by casting the full general `GraphicsContext` payload. | Fixed with borrowed `IEditorPresentationBridge`; API-specific adapters validate their concrete bridge before native setup. |
| P2 | The facade exposed a full `RenderTarget` and stale `Tick`/`PostInitialize` paths. | Fixed with value `RenderTargetView`, metrics snapshot, and removal of unused lifecycle wiring. |
| P2 | Strict cross-backend silhouette comparison rejected a bounded edge-only rasterization difference. | Resolved with independently bounded edge (24) and structural (3) metrics, exact contour bounds, and synthetic translation/thin-feature rejection. |

The architecture direction from this round remains sound: Gameplay retains
copied source commands, `RenderSceneCoordinator` owns Render scene policy and
CPU snapshots, `DeferredRenderer` owns pass state and targets, Graphics owns
GPU/native execution, and Editor owns ImGui policy. The common presentation
bridge carries no Vulkan or OpenGL implementation types.

## Review round 2 — independent findings

### R1.5-F1 — P1 — The silhouette comparator can accept a globally displaced model

**Location:** `engine/example/graphics/rhi_example.cpp:1737-1788`

Every mismatch is discarded when the opposite image contains any model pixel
within a 3x3 neighborhood. There is no limit on the number of discarded
`edge_displacement` pixels; the 16-pixel budget applies only to mismatches left
after that filter. Consequently, translating an entire silhouette by one pixel
can pass with zero counted differences. The synthetic review probe demonstrates
that behavior with 12 raw mismatches. This contradicts the journal's claim that
the policy cannot accept moved geometry and makes the R1.4/R1.5 visual gate
false-green.

**Required change:** Count and bound the displaced-edge population as a
separate metric, or compare against per-backend approved baselines using a
bounded contour/area/centroid policy. Add synthetic tests that reject whole-
model translation and removal of one-pixel-thick features while permitting the
known 19-pixel backend edge variation.

**Resolution:** Counted edge displacement is bounded independently from
structural differences; model area may differ by at most one pixel and contour
bounding boxes must match. Synthetic probes reject a one-pixel whole-model
translation and removal of a separated thin feature, while the live baseline
records `raw=19`, `edge=16`, `structural=3`, and `area_delta=1`.

**Status:** Addressed.

### R1.5-F2 — P1 — Runtime ignores a failed frame begin and still records/presents Editor UI

**Location:** `engine/runtime/engine.cpp:534-550`,
`engine/runtime/render/render_system.cpp:127-150`, and
`engine/runtime/graphics/backend/vulkan/vulkan_backend.cpp:113-120`

`RenderSystem::BeginFrame()` now has an explicit `false` result when no active
frame context exists, including the normal Vulkan out-of-date swapchain path.
`Engine::RenderTick()` ignores that result, runs the editor composite fallback,
calls `EndFrame()`, and may swap OpenGL buffers anyway. This defeats the new
frame-bracket contract precisely on the recoverable backend path it is meant to
represent; Editor work may be built or submitted without an active Render
frame, and the diagnostic is not surfaced.

**Required change:** Make the production caller branch deliberately on
`BeginFrame()`. On a recoverable skipped frame, poll events and skip all frame
recording/presentation; on a fatal failure, propagate the diagnostic into the
existing render-thread failure path. Add a Runtime-level regression for the
failed-begin path, not only the direct `RenderSystem` unwind test.

**Resolution:** Runtime now classifies a failed begin in the `Ready` state as a
recoverable skipped frame, polls events, and performs no Editor recording,
`EndFrame`, or OpenGL swap. Any other failed-begin state escalates the Render
diagnostic through the existing render-thread exception path. The Runtime frame
policy regression covers both dispositions.

**Status:** Addressed.

### R1.5-F3 — P2 — Editor UI initialization is not transactional across the new throwing bridge path

**Location:** `engine/editor/ui/editor_ui.cpp:27-33`,
`engine/editor/ui/editor_ui.cpp:62-86`, `engine/editor/ui/editor_ui.cpp:209-220`,
and `engine/runtime/engine.cpp:459-492`

`EditorUI::Initialize()` creates the ImGui context before bridge validation and
native renderer/WSI initialization. The new null, unsupported, mismatched, and
native-resource failure paths throw. `Engine` marks the UI initialized only
after the call returns, so its catch path does not call `CloseUI()` for a
partial initialization. `EditorUI` and the Vulkan renderer have default
destructors, while `Close()` assumes both renderer and WSI are non-null. A
failed initialization can therefore retain the ImGui context and partially
created Vulkan objects until backend/device teardown.

**Required change:** Give Editor UI/backend initialization transactional RAII
semantics. Partial cleanup must be idempotent and safe for null or half-
initialized members. Cover null/wrong bridge type and a native initialization
failure with tests that prove all acquired state is released.

**Resolution:** Editor UI initialization is transactional. ImGui context,
renderer, and WSI state are tracked independently; failed renderer/WSI setup
rolls back partial backend state, and `Close()` is null-safe and idempotent.
Vulkan/OpenGL initialization now reports failure and cleans native resources on
exception. Null and mismatched bridge rollback tests pass.

**Status:** Addressed.

### R1.5-F4 — P2 — The recorded evidence does not prove all mandatory R1.5 acceptance criteria

**Location:** `.spec/journal/2026-09-04-render-system-r1-5.md:63-83` and
`engine/test/unit/render/render_system_test.cpp:543-596`

The two new focused tests prove stable sink addresses and the missing-recorder
unwind, but no test proves borrowed target-view refresh/invalidation after
resize, bridge/API mismatch behavior, coordinator drain/prepare ordering, or
the production failed-begin behavior. The journal also calls exact-PID process
termination a clean Editor shutdown; forced termination proves startup but does
not execute or verify `EditorUI::Close()`, Render shutdown, or backend teardown.
Those are explicit plan/spec acceptance items, so passing 265 total tests
does not close them.

**Required change:** Add the missing contract/integration coverage and capture
an orderly Vulkan and OpenGL shutdown through the application close path, with
exit status or teardown evidence. Correct the journal/spec completion claims to
match the evidence until those checks pass.

**Resolution:** Added borrowed-view refresh coverage, bridge mismatch and
idempotent Editor rollback coverage, coordinator/frame-order coverage through
the existing RenderSystem characterization, and a Runtime-level failed-begin
policy regression. The focused targets, full Debug build/CTest, dual-backend
smoke, and the six inspected captures pass. Runtime startup reaches the typed
Editor bridge on both APIs, but the current desktop automation surface does not
expose the native GLFW window, so orderly close-path teardown remains
unverified; the earlier forced-termination evidence is not counted.

**Status:** Partially addressed — orderly shutdown evidence remains open.

### R1.5-F5 — P2 — Durable architecture records still describe the pre-R1.5 boundary

**Location:** `docs/render/PLANS.md:39-45`, `docs/render/design.md:61-74`,
`docs/graphics/TODO.md:147-151`, and `docs/graphics/graphics_module.md:328`

The module plan says `RenderSystem` still owns source inboxes and a general
Editor graphics-context escape hatch, the design calls the landed coordinator
"proposed," and Graphics still marks/describes the typed bridge migration as
future work. These documents are project source-of-truth records, so the R1.5
completion claim currently conflicts with the documented architecture.

**Required change:** Update the durable Render and Graphics records to present
tense and mark only the actually landed bridge/facade work complete. Keep the
open review findings in the R1.5 review/TODO rather than describing the whole
stage as accepted.

**Resolution:** Render plans/design and Graphics records now describe the
landed coordinator and typed bridge in present tense; the Graphics TODO marks
the public context migration complete while retaining only private legacy
helpers.

**Status:** Addressed.

## Positive observations

- The stable coordinator member preserves the pre-initialization sink-address
  contract across rollback and retry without adding a broad interface layer.
- The common editor bridge is narrow and API-neutral; native Vulkan payloads
  remain below the backend-specific boundary.
- Missing-recorder handling closes the backend frame and keeps `RenderSystem`
  ready, and the focused test verifies that local contract.
- The implementation removes stale facade surface instead of introducing a
  parallel lifecycle, and the current build/test suite remains green.

## Disposition

R1.5 code findings F1–F3 and F5 are addressed and validated. F4 remains open
only for orderly application-close evidence; the known RuntimeLib/EditorLib
cycle and backend-private Graphics context helpers remain outside this stage.
