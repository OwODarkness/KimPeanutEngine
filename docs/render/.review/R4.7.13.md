# R4.7.13 — Guided one-SPP preview

Date: 2026-09-27. Status: optional preview path implemented and measured;
quality/lifecycle acceptance remains open.

Plan: [R4.7 GPU strategy](../.plan/R4.7-gpu.md).

## Implementation

Adds `low_spp_preview` to `render.path_trace_probe`. It traces one sample per
dispatch while retaining the 8-bounce limit and existing progressive history.
The path-trace raygen writes a primary world-normal/view-distance guide into a
renderer-owned RGBA16F target. Render declares its path-trace storage write and
tone-map sampled read in the frame graph; Graphics still owns native images and
transitions. Tone mapping applies a 3x3 spatial filter weighted by guide-normal
and relative view-depth agreement. The four-SPP Beauty reference remains the
default. No vendor denoiser is required.

## Findings

### F1 — P2, open: spatial-only guides are not full temporal reconstruction

The guide contains primary normal and view distance only. The filter has no
motion vectors, disocclusion history, roughness/albedo guides, or separate
diffuse/specular signals. It has only been inspected on a static Sponza view;
moving geometry, camera motion, material/light edits, Cornell and a third scene
remain open. Texture edges on a surface may blur, and no equal-wall-time error
metric was recorded. The new mode is explicit and must remain opt-in.

### F2 — P2, resolved: guide image lifetime and graph synchronization

The guide target is sized with path-trace history, retained by DeferredRenderer,
included as an imported graph resource with storage-write then sampled-read
uses, and destroyed after binding retirement and backend idle. Debug Vulkan
validation and live screenshot export passed without logged validation errors.

## Review verdict

Keep `low_spp_preview` as an optional interactive preview with an explicit
one-SPP quality tradeoff. Do not substitute it for the four-SPP reference or
claim equivalence. The implementation has a useful Sponza frame-time result,
but the full R4.7.13 quality gate is still open pending movement/edit tests,
multi-scene captures, convergence/error comparison and extended resize/toggle
lifecycle validation.

## Accumulated Beauty denoising follow-up — 2026-09-27

Added opt-in `beauty_denoise`, preserving the four-SPP Beauty path and its
progressive mean. Ray generation merges centered luminance sample variance per
dispatch into history alpha; the stored quantity is sample variance, not a
growing M2 sum. The existing RGBA16F history and primary guide target are
reused. Tone mapping performs one 5x5 à-trous spatial level at stride two,
weighting neighbors by luminance variance, primary normal, and relative view
depth. `beauty` stays raw, while `low_spp_preview` keeps its prior one-SPP
filter and sample budget. No new GPU resource or RHI ownership was added.

Debug build and direct `glslangValidator` compilation of the ray-generation and
tone-map shaders passed. A Debug Vulkan run selected `beauty_denoise`, reported
active path tracing at four SPP/dispatch and about 5,000 accumulated samples,
and exported a screenshot; its log had no validation/VUID or `VK_ERROR` entry.
After changing history alpha from M2 to normalized sample variance, both
shaders compiled again and the final RelWithDebInfo executable rendered the
mode on Sponza. The same RelWithDebInfo session captured raw Beauty at 5,228
samples and denoised Beauty at 6,148 samples. Its denoised Runtime profile
reported 4 SPP/dispatch, 27.56 ms total-GPU p50 and 0.085 ms tone-map p50
(diagnostic snapshot, not an isolated denoiser cost). The filtered capture is
`save/screenshots/validation/r478-relwithdebinfo-beauty-denoise-6k-1.png`; raw
Beauty is `save/screenshots/validation/r478-relwithdebinfo-beauty-raw-5k.png`.
Visual review sees less grain in dark stone/floor regions while keeping broad
folds and tile layout. The counts are close but not equal, and no numeric
image-error metric was taken.

This is a single spatial level inspired by SVGF, not full SVGF. There is no
motion reprojection, disocclusion rejection, multilevel filtering, roughness,
albedo, or separated diffuse/specular guides. Leave it opt-in. Equal-count
raw/filtered comparisons, camera/object/material/light motion, Cornell and
another scene, very long accumulation, and resize/toggle lifecycle checks
remain open. Fine texture can blur; a moving scene can show temporal artifacts.
