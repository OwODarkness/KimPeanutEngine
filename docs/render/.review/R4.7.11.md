# R4.7.11 — Inline ray-query visibility

Date: 2026-09-27. Status: Sponza experiment implemented and repeatably faster;
Debug validation passed; cross-scene and capability-fallback coverage remains
open.

Plan: [R4.7 GPU strategy](../.plan/R4.7-gpu.md).

## Scope and candidate

Adds opt-in `ray_query_visibility` mode to the R4.7.11 path-tracing experiment.
`TraceVisibility` uses `rayQueryEXT` with opaque, terminate-on-first-hit flags
for direct-light shadow visibility; the existing scalar-payload `traceRayEXT`
visibility shader remains the default and fallback mode. The mode is exposed
through the Runtime `render.path_trace_probe` command. The query feature and
GLSL compiler support were verified on the RTX 4070 Laptop used for this run.

Source locations: `../../../asset/shader/ray_tracing_path_tracer.rgen:111`,
`../../../engine/runtime/render/path_trace_probe_mode.h:16`, and
`../../../engine/runtime/runtime_global_context.cpp:151`.

## Runtime evidence

Visible Vulkan RelWithDebInfo Sponza runs used 1094x619, 4 SPP, 8 continuation
bounces, 120 warm-up and 300 measured frames, 786,098,304 AS bytes and complete
469,885,796-byte tracked texture residency. GPU telemetry stayed at P4,
1020/6001 MHz, 60–61 C and about 35–36 W. The user-edited Sponza directional
light intensity of 1000 was preserved. Three windows per mode show:

| Mode | PT GPU p50 mean | PT range | Total GPU p50 mean | Total p95 mean |
| --- | ---: | ---: | ---: | ---: |
| `beauty` / `traceRayEXT` visibility | 23.188 ms | 23.119–23.263 | 27.903 ms | 29.340 ms |
| `ray_query_visibility` | 21.940 ms | 21.916–21.971 | 26.636 ms | 27.727 ms |

This is a 5.38% PT p50 and 4.54% total GPU p50 reduction in this setup. Both
modes retained 4 samples per dispatch and 8 bounces. Near-matched captures at
1728 and 1700 accumulated samples look visually consistent; their RGB8 MAE is
7.18/255, so this is not an exact equal-sample image comparison. Profiles and
telemetry are in `save/diagnostics/r471-query-ab-window-*.json` and
`r471-query-ab-window-summary.csv`; captures are
`save/screenshots/validation/r471-query-ab-equal-sample-{baseline,query}.png`.

## Findings

### F1 — P2, open: non-query-device and alternate-scene coverage

The live comparison covers one RTX 4070 Laptop and Sponza only. A Debug Vulkan
validation launch selected `ray_query_visibility` and exported
`r471-debug-ray-query.png` without logged validation errors. Cornell and a
reordered/material-overridden third scene remain open. The current Vulkan
device-selection contract requires ray-query support for its RT contract, so a
ray-tracing-pipeline device without ray query is not currently a supported
runtime configuration and could not be exercised as a fallback here. The
compiler rejects `GL_EXT_shader_invocation_reorder`, so SER was not attempted.

### F2 — P2, resolved for this experiment: unchanged-work Sponza timing

Three windows per mode kept the probe at 4 SPP/8 bounces, the same scene and
residency, with steady clocks and a repeatable lower PT and total-GPU p50 for
the opt-in ray-query path. `beauty` continues to use the existing pipeline
visibility route. This result is hardware/scene-specific; no default change is
made.

## Review verdict

Keep ray-query visibility opt-in. The Sponza result supports further testing,
but Cornell and general-scene checks remain open, and a query-disabled RT
device cannot be evaluated under the current Vulkan capability contract. No
wavefront queue or SER path was added.
