## Review round 1 — 2026-09-02

### F1 — typed IDs are unique but are not bound to their declared pass roles

- Priority: P2
- Location: `engine/runtime/render/render_pass.cpp:89-103`,
  `engine/runtime/render/deferred_renderer.cpp:554-594`
- Status: addressed

`FixedRenderPassSequence::Create()` checks that every ID is in range and
appears once, but it never checks that an ID occupies its canonical position or
owns the metadata defined for that role. Swapping only the IDs of two otherwise
valid entries therefore succeeds. Execution dispatches by the swapped ID while
resource validation still reasons about the unchanged entry metadata. For
example, exchanging `GBuffer` and `ToneMap` validates successfully but invokes
tone mapping at the G-buffer entry and G-buffer recording at the tone-map
entry. This recreates the declaration/execution divergence that R1.3 is meant
to eliminate, and a typo in the production table is accepted at initialization.

Bind each closed ID to its canonical ordinal and role metadata, or otherwise
make the canonical declaration and dispatch mapping share one mechanically
checked identity. Add a negative test that swaps two unique IDs while leaving
their entries unchanged and expects sequence creation to fail.

`FixedRenderPassSequence::Create()` now requires each typed ID to equal its
canonical ordinal in the closed sequence. The focused suite adds a regression
test that swaps two otherwise valid unique IDs and verifies creation fails.

### F2 — moving a frame leaves the moved-from cursor executable

- Priority: P2
- Location: `engine/runtime/render/render_pass.h:107-139`
- Status: addressed

The frame advertises move-only ownership, but its defaulted move operations
copy the sequence pointer, outcome array, flags, and cursor because every member
is a scalar or scalar-like value. The source is not invalidated. After
`FixedRenderPassFrame moved = std::move(frame)`, both objects can execute the
same logical frame and invoke renderer or editor callbacks, contradicting the
plan's one active cursor, exactly-once external execution, and later-frame
reuse rejection. The sequence has the related weaker symptom that a moved-from
object still reports `IsValid() == true` unconditionally.

Either delete frame moves if no consumer needs them, or implement moves that
transfer ownership and put the source into an explicitly rejected state. Cover
moved-from renderer execution, external execution, and finalization in the
focused tests.

Custom sequence and frame move operations now consume their sources. A moved
frame clears its sequence pointer, cursor, flags, and outcomes, so renderer,
external, and finalization calls on the source are rejected. The focused suite
covers the moved-from behavior.

### F3 — the R1.3 records describe a superseded architecture and validation state

- Priority: P2
- Location: `docs/render/design.md:25-31`,
  `.spec/journal/2026-09-02-render-system-r1-3.md:9-15,53-65`,
  `.spec/specs/render-system-r1-3.md:21-29,74-85`,
  `docs/render/risks.md:16-25`, `docs/render/TODO.md:37-48`
- Status: addressed

The design document still presents `RenderPassSchedule` plus a separately
authored `RecordFrame()` order as the current architecture. The R1.3
spec/journal/TODO/risks still say R1.2 evidence is unverified and that MSBuild,
CTest, and smoke are blocked by the Windows SDK probe, despite the completed
R1.2 review and the passing R1.3 evidence below. The TODO also repeats the R1.2
ownership paragraph and its spec/journal links. These contradictions prevent
`docs/status.md` and the Render module records from serving as a reliable
current-state and acceptance ledger.

Update the durable design to the landed sequence/cursor architecture, append a
dated correction and current validation evidence to the factual journal, bring
the spec/risks/TODO checklists into agreement, and remove the duplicated R1.2
roadmap text. Preserve the historical permission failure as history rather
than silently replacing it.

The design now describes the immutable sequence and consuming cursor; the
spec, journal, risks, TODO, and status ledger record the corrected architecture
and current evidence. The duplicated R1.2 roadmap paragraph was removed, while
the original SDK permission failure remains in the journal's historical probe
record.

## Positive observations

- The production table contains the intended eight distinct entries in the
  planned directional → spot → point → G-buffer → lighting → tone-map → capture
  → editor order.
- `RecordFrame()` no longer carries a second manual pass call list; renderer
  operations are reached through typed-ID visitation.
- Conditional diagnostic conversion and direct SceneColor readback remain
  distinct, and the external editor stage is cursor-gated and exactly once for
  an unmoved frame.
- Required operation failure is observable while later stages continue, which
  preserves the documented fail-soft frame policy.
- Render/Graphics ownership remains API-neutral; no Vulkan or OpenGL type leaks
  into the common sequence contract.
