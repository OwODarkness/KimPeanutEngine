# R4.6 — Cornell Box RT-pipeline validation

**Status:** implementation in progress. Vulkan dispatch, Cornell hit shading,
direct area light, one diffuse bounce, and progressive history are observed in
the runtime. Reference comparison and complete lifecycle evidence remain open.
See the [R4.6 review](../.review/R4.6.md).

**Authority:** [R4.6 execution spec](../../../.spec/specs/render-r4-6-cornell-path-tracing.md)

**Parent:** [R4 render-graph plan](R4.md)

**Current stop gate:** visual framing/quality and R4.6e lifecycle. The user
clarified that the downloaded JPEG is a qualitative guide, so exact source
settings and pixel metrics are not required.

## Objective

Produce one honest, reference-comparable Cornell Box path-tracing result. The
path must generate camera rays from an RT pipeline, reconstruct the hit from
the TLAS and shader-visible scene records, sample the rectangular ceiling
emitter, and integrate at least one diffuse secondary bounce. R4.5's deferred
ray-query shadow path remains unchanged and is not used as R4.6 evidence.

## Boundary and ownership

| Concern | Owner | R4.6 rule |
| --- | --- | --- |
| Cornell camera, emitter, materials, integrator settings | Render | Publish immutable frame records and revision keys. |
| Geometry/material/instance lookup records | Render → Graphics upload seam | Use stable shader-visible IDs; never infer material from descriptor order. |
| BLAS/TLAS, RT pipeline, SBT, storage images, retirement | Graphics/RHI | Keep Vulkan handles, device addresses, SBT layout, and barriers below the common contract. |
| Logical pass order and history versions | Render Graph | Declare AS reads, storage writes, accumulation ping-pong, resolve, and capture dependencies. |
| Shader stages and hit reconstruction | Asset/Resource + Vulkan backend | Extend stage ingestion and native translation; do not add a general material graph. |
| Reference comparison and runtime evidence | Render validation | Compare only aligned display-space images and report sample count/settings. |

## Required graph variant

R4.6 is a dedicated Cornell validation variant, not a branch added to
`deferred_lighting.frag`:

```text
existing BLAS/TLAS build or update
              ↓
PathTraceDispatch
  reads: TLAS, scene lookup buffers, camera/light/integrator constants,
         previous accumulation history
  writes: current linear-HDR sample or accumulation target
              ↓
Accumulate
  reads: current sample + previous history + sample count
  writes: next history + next sample count
              ↓
Resolve / tone-map / capture
```

The primary ray path must not read a raster G-buffer. The graph must use
explicit SSA versions for history ping-pong; no in-place history update or
implicit backend ordering is allowed. OpenGL and Vulkan devices without the
complete RT-pipeline/storage-image contract report R4.6 unavailable and keep
the normal renderer alive.

## Original frozen reference gate — R4.6a (superseded)

The 2026-09-22 acceptance revision in the execution spec replaces this gate
with a qualitative visual review of the Cornell scene. The manifest remains a
record of the downloaded image's known identity, not a blocker.

Before implementation tuning:

1. Verify `save/cornell_box_ref.jpeg` dimensions and SHA-256 against the
   execution spec.
2. Record a tracked manifest for resolution, crop, origin, camera rays,
   geometry scale, wall reflectances, output transfer, exposure, and tone map.
3. Resolve the rectangular emitter contract. The existing point light is not
   valid R4.6 evidence. Prefer the imported `area_light` section when its
   identity is stable; otherwise add an explicit validation-only emitter record
   tied to the manifest.
4. Freeze the comparison budget, bounce count, RNG seed policy, global metrics,
   and local probes before inspecting tuned candidate output.

No later stage may change the manifest silently. A changed manifest creates a
new revision and invalidates prior comparison evidence.

## Implementation stages

### R4.6b — Vulkan RT pipeline and dispatch

Extend the shader asset/resource path for ray-generation, miss, and
closest-hit stages. Implement only the native Vulkan surface required by this
consumer: pipeline creation, shader groups, SBT allocation/alignment, RT
descriptor bindings, `DispatchRays`, storage-image writes, and submission-safe
retirement.

Required proof:

- common descriptors validate stage/group/SBT/dispatch dimensions;
- Vulkan creates and retires the pipeline and SBT without validation errors;
- a miss-only storage output can be captured before hit shading is enabled.

### R4.6c — scene lookup and hit reconstruction

Publish copied lookup records for Cornell geometry sections, instances, and
materials. Each record must define vertex/index ranges, object and normal
transforms, material ID, and the mapping from instance custom index, geometry
index, primitive index, and barycentrics.

Validate in this order:

1. primary-ray hit/miss mask;
2. world-position output;
3. geometric/shading-normal output;
4. material/base-color output.

Do not begin indirect lighting until these debug outputs are stable and the
multi-section mesh mapping is proven.

### R4.6d — direct area light and one diffuse bounce

Implement a fixed, deterministic integrator:

- one camera ray per pixel/sample;
- one rectangular-emitter sample with explicit area/solid-angle PDF;
- bounded shadow ray for direct lighting and soft penumbrae;
- one cosine-weighted diffuse secondary bounce;
- direct-light sampling at the secondary hit;
- fixed maximum depth of two surface hits, with no Russian roulette initially.

If multiple importance sampling is not implemented, use next-event estimation
as the sole emitter estimator and exclude unweighted emissive-hit contributions
from sampled paths to avoid double counting. Keep a black miss environment for
the reference contract.

Required proof: disabling the secondary bounce removes the red/green local
color-bleeding probes while leaving direct-light geometry intact.

### R4.6e — accumulation and reset lifecycle

Accumulate linear HDR values in graph-declared history resources. Use a stable
per-pixel/per-sample seed derived from the frozen seed, pixel coordinate, and
sample index. Publish the sample count with every capture.

Reset history when any of these revisions changes: camera/extent, geometry,
instances, materials, emitter, exposure/tone map, shader/pipeline, integrator
settings, or RNG policy. Test resize, scene reload, failed dispatch, and
repeated start/stop before final visual comparison.

### R4.6f — reference evidence and closure

Render the frozen sample budget at the manifest resolution, export:

- accumulated candidate image;
- reference-aligned difference image;
- global luminance/chroma and perceptual metrics;
- local probe report for red bounce, green bounce, neutral wall, emitter, and
  soft-shadow penumbra;
- sample count, camera/light/integrator settings, timings, AS/storage memory,
  validation log, and orderly-close evidence.

The stage cannot close if the path silently falls back, if the candidate and
reference are not identically aligned, or if the comparison passes while the
secondary-bounce and penumbra probes fail.

## Validation matrix

- Unit/contract: shader-stage ingestion, RT pipeline descriptors, SBT regions,
  dispatch dimensions, invalid handles, and retirement.
- Render graph: TLAS read → storage write, history SSA ping-pong, resolve/capture
  ordering, missing binding failure, and reset-key invalidation.
- CPU/reference: camera-ray generation, barycentric reconstruction, rectangle
  sampling/PDF, cosine hemisphere sampling, throughput, and seed stability.
- Runtime Vulkan: validation-enabled RT session, capture readiness, sample
  count, per-pass/dispatch CPU/GPU timing, AS/storage memory, resize, failure,
  repeated start/stop, and orderly close.
- Runtime OpenGL/unsupported Vulkan: explicit R4.6 unavailable result plus
  healthy raster fallback; never count fallback output as RT evidence.

## Reference basis

The plan follows the repository's pinned Sakura study: typed graph resources,
explicit AS/output hazards, and a separate ray-tracing sample are useful, but
Sakura's raw-RHI callbacks and incomplete native RT ownership are not copied.
The gkNextEngine study reinforces shared scene data, separate renderer policy
and Vulkan execution, and evidence-driven visual validation. No reference
repository source was available locally for a new source inspection in this
planning pass; the pinned project studies remain the design basis.
