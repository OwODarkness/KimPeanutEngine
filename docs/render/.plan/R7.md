## Objective and boundary

Improve the existing opaque deferred raster renderer in this order:
spatial SSAO, motion/history contracts, native-resolution TAA, then exponential
height fog. Local reflection probes and SSR are subsequent decision gates;
volumetric fog requires a separate plan after this baseline is accepted.

R7 serves raster lighting with either shadow maps or ray-query direct shadows.
R6 continues to own interactive path-tracing reconstruction. Share coordinate
conventions and previous-submitted-frame semantics where useful, but retain
separate estimators, filters, histories, and acceptance criteria. SSAO and raster
TAA must not be applied over full path-traced Beauty.

The concrete question is how to add these consumers to the existing compiled
graph without reviving facade-owned pass state or weakening GPU retirement.
Acceptance requires visible quality improvement, disabled-feature parity,
truthful effective settings, and safe execution on Vulkan and OpenGL.

## Source baseline and prerequisites

Inspected current source establishes:

- `asset/shader/pbr_gbuffer.frag`: four color attachments and sampled depth;
  world-space shading normals and material AO are already available.
- `asset/shader/deferred_lighting.frag`: depth-to-world reconstruction and
  separate direct/ambient terms; material AO currently affects both diffuse
  and specular IBL. No screen-space AO input exists.
- `render_pass_declaration.cpp`: graph resource scopes and separate raster/PT
  producers of HDR color. Preserve attachment-specific reads.
- `render_camera.h` / `render_shader_data.h`: current camera/object uniforms
  contain current transforms only. Motion needs an explicit new Render ABI.
- `renderer_frame_targets.h`: logical target descriptions are Render policy;
  HDR allocation is already transient and Graphics-owned.
- `passes/fullscreen_pass_resources.h`: shared fullscreen mesh/sampler exists.
  The common recorder has ray dispatch but no general compute dispatch.
- `asset/shader/tone_map.frag`: PT spatial reconstruction and raster selection
  presentation already exist. Keep scene TAA separate from these functions.

Neither fog, scene TAA, nor SSAO was found in the inspected render/shader paths.
This is a source review, not fresh runtime evidence. The older D-stage docs
describe the original fixed schedule; current graph authority is R3/R5.

[R5.2](R5.2.md) and [R5.3](R5.3.md) remain acceptance prerequisites for
affected graph/pass lifetime behavior. Their broader validation was deferred by
the user for this milestone; this scope decision does not close those R5 gates.
R7.1 proceeds on the existing graph contracts, while cross-backend and lifetime
acceptance remain required before R7 core completion.

## Ownership, resources, and frame data

- The compiled render graph is the sole scheduling/execution authority for
  every R7 producer, filter, resolve, composition, and diagnostic conversion.
  There is no parallel fixed schedule or ad-hoc post-process loop. Concrete
  pass owners record through the typed graph pass context; no backend target
  lookup or resource-state transition may bypass declared graph uses.
- Gameplay/environment authoring publishes copied fog/probe values. Runtime
  transports them; Render validates a frame-boundary settings snapshot.
  Render never loads arbitrary files for a new effect.
- Concrete Render owners hold SSAO, raster temporal AA, and height-fog policy,
  pipelines, settings, and logical resource descriptions. `DeferredRenderer`
  composes them and authors dependencies; it does not absorb their algorithms.
- Graphics allocates textures, records native commands, translates transitions,
  and retires GPU objects. Prefer existing fullscreen raster commands; add a
  compute contract only for a measured consumer and a separately reviewed ABI.
- Raw AO/filter intermediates, fogged HDR, and resolved HDR are graph
  transients. TAA color/depth/normal/validity histories are persistent imports
  owned logically by the temporal pass and physically by Graphics.
- Declare distinct logical HDR versions/targets. No pass samples the same
  physical subresource it writes; filters/history use ping-pong resources.
- Rotate histories, previous transforms, and jitter sequence only after a
  successful submitted frame. Rejected frames never become temporal input.
- Resize, mode change, reload, disable, and shutdown invalidate logical history;
  release bindings before safe Graphics retirement or the established idle
  boundary. Do not replace submitted textures in place.
- Requested/effective settings, inactive reasons, history age/reset reason,
  pass timings, resource sizes, and memory estimates are observable through
  Runtime stats. New capture views use the semantic capture service.
- Feature disabled means identity output and no unnecessary producer work.
  Enabled required-producer failure follows R5 failure propagation; it cannot
  silently publish stale AO/history. Any recovery fallback is explicit.

## Intended graph flow

```text
Shadow work → GBuffer → SSAO → AO filter → DeferredLighting
                    └→ motion/depth/validity inputs          ↓
                                            HeightFog (optional)
                                                       ↓
Previous submitted histories ───────────────────────→ TAA (optional)
                                                       ↓
                                              ToneMap + selection
                                                       ↓
                                               EditorComposite
```

AO modulates ambient diffuse inside deferred lighting, before tone mapping.
Fog consumes scene-linear HDR and depth, writes a distinct HDR output, and
precedes TAA when both are enabled. Selection/UI stay outside temporal history.
Diagnostic views retain their documented raw meanings; jittered diagnostic
captures must report jitter or use an explicitly frozen comparison policy.

Each filter iteration is an explicit graph node, with its own source/destination
versions. Extend typed resource roles, physical binding assembly, conditions,
profiling IDs, and graph validation for the actual consumers together; do not
encode dependencies solely as call order in `DeferredRenderer`.

| Graph node | Declared reads | Declared writes |
| --- | --- | --- |
| SSAO estimate | GBuffer sampled depth and normal attachment only | Raw AO transient |
| AO filter / guided upsample | Previous AO version, depth, normal | Distinct filtered AO version |
| Deferred lighting | Existing inputs plus final AO when enabled | Lit HDR version |
| Motion output | Current/previous submitted transforms; depth if reconstructed | Motion and validity targets |
| Height fog | Selected lit HDR version, sampled depth, frame/environment data | Fogged HDR version |
| TAA resolve | Selected current HDR, motion/validity, current guides, previous imported histories | Resolved HDR and next history resources |
| Tone map | Selected resolved/bypass HDR; selection attachment for raster | Scene color |
| Diagnostic conversion | Requested semantic source only | Owned capture/Viewer output |

Motion may be an additional GBuffer output if the attachment/ABI review supports
it; in that case declare the producer there rather than inventing a second
motion pass. Keep GBuffer attachment scopes precise. Persistent TAA imports and
next-history writes are distinct typed graph resources even though the temporal
owner manages their logical ping-pong mapping. Graph execution decides resource
states, leases, producer failures, and consumer skips; Graphics translates the
result into native execution and synchronization. Disabled branches bind the
appropriate bypass HDR version and prune unused producers.

PT omits SSAO/TAA regardless of raster diagnostics demand. Initial height fog
is raster-only, with an explicit inactive reason in PT mode. A later PT fog
adapter needs a validated guide-distance/background contract; medium transport
inside the PT integrator is outside R7. Reflection composition, if selected,
belongs before fog/TAA and must replace the selected environment-specular term
rather than add a second copy of it.

## R7.0 — Establish the raster quality and correctness baseline

1. Record RT-off and PT-off/ray-query-on Sponza, Cornell, and PBR showcase
   baselines; use `terrain_baked.level` when its products are available.
2. Close the affected R5 graph/binding/failure/lifetime checks listed above.
   Distinguish stale historical failures from a reproduced current failure.
3. Add a checked-in small fixture with a plane, convex object, concave corner,
   thin foreground occluder, AO-textured material, and a moving rigid object.
   Freeze camera paths, lighting, exposure, and viewport extent.
4. Establish disabled-feature captures and three matched RelWithDebInfo timing
   windows. Freeze a numeric GPU-time/memory budget for each slice before its
   implementation, based on measured headroom; do not promise 60 FPS.

Initial Vulkan budgets are for the checked-in 1094×631 fixture and the RTX
4070 Laptop GPU. The three independent RelWithDebInfo fixture runs measured a
worst baseline GPU p95 of 3.17 ms; Sponza measured 5.42 ms with ray tracing
disabled. Cap added GPU p95 at 1.0 ms for SSAO, 0.5 ms for motion/validity,
1.0 ms for TAA resolve, and 0.5 ms for height fog, with the combined raster
stack capped at 8.5 ms GPU p95 on Sponza. Cap R7-owned incremental texture
storage at 32 MiB at this extent, including persistent temporal histories.
These are acceptance ceilings for the measured Vulkan device, not frame-rate
promises; OpenGL requires a matched baseline before its implementation gate.

Cornell and PBR now have direct-source raster variants and Vulkan scene-color
captures in both deferred shadow-map and hybrid ray-query modes, with PT off.
The variants load successfully in RelWithDebInfo and produce the expected
scene geometry. PBR's matched 1094×631 windows each completed 120 warm-up and
300 timing samples: ray-query p50/p95 1.903/3.298 ms, RT-off 1.068/1.358 ms.
Cornell produced 32 triangles but its GPU timing summaries did not accumulate
samples during these short capture runs. Sponza retains both feature-off
captures and the compact fixture retains its three matched timing windows.
The direct-source levels and their model assets are checkout-local ignored
content, so portability through a clean archive/import is not established.
Sponza's native material products still fail dependency resolution; its capture
uses a neutral override.

The prior RelWithDebInfo `GraphicsSmoke` run exited successfully for six frames
per API and did not reproduce the historical GBuffer descriptor binding-5
error. It did log rejected invalid vertex-stream handles from its negative
streaming-geometry probe. This distinguishes that old failure from the current
smoke result but does not accept R5 binding/lifetime coverage.

At the user's direction, R7.0 is closed as a baseline milestone without the
expanded R5 validation run. R5.2/R5.3/R5.4 correctness acceptance remains open,
including untested AS failure/abort cases and the failed-frame editor-composite
validation error. Runtime captures came from RelWithDebInfo, but no live
`GLFW30` foreground handle was discoverable, so interactive desktop visibility
was not verified. These limitations remain open for later acceptance; they are
not claims that the R5 gates passed.

**Exit:** baseline scenes/captures, deterministic fixture, and documented
quality/performance budgets recorded. Expanded R5 correctness validation is
deferred and tracked as an independent open gate; this milestone does not
declare all of R5 or R6 complete.

## R7.1 — Spatial SSAO and ambient-diffuse integration

Implementation and Vulkan runtime checkpoint (2026-10-03): the compiled raster graph declares
full-resolution AO estimate and depth/normal-guided filter passes backed by
Graphics pooled R8 transients. Render reconstructs world positions from the
GBuffer, uses deterministic 6/12/24-tap Low/Medium/High kernels, and feeds
filtered AO into ambient diffuse with `min(material_ao, screen_ao)`; material AO
still controls specular IBL and direct lighting is unchanged. PT omits both AO
passes. Disabling SSAO compiles out both producers and their transients, while
lighting gates AO sampling off. RenderSystem settings and requested/effective
stats include radius, bias, strength, and active sample count. Semantic raw and
filtered AO views are available through `capture.screenshot`. RelWithDebInfo
Vulkan Sponza captures confirm the AO passes execute at Low/Medium/High, AO-off
prunes them and returns white diagnostic views, and AO-on/off scene captures
differ. The High preset measured 0.434 ms for estimate plus filter at the
1094x631 viewport, within the recorded 1.0 ms p95 budget. The OpenGL Sponza
launch did not expose the Runtime command port, so cross-backend validation,
AO-material fixture acceptance, and the silhouette/planar-darkening checks
remain open; R7.1 is implemented but not accepted.

1. Add graph-declared AO estimation/filter nodes and typed resources, recorded
   by the Render-owned fullscreen AO owner using reconstructed view-space
   positions and normals transformed consistently from the GBuffer. Start with
   a bounded hemisphere kernel, world-unit radius/bias, and deterministic
   sampling. Full resolution is the correctness reference.
2. Read depth without filtering across silhouettes. Background, invalid depth,
   and off-screen samples must have defined unoccluded/ignored behavior.
   Normalize by valid sampling weight and bound the final visibility to [0,1].
3. Add depth/normal-aware filtering with distinct read/write targets. Compare
   half-resolution estimation plus guided upsampling against the full-resolution
   reference before selecting a quality preset. Do not add temporal AO yet.
4. Preserve material AO and its current specular-IBL treatment. Initially use
   `min(material_ao, screen_ao)` for diffuse ambient visibility to avoid strong
   overlapping attenuation; compare with multiplication in the AO-textured
   fixture before freezing the documented combination policy. Direct lighting
   and emissive contribution remain unaffected by screen AO.
5. Add enable/radius/bias/strength/quality settings and raw/filtered AO captures.
   Do not add screen AO to full PT or treat it as indirect bounce lighting.

**Exit:** grounded contacts/creases under ambient illumination, no planar
self-darkening or silhouette halos beyond the frozen tolerance, defined
off-screen limits, AO-textured material acceptance, disabled parity, and
cross-backend lifecycle/performance evidence. More advanced GTAO/HBAO is a
measured replacement candidate, not a prerequisite.

## R7.2 — Motion, jitter, and submitted-history contract

1. Define a Render-owned temporal frame record: current/previous view and
   projection, jittered/unjittered matrices, viewport extent, view-space depth,
   and stable object identity with previous submitted rigid transforms.
   Use a separate versioned uniform block where possible; audit every producer
   and shader if an existing ABI must change.
2. Freeze motion as current-to-previous UV displacement, excluding projection
   jitter. Specify Vulkan/OpenGL texture orientation, depth/NDC conversion,
   pixel centers, and jitter correction once. TAA accounts for sample jitter
   exactly once when locating historical samples.
3. Begin with static geometry/camera reprojection, then rigid-object motion.
   New/removed objects and unsupported deformation explicitly reject history.
   Do not label camera-only motion as animated-object support.
4. Keep jitter Render-owned and temporal-consumer-specific. CPU picking and
   culling retain an unjittered camera with a conservative visibility margin;
   shadow fitting must not become frame-jitter dependent. Raster jitter must
   not reset or modify raw PT accumulation.
5. Add motion/validity/depth captures and tests for identity, translation,
   rotation, rigid-object movement, camera cuts, and failed submissions.
   Reconcile the convention with R6.2 without sharing filter histories.

**Exit:** static unjittered motion is zero, analytical transforms reproject
correctly on both APIs, jitter-only movement does not masquerade as object
motion, and rejected frames cannot advance previous-frame state.

## R7.3 — Native-resolution temporal anti-aliasing

1. Introduce a graph-declared raster temporal resolve pass before ToneMap,
   including explicit persistent history imports and next-history writes. Reproject
   scene-linear HDR history with R7.2 inputs; reject invalid/out-of-bounds depth,
   disocclusion, normal/identity disagreement, and unsupported moving surfaces.
2. Bound historical color using the current neighborhood and a documented
   confidence/history weight. Define HDR/outlier handling and preserve bright
   thin features; keep optional sharpening separately controllable.
3. Bootstrap from current color when history is absent. Reset on cuts, extent
   or projection discontinuity, scene replacement, relevant lighting/material
   changes, shader reload, and PT/raster mode switches. Exposure applied after
   scene-linear history must not require a history reset.
4. Define sky reprojection from camera rotation or reject sky history initially;
   never interpret clear depth as a finite surface. Preserve selection and UI
   outside the accumulated color.
5. Compare deterministic motion sequences against TAA-off and an offline
   supersampled reference. Freeze shimmer reduction, edge-detail retention,
   disocclusion recovery, and ghosting tolerances before tuning weights.

**Exit:** measurable reduction in temporal shimmer without unacceptable trails
or blur, repeatable motion/cut recovery, safe history lifecycle, and the R7.0
GPU/memory budget. Upscaling, frame generation, and PT denoising are excluded.

## R7.4 — Exponential height fog

1. Add copied settings for enabled state, density, reference height, height
   falloff, scene-linear fog color, and finite maximum distance. Validate
   nonnegative density/falloff and finite bounded inputs at the frame boundary.
2. Define height along the engine's documented world-up axis, then integrate
   density along the camera-to-surface ray using
   `rho(h) = rho0 * exp(-falloff * (h - reference_height))`, with stable limits
   for horizontal rays and zero falloff. Density has inverse-world-unit scale.
   Compute `T = exp(-integral(rho ds))` and
   `fogged_hdr = T * surface_hdr + (1 - T) * fog_color`.
3. Reconstruct distance from world position, not raw nonlinear depth. Define
   perspective/orthographic origins and clamp exponents/optical depth safely.
   Sky uses an explicit finite distance and sky-affect policy.
4. Declare fog reads/writes as a graph node producing a distinct HDR version
   before TAA/ToneMap. Fog edits invalidate TAA
   history. Initial fog is analytic, unshadowed, and opaque-raster-only;
   transparency, physical atmosphere, and volumetric light scattering wait.
5. Capture transmittance and final color across terrain, indoor, and horizontal
   ray fixtures. Zero density must be an exact identity path.

**Exit:** monotonic transmittance, stable horizontal/zero-falloff limits,
consistent distance on both APIs, seamless defined sky behavior, correct
HDR/TAA ordering, and lifecycle/performance acceptance.

## R7.5 — Core acceptance and follow-up decisions

Close the R7.0–R7.4 matrix before opening a new major effect. Record each
feature independently and all enabled together, including raster shadow maps,
ray-query shadows, and mode transitions to/from unchanged PT output.

Subsequent work requires its own concrete stage plan and evidence:

- **Local reflection probes before SSR:** study actual reference source;
  select bounded authored probe volumes, processed/cooked environment products,
  roughness prefiltering, local correction, blend/fallback rules, memory budget,
  and update policy. Asset/Resource prepares products; Render selects probes;
  Graphics owns textures. Begin with static authored probes rather than
  automatic per-frame six-face scene capture.
- **SSR after reflection fallback:** define depth hierarchy/ray thickness,
  confidence, roughness behavior, misses/off-screen fallback, replacement of
  existing specular IBL, and temporal rejection using R7.2. Add only if a
  reflective fixture demonstrates a quality benefit within the measured budget.
- **Volumetric fog after analytic fog/TAA:** separately design view-aligned
  volume cells, light/shadow injection, integration, history, 3D resources,
  compute needs, and memory/timing budgets. A light-shaft fixture must justify it.

These are follow-up directions, not hidden conditions for R7 core completion.
GI, clustered lighting, GPU-driven draws, virtual geometry, and temporal
upscalers require independent workload evidence rather than a feature checklist.
