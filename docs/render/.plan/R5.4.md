# R5.4 — narrow Graphics contracts and audit RT retirement

**Status: implementation and acceptance evidence complete; one validation
follow-up is recorded below.** This stage removes
Render-specific uniform schemas and timing cardinality from common Graphics,
while keeping native query storage and RT resource operations below the
`RenderBackend` facade.

## Boundaries and invariants

- Render owns `CameraData`, `PerPassData`, `PerObjectData`, the profile-pass
  enum, and the set of stable profile IDs it requests.
- Graphics owns native query allocation, query-slot assignment, and backend
  timing collection. Render registers stable IDs derived from canonical pass
  names before initialization. Graphics accepts up to `kMaxGpuProfilePasses`
  unique caller IDs; returned timing records preserve those IDs.
- Preserve the uniform shader ABI: `CameraData` remains two aligned matrices,
  pass data remains one camera block, and object data remains one model matrix.
- Keep `RenderBackend` as the composition/factory/frame facade. Backend owners
  remain private; no per-pass virtual interface is introduced.
- Vulkan tables and binding sets retire only after submitted serial completion;
  a table also waits for descriptor references to reach zero.
- Pipeline destruction remains immediate only at an idle ownership boundary.
  Do not split private owners until runtime teardown evidence justifies a
  stronger ownership boundary.

## Implementation steps

1. Move pass/object uniform schemas into `render/render_shader_data.h`, retain
   their data members and layout assertions, and update Render plus the RHI
   example to use the Render types.
2. Replace the Graphics constant for Render's profile count with a bounded
   registration API. Reject duplicate IDs, over-capacity registration, and
   changes after backend initialization. Configure the Render profile IDs
   before creating native query pools.
3. Map stable IDs to backend-local query slots in Vulkan and OpenGL. Preserve
   per-frame skipped-pass handling and return the original caller ID.
4. Audit Vulkan RT destruction and cleanup callers. Keep immediate pipeline
   destruction only where the caller first drains GPU work; retain serial-based
   retirement for AS, descriptor sets, and address tables.

## RT lifecycle audit and split decision

- `DeferredRenderer::Cleanup` aborts graph execution, releases pass bindings,
  marks scene resources for retirement, calls `backend->WaitIdle()`, then
  destroys the path-tracing pipeline and its SBT. `RenderSystem` also waits
  before scene replacement and backend teardown. `PathTracingPass::Cleanup` is
  called from this renderer cleanup path.
- `EnsureHistoryTargets` waits idle before replacing history resources and
  releasing their bindings.
- Vulkan AS resources, descriptor sets, and address tables are marked pending;
  the backend stamps pending objects with submission serials and collects them
  after completion. Tables additionally wait for descriptor references to be
  released.
- Rejected or aborted graph recording does not submit its partial command
  buffer. Submitted frame resources use the serial path above. Device cleanup
  waits idle before destroying all remaining owner resources.
- **Decision: no private-owner split and no new retirement mechanism in R5.4.**
  The source audit finds an explicit idle boundary for RT pipeline/SBT cleanup
  and existing serial retirement for referenced mutable resources. Runtime
  teardown/reload evidence is still required before claiming this audit fully
  accepted; change the decision only if that evidence exposes a caller outside
  these boundaries.

## Acceptance

- Uniform layout assertions and contract coverage prove the prior sizes,
  alignment, offsets, and shader bindings remain unchanged.
- Duplicate and over-capacity profile registration is rejected; configured IDs
  survive both backend query collection paths.
- OpenGL-only and Vulkan-enabled builds pass.
- Runtime evidence covers orderly close, scene reload, and rejected dispatch
  while Vulkan validation is active, with no premature RT pipeline/SBT/table
  destruction.
- Update the R5.4 decision if runtime evidence contradicts this source audit.

## Current result

The source changes move uniform ownership and remove the hardcoded Render pass
count from Graphics. Render registers name-derived stable IDs, and both backend
query paths map those IDs to backend-local slots. Debug `RuntimeLib` builds pass
with both backends enabled and with OpenGL only. Layout and registration
contracts pass in the graphics/render suite (224/224). Runtime validation on
Vulkan Cornell confirmed rejected dispatch recovery, successful level reload,
and orderly close with all reported RT teardown counts at zero. Before/after
reload captures are retained under `save/screenshots/validation/`.

The injected failure frame also exposed a Vulkan layout validation error during
ImGui presentation: a sampled image was still in color-attachment layout. The
subsequent frame recovered and RT teardown was clean, so this does not show
premature RT destruction. Keep the failed-frame editor-composite transition as
a follow-up; the injected failure frame is not validation-clean.
