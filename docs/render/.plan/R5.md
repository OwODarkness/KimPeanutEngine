# R5 — post-R4.6 Render/Graphics architecture decoupling

**Status:** proposed, design only. Do not start source changes until R4.6 has accepted real RT dispatch and Cornell comparison evidence, its worktree is stabilized, and the [R5 review](../.review/R5.md) is revalidated.

**Owners:** Render owns scene/pass policy and graph compilation/execution policy; Graphics owns physical resources, native commands, synchronization, and retirement. This cross-module plan is indexed from both module roadmaps rather than duplicated in Graphics.

## Objective and boundary

Make `DeferredRenderer` a comprehensible coordinator while preserving current Vulkan/OpenGL raster output, Editor terminal composition, R4.5 ray-query shadows, and accepted R4.6 path-traced output. The intended improvement is explicit ownership and graph correctness, not a wholesale renderer rewrite or a new universal RHI.

```text
RenderSystem / RenderSceneCoordinator
  -> immutable RenderFramePacket (scene, camera, light, material, visibility)
  -> DeferredRenderer coordinator (variant choice, failure policy, lifetime)
      -> RenderGraph declaration/compiler (logical versions and state intent)
      -> RenderGraphFrameExecutor (frame bindings, transients, transitions,
                                   attachment boundaries, outcomes)
      -> concrete pass families (shadow, deferred, RT, post/capture)
  -> Graphics common contracts (handles, recorder, capabilities, timing)
      -> Vulkan/OpenGL physical owners and submission
```

This is a responsibility diagram, not a commitment to these exact C++ class names. Use concrete collaborators and value-only frame records first; add an interface only for a live alternate implementation or an established test seam.

## Stage gates and order

### R5.0 — close the prerequisite and freeze a baseline

1. R4.6 review/spec/journal must show successful 1×1 and full `vkCmdTraceRaysKHR` dispatch, valid Cornell output compared under the frozen manifest, and resource/lifetime evidence. R4.5 remaining evidence is still tracked separately.
2. Record current graph variants, pass outcomes, target/resource ownership, frame teardown, and the Render/Graphics dependency graph. Re-run [R5 review](../.review/R5.md) on the accepted tree and resolve changed line references/findings.
3. Capture repeatable Vulkan and OpenGL raster fixtures; preserve the accepted R4.6 image/settings and RT availability/fallback behavior. Gather CPU graph build/execute, command-record, GPU pass, descriptor, and transient-pool metrics before claiming optimization.

**Exit:** comparable baseline and acceptance thresholds are recorded in a stage spec/journal. If R4.6 is still blocked, R5 remains design only.

### R5.1 — prove graph failure and resource semantics before extraction

1. Add a graph-frame test where an *enabled conditional producer* fails and an exported dependent result must fail/skip. Keep truly optional diagnostic capture distinguishable from required conditional rendering.
2. Define separate concepts for *variant inclusion* and *required-once-enabled* execution. Failure must propagate to the frame and prevent dependent presentation/readback; outcome records must name failure and skip reason.
3. Add contract tests for imported one-to-many resources (all geometry buffers), AS build/read chains, transients, resize, conditional capture, and external terminal ordering. Verify logical declared accesses cover every physical transition and recorder use.

**Exit:** R5-F1/F2 have failing-before/fixed-after tests; no regression in existing `RenderGraphTest`, `RenderPassScheduleTest`, and `RenderSystemTest`.

### R5.2 — extract the graph frame execution boundary

Move only `DeferredRenderer`'s graph plan selection/binding validation, transient lease handling, transition application, attachment begin/end, outcome/profile collection, and terminal handoff into a Render-side executor. The coordinator supplies a compiled plan, frame packet, typed imported binding table, callback registry, and borrowed common `CommandRecorder`/backend capability view. The executor never loads assets or chooses materials/lights. Graphics alone owns actual allocation, synchronization, and retirement.

Replace string comparisons such as `SceneGeometry`/`SceneBLAS` with typed resource keys and per-frame bindings. A binding can represent a group of physical resources, but declares members and intended access explicitly. Keep current target pool and single `SceneHdr` lease semantics until this extraction has passed parity. Avoid a generic allocator framework and aliasing in this stage.

**Exit:** no graph physical binding/transition/sweep code remains in `DeferredRenderer`; graph tests cover missing/extra bindings, failure propagation, and multi-resource state application. The executor is usable by both raster and R4.6 graph variants without RT-specific name checks.

### R5.3 — split pass families and their state by lifetime

Introduce a value-only immutable `RenderFramePacket` at the coordinator boundary. Move pass-owned state and setup/record/cleanup as cohesive units, in this order: (a) shadow scheduling/recording/cache, (b) deferred G-buffer + lighting/material/environment, (c) tone-map/capture, (d) RT scene BLAS/TLAS build and R4.6 path pass. Keep mesh/section packet sharing explicit rather than copying it into every collaborator. Do not create per-pass inheritance or move material/lighting policy into Graphics.

Each collaborator declares which graph resources it reads/writes, what frame data it borrows, which GPU handles it owns, and teardown order. Pipelines and descriptor sets retire through existing Graphics safety rules. `DeferredRenderer` remains the renderer-facing facade for initialization, `RecordFrame`, `FinalizeFrame`, resize, and captures.

**Exit:** the coordinator no longer stores shadow, environment, and RT AS state in one aggregate; focused tests cover init rollback, repeated cleanup, resize, cache invalidation, failure paths, and pass-order-independent shared packet use. Accepted visual output remains within the frozen comparator contract.

### R5.4 — narrow common Graphics contracts, then audit Vulkan RT internals

Move `CameraData`/per-pass/per-object uniform schemas to Render-owned frame/shader contracts, preserving binary layout and shader binding compatibility. Let Graphics time caller-supplied pass IDs without an RHI-owned Render pass count. Keep `RenderBackend` as a composition/factory/frame facade while passing narrower borrowed services to consumers only when the call graph warrants it; preserve OpenGL defaults and Editor's typed presentation bridge.

After RT runtime evidence exists, audit Vulkan AS/pipeline/SBT ownership separately: creation rollback, validation limits, binding-set lifetime, submission serials, delayed destruction, and shutdown. Only then decide whether its AS and RT-pipeline internals need separate private owners. The public common RT vocabulary should change only for an observed missing consumer contract.

**Exit:** Render-specific schemas/count are absent from common Graphics headers; no Asset/Render include or native type leaks into the wrong layer; OpenGL-only and Vulkan configurations compile; the RT lifetime audit has tests and a written split/no-split decision.

### R5.5 — optional future graph capabilities, only from evidence

Re-measure 32 eager graph variants, graph compilation, physical target pool use, and pass execution. Introduce on-demand variant caching, general transient resources, attachment aliasing, async compute, or multi-queue execution **only** if a concrete R4.6 or later consumer and measured cost justify each separate design. A render graph should model R4.6 history ping-pong and external presentation explicitly; it should not own physical GPU memory or silently infer hidden AS scratch work.

**Exit:** each optional extension has its own workload, hypothesis, correctness tests, and acceptance budget; absent evidence, record “no change.”

### R5.6 — cross-backend closure

Run the [validation matrix](../../validation_matrix.md) at the appropriate levels: focused graph/render/graphics tests, Debug build and CTest, OpenGL-only build, Vulkan/OpenGL Runtime startup fixtures and fresh captures, Editor terminal/capture and resize, application close, R4.5 ray-query fallback, and R4.6 Cornell RT comparison on capable Vulkan. Inspect images; compilation alone is not visual or lifetime evidence. Record CPU/GPU/profile deltas against R5.0, including regressions, and check the final diff for module ownership/API drift.

**Exit:** no unexplained visual difference, validation error, resource leak, failed required pass presented as success, or material performance regression. Close in `.spec/journal/` only after the evidence exists.

## Non-goals and risk controls

- Do not repair R4.6 by refactoring the renderer first; close its native dispatch blocker at the current boundary.
- Do not replace the fixed graph declaration with an unrestricted dynamic plugin graph, change scene/material architecture, or import a foreign engine's abstraction hierarchy.
- Do not add a new public RHI interface per pass or expose Vulkan/OpenGL implementation types above Graphics.
- Do not claim optimization from shorter files. Profile graph build/execute, CPU record time, GPU passes, descriptor churn, allocation, and memory before/after.
- Do not start aliasing or multi-queue scheduling as part of decoupling; both need separate synchronization and lifetime proofs.
