# R5.2 — Typed bindings and frame execution: implementation plan

**Status:** in progress; physical bindings, executor-owned transitions,
attachment/profiling brackets, transient leases, external-terminal ordering and
typed finalization landed 2026-09-28. Full stage evidence remains open.
**Parent:** [R5](R5.md#r52--extract-typed-graph-binding-and-frame-execution).
**Prerequisite:** R5.1 complete; close the affected R5.0 graph-outcome and
image-comparison gates in the [execution spec](../../../.spec/specs/render-r5-render-configuration-graph-ownership.md).

## Concrete objective and inspected baseline

Remove physical graph-resource resolution and execution machinery from
`DeferredRenderer`, including their structs and fields. Keep scene preparation,
light selection, pass recording, settings resolution, and backend submission
outside the executor. This is a responsibility extraction, not a `.cpp` split.

Inspected HEAD `01d2242caac1ffafcc4c600d54d0b0fc129e9029` plus uncommitted R5.1
changes on 2026-09-28. `deferred_renderer.cpp` is 4,587 lines. Symbol names below
are the mapping authority; line numbers and counts will change. Reinspect the
working tree at implementation start; do not replace ongoing R5.1 edits.

Current problems to address explicitly:

- `BuildFrameResourceBindings` binds only the first geometry vertex buffer;
  transitions later expand the actual group by string name.
- `ValidatePassBindings` exempts virtual RT buffers and `SceneBLAS` by name.
- `SceneInstances` and `SceneScratch` have no Render-visible physical handles;
  the present path effectively skips their graph binding/transition coverage.
- `RecordFrame` mixes execution, attachment boundaries and cached-shadow policy.
- `ExecuteEditorCompositePass` owns external transition/profiling work separately.
- `FinalizeFrame` mixes execution finalization, lease release and PT history commit.

## Render graph authority — user clarification, 2026-09-28

Make full use of the existing graph, rather than moving the renderer's manual
schedule into a new class. The compiled graph is the sole authority for pass
order, enabled producers, inter-pass resource dependencies, transitions,
attachment scopes, transient lease intervals and required-output failure.
Pass IDs remain callback/timing identities; they must not define a parallel order.

Every resource with a producer, state or lifetime that varies between graph
passes, and every exported Scene Color/Capture/Viewer output, must be declared.
Audit actual pass recording against declarations before extraction. Stable
material textures/meshes and frame uniform arenas may remain externally managed
imports only with explicit readiness, read-usage and retention contracts; they
are not unexplained "virtual" exemptions. Asset upload scheduling itself stays
with Resource/Graphics and is not rebuilt as a new queue graph in this stage.

Introduce `RenderGraphPassContext`: the executor supplies only typed declared
resources, the borrowed recorder and frame services. Pass callbacks cannot look
up global targets by name, ask a sibling owner for undeclared writable state,
open attachment brackets, release graph leases or issue graph-owned transitions.
Attempting an undeclared resource access fails the recording contract. Persistent
cache/history validity remains pass policy, while every current/previous history
import and consumer dependency remains visible to the graph.

| `deferred_renderer.{h,cpp}` | Populate imports from current owners, select plan, supply pass callbacks, delegate execution/finalization |

Add the new `.cpp` files to `engine/runtime/render/CMakeLists.txt`. Keep
`RenderGraphFrame` as the outcome/dependency cursor; the executor composes it,
not a second scheduler. `RenderSubmissionExecutor` remains the separate draw
packet interpreter; do not rename or duplicate it.

Graphics retains allocation, resource-state tracking, native barriers and
retirement. The executor borrows `CommandRecorder` and common handles. It never
loads assets, calls scene/material resolvers, chooses lights or submits queues.

## Typed plan and binding contract

1. Extend the renderer declaration with `RenderFrameResourceRole` for existing
   texture roles plus geometry inputs, instance inputs, scratch, BLAS group and
   TLAS. This enum belongs in Render, not the generic graph or Graphics.
2. Return a `CompiledRenderFramePlan` containing the existing compilation result
   and a typed import map. Record roles when resources are authored, including
   sanctioned versions created by graph writes. Preserve all 64 eager variants.
   Keep `CompileRenderFrameGraph` as a compatibility adapter if tests need it;
   both APIs must use one builder and compile once per requested variant.
3. Construct `RenderGraphBindings` from that map and owner-supplied resources.
   Bind the exact graph identity/kind and declared versions; never infer a
   binding by name or accidentally accept a handle from another cached plan.
4. A texture binding borrows its `RenderTarget` and validates attachment scope.
   A buffer binding contains every physical member of its logical group; an AS
   binding contains every BLAS or the selected TLAS. Store common handles only.
   Deduplicate identical members without losing their intended use/access.
5. Required groups are nonempty. An intentionally absent optional resource must
   be absent from the selected plan, not represented as a successful empty group.
   Reject missing roles, duplicates, extra/foreign bindings and wrong kinds.
6. Transition processing visits the binding members for each compiled intent,
   preserving attachment scopes and portable usage. Names survive only in error
   messages. Preserve the current prepared-TLAS-before-build binding rule.

Move `FrameTextureBinding`, `FrameBufferBinding`,
`FrameAccelerationStructureBinding` and their vectors out of the facade.
Replace single-buffer resolution with a typed group view; a pass requiring one
member must request/assert that cardinality explicitly.

### Graphics-owned AS build inputs: required bridge

Do not create fake handles or retain a name-based exception for hidden storage.
Introduce a narrowly scoped, common `RayTracingResourceOwner` preparation API:
`PrepareBuildResources(build descriptions)` returns a frame-scoped view of
common buffer handles for the instance inputs and scratch used by those builds.
Graphics creates/registers and owns these resources; Render only copies borrowed
handles into its frame binding groups. Preparation must happen before graph
transitions and must not record the AS build command.

Inspect the Vulkan build owner first: reuse its existing allocation/upload path,
enumerate all actually consumed inputs, and pin view validity through the frame
bracket. No native buffer/device-address ownership escapes to Render. Audit
scratch read/write intents against the actual build, rather than blindly carrying
the current `SceneScratch` read declaration into the new table. If a usage/schema
correction is needed, land and validate it separately before moving the executor.
An unsupported backend reports unavailable RT preparation; raster needs no bridge.
Update common-contract fakes and Graphics contract tests for this bounded API.
R5.4 still owns the later schema/timing and retirement audit.

## Executor bracket and callback contract

Proposed concrete API shape: `BeginFrame(plan, bindings, recorder, callbacks,
profile sink)`, `ExecuteRenderer()`, `ExecuteExternal(callback)`, `Finalize()`
and `Abort()`. Names may follow local style; the ownership contract is fixed.

- Compiled plans outlive the frame. Bindings, recorder and callbacks cannot
  survive finalization/abort. Do not retain the caller's `RenderSceneFrameInput`
  reference in a callback that is invoked after `RecordFrame` returns.
- Allocate existing transient leases during begin; partial acquisition rolls
  back exactly once. Preserve pool handle stability. Render wrappers borrow
  leased targets; Graphics controls when pooled resources are reusable.
- Before the attachment opens, the pass callback provides an explicit disposition:
  record, reuse valid prior output, or fail. Shadow owners supply cached-output
  reuse; the generic executor has no shadow-name/type branches. Reused outputs
  still satisfy consumer state requirements and retain established outcomes.
- Open attachments only for attachment-write usages, never for PT storage-image
  writes. Close every opened attachment and GPU profiling bracket on all exits.
- Keep existing required-producer failure propagation in `RenderGraphFrame`.
  Optional capture failure cannot turn unrelated valid scene output into failure.
- Resolve the external terminal's transitions before invoking the host callback;
  do not finalize/release frame resources while that callback can still run.
- `Finalize` returns a typed result containing frame success, required failure,
  diagnostic and per-pass outcomes. It does not increment PT samples or swap
  history. The facade later delegates that commit to the PT owner (R5.3).
- Invalid finalization cannot leave a silently reusable half-active frame.
  Report failure, then explicitly abort its borrows/leases. Abort is idempotent
  and does not manufacture successful output or early GPU destruction.

### Implementation update — 2026-09-28

The implementation now includes R5.2.1 typed import roles and exported graph
outcomes; R5.2.2 exact one-to-many physical bindings plus the common Graphics
AS build-resource preparation bridge; R5.2.3 binding validation, transition
application, transient acquisition and rollback in the new Render graph files;
and the core R5.2.4/R5.2.5 execution move. `RenderGraphExecutor` composes the
existing `RenderGraphFrame`, owns attachment/profiling brackets, cached-output
reuse disposition, external-terminal transitions, transient leases, abort and
typed finalization results. Pass callbacks receive `RenderGraphPassContext`;
renderer texture access is restricted to roles declared by that pass.

The R5.2 gate is still open. Debug Vulkan Cornell reaches active PT, reports
executed renderer and external outcomes, and exports a valid image. Sponza also
reaches active PT, but the retained late-frame probes report BLAS/TLAS build
passes `not_in_plan`; those snapshots do not establish startup build-plan
selection. The new Graphics preparation bridge has compiled but lacks a
retained successful prepare/build/submission/retirement record. See the
[R5.2 review](../.review/R5.2.md) for source risks, intermediate TLAS failure
evidence, and a deterministic build-frame validation procedure. Runtime parity across raster/PT,
Capture/Viewer, resize/reload, required failure, and OpenGL, lease-failure
contracts, the prescribed test matrix, and matched image-error comparison are
also not yet recorded. The R5.2 journal lists the exact implementation and
remaining acceptance work.

Do not move pass pipelines/history in these slices. Do not combine the Graphics
bridge, full executor move and shader changes in one patch.
