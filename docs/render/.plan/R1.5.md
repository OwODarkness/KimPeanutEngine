## Status and implementation gate

Landed on 2026-09-04. R1.1–R1.5 code is complete; orderly application-close
evidence remains pending. The strict
cross-backend `GraphicsSmoke` silhouette comparison is guarded by separately
bounded edge and structural metrics, exact contour bounds, and synthetic
translation/thin-feature rejection probes.

R1.5 is the final structural and evidence stage. It may change Render's public
facade, the common Graphics editor-presentation capability, Runtime wiring, and
Editor UI initialization. It does not authorize a render graph, renderer
features, shader/target changes, general native interop, or a fix to the known
RuntimeLib ↔ EditorLib build cycle.

## Objective

Finish R1 with a small, explicit `RenderSystem` surface and a frame path whose
owners are visible from the code:

- one stable scene coordinator owns Gameplay-facing source inboxes and
  Render-side scene state;
- `RenderSystem` owns composition, lifecycle, the backend/frame bracket,
  capture routing, and renderer invocation;
- Editor receives only a typed Graphics-owned presentation bridge and a
  borrowed scene-target view, never the backend's general `GraphicsContext`;
- stale duplicate lifecycle paths are removed;
- focused, full, cross-backend, and visual evidence closes the parent R1 plan.

Success is defined by responsibility and contract reduction, not by a target
line count.

## Current state

R1.2–R1.4 removed pass implementation, pass order, path loading, and CPU
resource processing from `RenderSystem`, but the facade still directly owns
four source registries, two worlds, camera selection, material-asset
resolution, and their drain/clear details. `BeginFrame()` performs material
refresh, every registry drain, world command application, snapshot assembly,
backend/frame setup, renderer invocation, and capture completion.

The public surface also contains four avoidable weaknesses:

1. `GetGraphicsContext()` returns `{ GraphicsAPIType, void* }`. Its sole
   non-test consumer is Editor startup; the Vulkan renderer casts the pointer
   to the full `VulkanContext` only to recover `VulkanEditorBridge`.
2. `GetSceneRenderTarget()` exposes the complete Render-owned target even
   though Editor uses only its borrowed `RenderTargetView`.
3. `Tick()` duplicates the split `BeginFrame()`/`EndFrame()` path and has no
   production caller.
4. `PostInitialize()` no longer performs post-initialization work after R1.4;
   it only logs the prepared shader count through another scalar accessor.

The source-sink pointers are acquired by `RuntimeContext` before
`RenderSystem::Initialize()` and are retained by Gameplay and `LevelInstance`.
Their addresses therefore must stay stable across initialization, rollback,
normal frames, and shutdown.

## Concrete design question

How can R1.5 move scene ingestion/state behind one stable Render collaborator
and replace the Editor's untyped backend-context access with the minimum real
presentation capability, while preserving source-token lifetime, fixed pass
order, the current editor terminal pass, and both graphics backends?

## Chosen design

### Stable `RenderSceneCoordinator`

Add one concrete, non-polymorphic `RenderSceneCoordinator` as a direct or
otherwise address-stable `RenderSystem` member created with the facade. It
owns:

- `RenderableSourceRegistry`, `LightSourceRegistry`, `CameraSourceRegistry`,
  and `EnvironmentSourceRegistry`;
- `RenderWorld`, `LightWorld`, and the selected/default `RenderCamera`;
- the `MaterialAssetResolver` whose records translate material AssetIDs into
  private Render handles;
- source resolution, ordered draining, frame-scene snapshot assembly, and
  scene-side clearing.

It borrows the initialized `MaterialSystem`, `RenderResourceResolver`, and
immutable `PreparedRenderAssetCatalog`; it does not own the backend,
`FrameContext`, capture service, renderer targets, passes, or lifecycle state.

```text
Gameplay / LevelInstance
        │ stable sink interfaces
        ▼
RenderSceneCoordinator
  inboxes → resolve/drain → RenderWorld + LightWorld + camera + environment
        │ frame-scoped immutable scene input
        ▼
RenderSystem → DeferredRenderer → Graphics/RHI
```

`PrepareFrame()` preserves the current order:

1. refresh material resources;
2. drain renderable sources and apply pending `RenderWorld` commands;
3. drain lights, cameras, and environment;
4. snapshot lights and copy camera/environment values;
5. publish a frame-scoped scene input with a narrow shadow-handle validity
   query.

The returned input may borrow the stable `RenderWorld`, but all mutable or
cross-thread producer data is drained or copied before renderer invocation. It
must not be retained after the frame. This is not a second scene graph and does
not replace the existing fixed pass input with a universal context bag.

Initialization binds dependencies without replacing the coordinator or its
registries. Rollback and shutdown clear scene records and material instances
before `MaterialSystem`, resolver, frame contexts, renderer, and backend are
destroyed. A failed initialization may be retried without invalidating the
sink pointers already held by Runtime.

### Hardened `RenderSystem` facade

Keep only operations with a current consumer and a clear capability:

| Capability | R1.5 facade shape |
| --- | --- |
| Lifecycle | `Initialize`, `Shutdown`, lifecycle state and diagnostic |
| Frame | `BeginFrame`, terminal editor composition, `EndFrame` |
| Gameplay input | four borrowed source-sink interfaces delegated to the stable coordinator |
| Capture | borrowed `IRenderCaptureService` |
| Viewport | value-returning scene `RenderTargetView` and deferred extent request |
| Editor backend | borrowed `IEditorPresentationBridge` |
| Tooling | one value `RenderSystemMetrics` snapshot |

Remove `RenderSystem::Tick()` and `RenderSystem::PostInitialize()` after the
caller audit. Initialization logs the prepared-catalog summary once; Runtime's
empty Render post-initialize hop is removed. Replace `GetLoadedShaderCount()`
with `GetMetrics()` so future metrics extend a value snapshot rather than grow
unrelated scalar getters.

Replace `GetSceneRenderTarget()` with `GetSceneRenderTargetView()`. The facade
continues to own resize requests, but external consumers cannot reach the
target handle, attachments, or recording methods.

`BeginFrame()` remains the lifecycle owner and should read as four high-level
actions: prepare scene input, open the backend/frame context, invoke the
renderer and route capture outcome, then publish `FrameActive`. If backend
recording opens but no valid frame context/recorder is available, unwind that
backend bracket, clear active pointers, remain `Ready`, and return failure.
Pass recording failures retain the established fail-soft per-pass policy.

### Typed editor-presentation bridge

Add a common Graphics interface such as `IEditorPresentationBridge` containing
only its graphics API identity and a virtual destructor. `RenderBackend`
returns a borrowed bridge owned for the initialized backend lifetime.

- `VulkanEditorBridge` implements the common marker/capability and retains its
  existing Vulkan-only `GetInfo`, `Record`, and `WaitIdle` operations.
- A small OpenGL bridge identifies the active OpenGL presentation path; it
  exposes no raw GL context because the current ImGui backend uses the current
  render-thread context.
- `IEditorImguiRenderer::Initialize()` accepts the common bridge. Each
  API-specific EditorUILib adapter validates/downcasts to its own concrete
  bridge and fails initialization on a mismatch.
- `RenderSystem` forwards only `IEditorPresentationBridge*`; it never exposes
  `VulkanContext`, `OpenglContext`, a command buffer, queue, device, or manager.

Remove public `RenderBackend::GetGraphicsContext()`. Backend-private
`CreateGraphicsContext()` helpers may remain for legacy Graphics managers until
a separately scoped Graphics cleanup removes them; they are not part of the
Render/Editor seam.

The common bridge intentionally does not contain ImGui methods. Moving ImGui
into Graphics would reverse the dependency and make the RHI own tool policy.
The API-specific Editor adapter remains the approved location for native ImGui
initialization and draw recording.

### Borrowed scene view

`graphics::RenderTargetView` remains a narrowly documented presentation value.
Its native image tokens are borrowed, may be interpreted only by the matching
Editor adapter, and expire on target resize or Render shutdown. R1.5 does not
turn it into a general native-resource interop API. Tests must prove the Editor
refreshes the view each draw and does not retain it across extent changes.

## Public API disposition

| Current member | Decision |
| --- | --- |
| `Initialize`, `Shutdown` | Keep |
| `BeginFrame`, `ExecuteEditorCompositePass`, `EndFrame` | Keep as the one frame path |
| `Tick` | Remove; no production caller |
| `PostInitialize` | Remove; R1.4 left no work for it |
| four `Get*SourceSink` accessors | Keep; delegate to stable coordinator |
| `GetRenderCaptureService` | Keep |
| `GetGraphicsContext` | Replace with typed editor-presentation bridge |
| `GetSceneRenderTarget` | Replace with value-returning target-view accessor |
| `RequestSceneRenderTargetExtent` | Keep |
| `GetLoadedShaderCount` | Replace with a metrics snapshot |
| lifecycle state / last diagnostic | Keep for Runtime and orchestration tests |

## Threading and lifetime

- Gameplay may enqueue copied source commands from the game thread; only the
  render thread drains and mutates Render scene state.
- The coordinator and its sink subobjects exist from `RenderSystem`
  construction until facade destruction. Initialization and rollback never
  replace them.
- The prepared scene input is valid only for the synchronous renderer call in
  the active frame.
- The editor bridge is borrowed on the render thread and becomes invalid before
  backend cleanup. Editor UI shutdown remains earlier than Render shutdown.
- The scene target view is reacquired every Editor draw and is never an owner.
- GPU safety and teardown order remain: close active frame → clear scene and
  material users → wait/drain readback → frame/renderer/resolver resources →
  backend cleanup.

## Implementation stages

### R1.5.A — characterize and freeze the facade contract

- Add a caller inventory for every public `RenderSystem` method.
- Extend orchestration tests for stable sink addresses, failed-init retry,
  missing active recorder/context unwind, and borrowed-view invalidation.
- Record the current Editor initialization and shutdown order.
- Diagnose or explicitly disposition the outstanding R1.4 silhouette evidence
  before final R1 closure.

### R1.5.B — extract scene coordination

- Add `RenderSceneCoordinator` and a frame-scoped prepared scene input.
- Move registry/world/camera/material-resolution state plus drain/clear logic
  without changing source handles, order, pending/failed behavior, defaults, or
  environment/shadow semantics.
- Keep the sink addresses stable across the entire facade lifetime.
- Reduce `BeginFrame()` and cleanup to collaborator-level operations.

### R1.5.C — replace the native editor context seam

- Add the common typed editor-presentation capability.
- Adapt Vulkan and OpenGL backends and both ImGui renderer adapters.
- Remove the public backend and RenderSystem `GetGraphicsContext()` path while
  retaining only backend-private manager context helpers.
- Replace the full scene-target accessor with a borrowed value view.

### R1.5.D — remove stale facade paths

- Remove `Tick()` and the no-op `PostInitialize()` chain.
- Replace the scalar shader-count accessor with a metrics snapshot.
- Audit headers, comments, CMake edges, and tests for stale bootstrap,
  `GraphicsContext`, and full-target claims.

### R1.5.E — close R1 with evidence

- Run focused coordinator, RenderSystem, Graphics contract, Runtime, and Editor
  build/tests.
- Run the full Debug build and complete CTest sequentially.
- Run Vulkan and OpenGL smoke, resize, editor startup/shutdown, and fresh PBR,
  point-shadow, and spot-shadow captures.
- Inspect captures and record the exact comparator outcome.
- Create the R1.5 journal, update the review/status/risk ledgers, and close R1
  only when every parent acceptance criterion has evidence.

## Acceptance criteria

- [x] One stable scene coordinator owns all four source registries, both worlds,
  camera/environment selection, material-asset records, and ordered drain/clear
  behavior.
- [x] Gameplay/LevelInstance sink pointers remain valid across initialization,
  rollback/retry, normal frames, shutdown, and facade destruction ordering.
- [x] `RenderSystem::BeginFrame()` contains only high-level scene preparation,
  backend/frame bracketing, renderer invocation/capture routing, and lifecycle
  transitions; it owns no per-source resolution details.
- [x] Invalid frame-context/recorder acquisition unwinds a begun backend frame
  and never leaves `FrameActive` or a stale active pointer.
- [x] `Tick()` and the empty Render `PostInitialize()` chain are removed; the
  split frame bracket is the only production frame path.
- [x] Editor initialization receives a typed, borrowed presentation bridge;
  neither Render nor Editor can recover the full backend `GraphicsContext`.
- [x] Common Render/Graphics headers expose no Vulkan/OpenGL type, and native
  ImGui work remains inside the API-specific Editor/Graphics bridge pair.
- [x] Editor receives only a value `RenderTargetView`, reacquires it every draw,
  and cannot access the Render-owned target or attachments.
- [x] Capture, extent changes, pass order, material/environment behavior,
  source-token semantics, and teardown order are unchanged.
- [x] Focused tests, full Debug build/CTest, both smoke paths, editor
  startup/shutdown, and six inspected fixture captures pass; the R1.4 strict
  cross-backend comparator is resolved or superseded by reviewed policy.
- [x] A formal review and factual journal close all R1 acceptance criteria and
  list any intentionally deferred Graphics-internal cleanup.

## Validation plan

R1.5 changes shared Render/Graphics headers and Runtime/Editor wiring, so it
requires validation-matrix Levels 2–4:

- `RenderSystemTest` plus focused source/coordinator and render-pass suites;
- `GraphicsContractTest` for the common bridge and backend contract;
- affected Runtime and Editor targets;
- architecture searches for forbidden public context/target access;
- full Debug build and complete CTest;
- Vulkan/OpenGL `GraphicsSmoke` with resize and teardown;
- Runtime editor startup/close and PBR, point-shadow, and spot-shadow
  SceneColor captures on both APIs.

Compilation alone cannot close R1.5 because the stage changes frame lifetime,
editor presentation, resize-invalidated views, and cross-backend output.

## Required architecture audits

The implementation journal must record searches proving:

- no production caller of removed `Tick()` or `PostInitialize()` remains;
- `RenderSystem` and Editor do not expose or consume `GraphicsContext`;
- Editor no longer casts a general context to `VulkanContext`;
- Render public APIs do not return `RenderTarget` or attachment handles;
- no Vulkan/OpenGL type enters common Render/Graphics contracts;
- no new Render → Editor dependency or expanded RuntimeLib ↔ EditorLib cycle is
  introduced.

## Rejected alternatives

- **Only extract private helper functions:** reduces method length but leaves
  scene state, resolution, and cleanup ownership on the facade.
- **Move source registries into `DeferredRenderer`:** couples Gameplay ingress
  to one rendering policy and makes a future renderer switch own source tokens.
- **Return `VulkanEditorBridge*` from `RenderSystem`:** makes a common Render
  header backend-specific.
- **Rename the `void*` context and keep its payload:** preserves the unsafe
  general escape hatch without narrowing capability.
- **Move ImGui rendering into Graphics:** makes the RHI depend on Editor/tool
  policy and third-party UI types.
- **Create a universal `RenderContext`/service bag:** hides ownership and
  recreates the original R1 problem.
- **Solve the RuntimeLib ↔ EditorLib cycle here:** important but independent of
  the Render facade and too broad for the final R1 stage.

## Reference evidence

Studied on 2026-09-04; branches are recorded because no repository checkout is
pinned locally.

- [Filament `Renderer` (`main`)](https://github.com/google/filament/blob/main/filament/include/filament/Renderer.h)
  makes `beginFrame`/render/`endFrame` the explicit public bracket and requires
  successful begin calls to be paired with end. R1.5 adopts the narrow bracket
  and state guarantee, not Filament's engine/threading architecture.
- [Dear ImGui Vulkan backend (`master`)](https://github.com/ocornut/imgui/blob/master/backends/imgui_impl_vulkan.h)
  requires real Vulkan instance/device/queue data and a command buffer. This
  supports retaining an API-specific Editor adapter; it does not justify
  exposing the full engine backend context through Render.
- [bgfx public interop API (`master`)](https://github.com/bkaradzic/bgfx/blob/master/include/bgfx/bgfx.h)
  exposes `InternalData { caps, void* context }` only as native interop, warns
  that callers must understand internals, and restricts access to the render
  thread. R1.5 rejects that broad escape-hatch model for normal Editor startup
  and uses a typed presentation capability instead.
- The local [gkNextEngine study](../../graphics/gknext_reference.md) says to add
  boundaries only for real Runtime/Editor consumers and keep the core readable.
  The coordinator and bridge each have a distinct current owner, lifetime, and
  consumer; no renderer-plugin hierarchy is introduced.

## Risks and open questions

- `GraphicsContext` remains an internal Graphics helper for legacy resource
  managers after the public getter is removed. Deleting that internal type is a
  separate Graphics cleanup, not an R1.5 acceptance condition.
- `RenderTargetView` still carries opaque native tokens. Its scope is limited to
  the matching presentation adapter and its lifetime is resize-sensitive; a
  future multi-viewport/editor-texture system may justify a generational
  registration handle.
- The common bridge uses runtime type validation at the API-specific Editor
  boundary. If project RTTI policy later changes, replace the downcast with a
  closed backend-owned adapter factory rather than restoring `void*`.
- R1.4's strict silhouette difference is evidence debt, not proof of an R1.5
  source change. The final journal must distinguish the baseline comparator
  result from regressions introduced by R1.5.
