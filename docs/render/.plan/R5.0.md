# R5.0 — Baseline Freeze

**Status:** closed 2026-09-28. See the [baseline journal](../../../.spec/journal/2026-09-27-r5-0-baseline-freeze.md),
[exit review](../../../.spec/journal/2026-09-28-r5-0-exit-review.md), and dated
corrections.

**Parent:** [R5 stage map](R5.md) ·
[execution contract](../../../.spec/specs/render-r5-render-configuration-graph-ownership.md)

## Objective

Establish enough reproducible evidence to know which behavior and resource
lifetimes an R5 extraction must preserve. R5.0 records the current system; it
does not tune the renderer or close unrelated R4 quality gates.

## Scope

- Reconcile the reported R4.8 phase label without assigning R4.7 evidence a new
  stage ID or inferring acceptance.
- Freeze the current Render/Graphics ownership, request flow, plan conditions,
  cache keys, frame borrows, persistent resources, and cleanup order.
- Establish comparable raster and path-tracing fixtures and capture the
  included/executed/skipped/failed graph outcomes relevant to each output.
- Record unchanged-frame reuse and matched performance evidence before moving
  an affected runtime path.

## Procedure

1. Record source revision and pre-existing working-tree changes. Inspect the
   R5 finding ledger and the RenderSystem, DeferredRenderer, declaration/frame,
   Viewer/capture, profile, and Graphics RT ownership seams.
2. For each capture, record backend/API, fixture and revision, camera, viewport,
   requested and effective settings, actual RT mode, IBL, visibility method,
   SPP/bounces/filter, validation state, residency, warm-up and sample window.
   Keep different graph-demand or quality variants as separate comparators.
3. Capture RT-off raster on Vulkan and OpenGL, and capable Vulkan PT on
   representative Cornell and Sponza views. Preserve a usable raster parity
   reference; do not treat a zero-IBL raster image as PT parity evidence.
4. Save graph outcome evidence for the relevant producers and terminal output.
   For unchanged resident frames record packing/upload, descriptor, AS, cache,
   and CPU/GPU counters. Use the comparison budgets and image-parity limits in
   the [execution contract](../../../.spec/specs/render-r5-render-configuration-graph-ownership.md).
5. Review remaining gaps against the exit criteria before extracting a path
   whose behavior depends on those gaps. Other R5 design or focused CPU
   contracts may proceed.

## Exit criteria

- [x] Historical phase-label reconciliation and current ownership/reuse map are
  recorded.
- [x] Existing PT/cache conditions and comparison rules are documented.
- [x] Vulkan/OpenGL Cornell RT-off captures provide the current raster reference.
- [x] Representative Cornell/Sponza PT graph outcomes are indexed under the
  frozen conditions.
- [x] The R5.0 exit review evaluates those outcomes and states which R5.2 paths
  have a reproducible baseline.

## Constraints

- Keep the current eager plan count and resource ownership unchanged during the
  freeze; this stage is measurement and characterization.
- Debug Vulkan validation establishes correctness. RelWithDebInfo windows are
  performance evidence only and must use a rebuilt matching executable.
- A capture proves only its recorded backend, fixture, settings, output, and
  graph demand; it does not close a broader quality or lifecycle gate.
