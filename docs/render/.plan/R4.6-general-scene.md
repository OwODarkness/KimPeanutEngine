# R4.6 follow-up — scene-driven ray tracing

Status: design recorded 2026-09-26; not implemented.
Parent: [R4.6](R4.6.md). Evidence: [live Sponza review](../.review/R4.6.md#live-sponza-correction--2026-09-26-18021805).

## Question and decision

Why does Cornell work while Sponza path traces the wrong image, and what
contract makes both ordinary inputs to one renderer?

Use the existing RenderWorld, section materials, lights, and environment as
the semantic authority for both raster and RT. Ray tracing is an optional
execution policy consuming those records. A level name, mesh count, section
count, geometry index, or special camera must never select a material or light.
Cornell is a validation fixture, not a renderer mode. The user's 2026-09-26
requirement supersedes the earlier suggestion of explicit Cornell-integrator
selection in the review: remove fixture-specific shading entirely.

## Why the existing result is asymmetric

| Concern | Cornell branch today | Sponza branch today | General requirement |
|---|---|---|---|
| Branch selection | One mesh, 6–8 geometries inferred as Cornell | Everything else treated as generic | No scene classification |
| Surface color | Geometry 4/5 assigned red/green; others fixed neutral | One `proxy.material` color per instance, currently magenta fallback | Resolve the actual section material for the hit instance |
| Emitter | Geometry 0 treated as emitter; fixed rectangle/radiance in C++ | First directional light only | Emission and light sampling come from authored scene records |
| Attributes | Positions and face normal suffice for diffuse boxes | UVs, smooth normals, textures and PBR parameters unused | Reconstruct actual vertex attributes and evaluate supported materials |
| Miss | Black is suitable for the closed validation box | Authored HDR environment ignored | Evaluate the scene environment |
| Transport | One diffuse bounce demonstrates colored walls | Limited diffuse shading cannot represent Sponza PBR | Explicit integrator settings and a declared material support contract |

Source anchors: `deferred_renderer.cpp:1259` (scene heuristic),
`:949` (fallback color), `ray_tracing_path_tracer.rchit:109` (fixed colors),
`ray_tracing_path_tracer.rgen:140` (emitter index) and `:152` (geometry-zero
bounce exclusion). The live normal probe proves geometry traversal; uniformly
magenta albedo proves that a working traversal can still shade the wrong data.
Cornell success bypassed the missing general material/light integration; it
did not establish it. Increasing samples cannot recover omitted semantics.

## Ownership and data flow

```text
Asset Model/Material/Texture/Level data
  -> Resource processing and prepared catalog
  -> RenderWorld + MaterialSystem + LightWorld + environment snapshot
  -> immutable RT geometry/instance/material/light records
  -> Graphics upload, native address translation, BLAS/TLAS, binding tables
  -> hit reconstruction, material evaluation, light sampling, integration
  -> graph-owned accumulation, resolve, capture
```

Render owns material interpretation, scene inclusion, integrator/mode settings,
light selection, and revision keys. Graphics owns native addresses, AS objects,
SBT/descriptors, GPU tables, synchronization, and retirement. Keep CPU asset
loading in Asset/Resource preparation. Reuse resolved material and texture
resources; do not invent a second RT asset importer or expose Vulkan types.
Use the current collaborators first; this design does not authorize the broader
R5 renderer refactor.

## Hit identity and material resolution

Define copied records with stable logical indices and bounds:

- Geometry: mesh handle, section identity, index range/type, vertex layout and
  offsets, original material-slot index. Geometry describes a reusable mesh.
- Instance: geometry range, transform/normal transform, visibility/shadow
  policy, and a range in a per-instance material-slot table.
- Material slot: resolved MaterialInstanceHandle and a dense material-record
  index. Populate with `GetMaterialForSection(section.material_index)`, using
  exactly the raster fallback rules. An override applies to the instance.
- Material: supported shading model, factors, texture/sampler references,
  color-space/channel intent, emissive, alpha mode/cutoff and sidedness.

The lookup is:

```text
hit instance ID -> instance record
local BLAS geometry ID -> that instance's mesh-section record
section.material_slot -> instance material-slot table -> material record
triangle ID + barycentrics -> interpolated attributes -> material evaluation
```

Do not confuse section ordinal with material-slot index. Do not put one
material ID into globally shared geometry when instances can override it.
Geometry reordering/replacement updates lookup generations consistently with
the BLAS. Duplicate geometry can reuse a BLAS while differing material tables
remain instance-local. Validate all ranges before dispatch; invalid data is an
explicit preparation failure, not an arbitrary table read or silent omission.

Graphics translates buffer handles/offsets into native shader lookup storage;
replace Render's `GetBufferDeviceAddress` calls. Native device addresses may
exist in backend GPU records, but never in Render semantic descriptors.
Use sized GPU scene buffers rather than a baked 512-entry camera uniform.
Report actual counts and supported limits; reject excess explicitly.

## Surface and lighting evaluation

Read the real `data::Vertex` layout: position, normal, UV, tangent and bitangent.
Interpolate attributes with barycentrics; keep geometric normal for visibility
and offsets, and shading normal for BSDF evaluation. Apply inverse-transpose
normal transforms and handle mirrored/nonuniform instance transforms. Use
documented fallbacks only for missing attributes, not for an entire level.

The first general material contract covers StandardPbr metallic/roughness and
Unlit, base color, normal and scalar maps, emissive, and existing alpha/sidedness
semantics. Reuse sampler and color-space rules: color maps decode to linear;
normal/scalar maps stay linear; tone map once after accumulation. Define
explicit texture LOD behavior for ray hits, starting with a documented bounded
policy and later ray footprints. Do not assume RT texture-table binding already
exists; extend the common binding contract only for these actual consumers,
with capability/descriptor-limit validation.

Asset already stores alpha mode/cutoff; Render's current material state does
not expose the complete contract. Carry it through resolution instead of
classifying all BLAS triangles opaque. Camera, secondary, and shadow rays must
apply consistent alpha rejection and sidedness. Alpha blending/transmission
requires a separately declared supported subset; until implemented, report the
unsupported surface semantics explicitly rather than claiming full fidelity.

Visible geometry belongs in primary/secondary traversal even when it does not
cast shadows. Shadow rays honor the authored shadow policy separately; a shared
TLAS needs masks/filtering that preserve both policies. Material overrides can
change opacity, so BLAS reuse must not lock in an incompatible opaque flag.

Consume every supported enabled directional, point, and spot light plus the
environment. Use common units, attenuation/range, cone and shadow intent; the
point fill in Sponza has `casts_shadow=false` and must still illuminate.
Read emitter radiance from emissive material records. Build an emitter sampling
list from actual transformed emissive triangles; a rectangle optimization is
allowed only from explicit geometric/light data, never geometry index zero.
Cornell currently authors a point light and emissive materials whose values
differ from the hardcoded RT rectangle. Move the intended validation lighting
into assets with an explicit documented lighting recipe; do not retain a hidden
override or double-count a duplicate point/area source.

Evaluate environment on primary and secondary misses and sample it for direct
lighting. Accumulate throughput-weighted emission and BSDF transport in linear
radiance. When light/emitter/environment sampling overlaps BSDF sampling, use
consistent PDFs and MIS to avoid double counting. Delta lights use their own
sampling treatment. Configurable bounce/sample/seed settings are independent of
level identity; preserve the existing raygen-driven iterative dispatch model.
Robust ray offsets must scale with numerical error and geometry, not Cornell
world units. A limited bounce budget is a quality setting, not special shading.

## Optional mode, graph and lifetime contract

Use user-selected Raster (RT off), Hybrid ray-query shadows, or PathTrace.
Normal startup defaults to Raster; capability cannot select PathTrace on its
own. A master RT-off policy disables both RT consumers. Publish requested mode,
effective mode, unavailability reason, scene/material/light counts and samples.
Unsupported explicit validation requests fail visibly; interactive fallback is
reported. Pass selection depends on policy and readiness, never the level.

RT-off startup skips RT-specific shader preparation, pipeline/SBT, AS and scene
tables, history allocation and dispatch. Hybrid prepares only its requirements.
After live disable, stop scheduling RT work and retire resources after in-flight
use; re-enable resets history. Apply policy through the existing game-to-render
handoff at a frame boundary. No UI/command-thread renderer mutation.

The graph declares every geometry/table/texture/light/environment read, AS
build/read, history read/write, resolve and capture dependency. Physical address
reads must not hide buffers from graph barriers/lifetime tracking. Update tables
without overwriting in-flight consumers; retire superseded generations safely.
History revision covers section mappings, material values/textures/samplers,
alpha, emitters, all lights/environment, transforms, settings and pipelines,
in addition to the existing camera/extent keys.

## Reference evidence and limits

Studied NVIDIA `nvpro-samples/vk_gltf_renderer`, branch `master`, on 2026-09-26
(moving branch; no commit SHA pinned). Actual
[gltf_pathtrace.slang](https://github.com/nvpro-samples/vk_gltf_renderer/blob/master/shaders/gltf_pathtrace.slang)
resolves hit node/primitive records, evaluates their material/texture data,
adds emissive radiance, and evaluates environment misses.
[get_hit.h.slang](https://github.com/nvpro-samples/vk_gltf_renderer/blob/master/shaders/get_hit.h.slang)
interpolates normals/UVs/tangents and distinguishes geometric/shading normals.
Adopt these data dependencies, not its Slang, denoisers, glTF-specific ABI or
native-pointer ownership. Here, Render publishes semantic records and Graphics
encodes GPU layout; the reference's single-API design is not our boundary.

Discovery also checked the existing [gkNextEngine study](../../graphics/gknext_reference.md)
and its repository. Direct access to the selected shader directory failed, so
no new source-level gkNext claim is used. GitHub MCP is unavailable; web access
provided the directly read NVIDIA source. Existing raster section resolution
is the strongest local precedent; no external framework is required.

## Implementation sequence and acceptance

1. Establish explicit optional policy and a backend-owned scene upload seam.
   Preserve raster and hybrid behavior; remove Render address exposure.
2. Resolve geometry/instance/section/material identity; support instance overrides
   and interpolate attributes/textures. Prove fallback is used only for missing
   material slots. Add independent material-ID/albedo/UV/normal probes.
3. Consume scene lights/environment/emission and define general PBR transport.
   Author Cornell illumination as ordinary scene data, then delete its heuristic,
   fixed colors/light constants, emitter-index rule and geometry-zero exclusion.
4. Carry alpha/sidedness/shadow intent through Asset-to-Render resolution and
   traversal; close dynamic table, graph/history and lifetime coverage.
5. Run targeted Render/Graphics/material contracts, serial build/full CTest,
   and Runtime command/capture validation on Cornell, Sponza, and a small third
   fixture. Cornell color bounce and emitter must survive without any special
   branch; Sponza albedo must show section textures instead of uniform magenta.

Include adversarial fixtures: reordered sections; nonzero section index offsets;
multiple instances of one mesh with different material overrides; an unrelated
one-mesh/6–8-section scene; emissive geometry away from index zero; visible
non-shadow-caster; nonuniform transform; alpha cutout; and an environment-only
scene. Test each light independently and verify emission/MIS energy behavior.
Verify RT-off/hybrid/path-trace modes, unsupported backend, transitions, resize,
reload, semantic resets, logged validation and zero tracked resources on close.
Record samples/settings and capture paths; raster/RT images need semantic
agreement in materials/lights, not pixel equality between different integrators.

This task records the design only. The preceding live Sponza probes remain the
runtime baseline; no implementation, build or new runtime validation occurred
during this design pass. No level-specific repair is accepted as completion.
