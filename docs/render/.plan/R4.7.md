# R4.7 — General path-tracing optimization

**Status: R4.7.0 complete; R4.7.1/R4.7.2 source implemented, acceptance open.**

The [R4.7.2 runtime correction](../.review/R4.7.2.md) records the SBT stride
and exception-cleanup fixes and valid Debug Beauty captures. Do not treat
those correctness runs as matched performance acceptance.

Optimize the R4.6 scene-driven path tracer while preserving Sponza's authored
indirect illumination and the same Cornell/general-scene contract. The
[review](../.review/R4.7.md) owns source evidence and findings;
[TODO](../TODO.md) owns execution status; the
[spec](../../../.spec/specs/render-r4-7-path-tracing-performance.md) owns
acceptance. This stage does not require the broad R5 renderer decomposition.

## Boundary and invariants

Render owns quality policy, scene/material revisions, logical bindings,
history invalidation and graph requirements. Graphics owns GPU scene tables,
descriptor allocation, native address patching, SBT layout, AS build policy
and submission-safe retirement. Resource/Asset continue supplying derived
geometry and asset lifetime. Common contracts expose handles/descriptions,
not Vulkan pointers, addresses or descriptor pools.

- No level names, mesh counts, Cornell colors or Sponza-specific shader paths.
- Preserve four SPP, full resolution, eight continuation bounces, BSDF/Russian
  roulette, current light intensity/environment and probe modes for the
  quality-preserving optimization track.
- Keep off-camera transport geometry. Authored source visibility still applies.
- Scene/material/lighting/environment/texture-residency changes invalidate the
  appropriate cached data and accumulation; camera changes reset history but
  do not dirty immutable materials.
- Never update/free descriptors, table memory or addressed mesh buffers while
  submitted work can read them. No steady-state device-wide idle workaround.
- Failed dispatch does not advance history/sample count. RT off, unsupported
  capabilities, resize, scene replacement and existing failure semantics remain
  usable. R4.7 must not silently redefine failure as successful accumulation.

## Execution order

Each stage is independently reviewable and measurable. Keep changes only when
they remove verified work and/or improve measurements without violating the
acceptance contract. If a timing change is below run-to-run variation, record
it as inconclusive instead of combining it into an unsupported speedup claim.

### R4.7.0 — Establish trustworthy attribution

Freeze the working-tree baseline and build identity before code changes.
Use RelWithDebInfo for performance; Debug plus validation for correctness.
Record validation/layer state in each run rather than comparing unlike builds.
Retain current profile-window commands and extend only missing attribution:

- Frame elapsed, CPU work phases, explicit frame-slot fence wait and present
  wait; avoid double-counting overlapping phase timers.
- PT GPU p50/p95, total GPU samples, valid/fresh query count, graph mode,
  render extent, camera, lights/environment, SPP/depth, history reset reasons
  and completion state for textures with a full-resolution streaming loader.
- RT descriptor/pool/table-buffer allocation counts, table upload bytes,
  scene-table record writes, BLAS/TLAS build/update counts and retired resource
  count. The current table path rewrites every record; it has no dirty-record
  comparison yet, so written-record count is the baseline proxy.
- Optional diagnostic primary/continuation/visibility-ray and path-length
  counters, or vendor GPU profiling. Counter-enabled timings are diagnostics,
  not the final benchmark.

Cache completed profile summaries and avoid repeated percentile sorting when
the window did not change. Use backend begin timing as the initial wait clue,
not as a precise fence-wait measurement.

**Gate:** rerunnable baseline with matching settings, completed tracked texture
residency and separate wait/work attribution. Do not claim CPU resource churn
consumes the entire frame time.

### R4.7.1 — Dedicated opaque visibility rays (F1)

Extend `RayTracingPipelineDesc` with an optional visibility miss shader while
keeping existing one-miss consumers valid. Graphics constructs/validates the
additional miss SBT record, stages, group indices, aligned regions and shader
module lifetime. Shader reflection/binding layouts remain compatible.

In ray generation initialize a separate scalar payload as occluded, trace
with opaque + terminate-on-first-hit + skip-closest-hit flags, and select the
visibility miss record. Only that miss writes unoccluded. Do not route the
boolean through the full surface miss shader. Preserve point/spot distances,
directional intervals and origin bias. Current opaque-material limitations
remain explicit; future alpha testing needs a separate semantic design.

**Gate:** blocked/unblocked light tests, Cornell/Sponza captures and probe
views pass; visibility rays perform no full closest-hit material evaluation;
PT GPU timing and shader register usage are compared at unchanged quality.

### R4.7.2 — Reuse primary work and reduce hit shading (F2, F7)

Move current pixel-center camera-ray construction and primary trace outside
the per-sample loop. Reuse the immutable primary surface/miss result while
keeping each continuation's RNG stream, throughput and bounce state separate.
Compute deterministic primary emission/direct lighting once; distribute its
contribution correctly across the existing sample average. Probe modes may
short-circuit independently. Do not reuse stochastic secondary hits.

Then evaluate three small shader changes independently: builtin world-to-object
inverse-transpose normal transform; one packed metallic/roughness lookup when
slot and sampling semantics match; removal of verified unused payload fields
across raygen/hit/miss shaders. Keep barycentric reconstruction initially;
more aggressive position reconstruction is deferred until shader profiling
justifies it. Preserve mirrored/nonuniform normals and texture channels.

**Gate:** one primary ray per pixel per dispatch in the current center-sampling
mode, independent continuation samples and equivalent accumulated images.
Check increased live registers do not negate trace savings. Future primary
jitter/DOF/motion blur must disable or redesign reuse.

### R4.7.3 — Static trace-quality AS policy (F3)

Apply backend-owned `PREFER_FAST_TRACE` to static BLAS; test TLAS preference
separately. The flags used for build-size queries, allocation and build/update
commands must agree. Preserve update eligibility/compatibility and handle
generation. Existing static signature-based reuse remains in place.

**Gate:** record AS build/startup duration, memory and steady traversal/pass
timings. Retain only justified policy. If traversal still dominates, measure
BLAS overlap and memory before considering compaction or geometry regrouping.
Do not introduce compaction readback or repartition all Sponza meshes blindly.

### R4.7.4 — Persistent scene tables and frame-safe bindings (F4)

Split the current all-in-one binding-owned table into a Graphics-owned,
versioned table resource with portable create/publish/retire operations and a
handle binding. Native buffer addresses are patched only by Graphics. Start
with the existing table layout to limit shader ABI changes; compact storage
or SSBO conversion is a later decision driven by capacity/device limits.

Retain one immutable GPU table while its scene version is unchanged. For a
dirty version, publish replacement storage and retire the previous version
after its last submission completes. Do not allocate a replacement each frame.
Use bounded descriptor-pool storage and cached binding sets per frame slot and
history/output parity. Choose a dedicated stable-offset per-slot camera buffer
or a validated dynamic-offset binding; a changing frame-arena offset is part
of descriptor identity and must not be accidentally cached as constant.

Cache identity includes pipeline/layout, TLAS/table/mesh-buffer generations,
environment texture/sampler, output/history target generations, frame slot and
camera binding range/offset strategy. Resize, scene unload, shader reload and
texture retirement invalidate references before owners retire native objects.
Do not rely on arbitrary eviction age as proof of GPU completion.

**Gate:** after static-scene warm-up, zero steady descriptor-pool/set/table
buffer creation and zero unchanged scene-table upload; bounded resources over
long runs. Camera data still changes correctly. Exercise frames in flight,
resize, toggles, scene replacement and failure cleanup under validation.

### R4.7.5 — Revision-driven extraction and graph-driven preparation (F5, F6)

Introduce only revisions justified by current consumers: mesh geometry/buffer
generation, instance topology/transform, section material override, material
parameters, texture slots/residency, authored lights and environment. Prefer
existing producer revisions; if absent, add a narrow revision boundary rather
than assuming snapshot pointer identity proves unchanged contents.

Cache CPU records and update affected ranges. Maintain a stable mapping from
instance/geometry/material indices to the shader tables; insert/remove/reorder
must not leave cached offsets stale. Keep separate transport-history identity
from GPU allocation identity: a reused resource can contain changed lighting.

Select supported active graph requirements before raster shadow preparation.
Skip only work with no active consumer. Deferred capture/debug requests and
hybrid/raster frames still prepare the data they need. On returning to raster,
invalidate or recompute skipped shadow state; preserve defined failure behavior.

**Gate:** static PT frames do not re-resolve every section/material; camera-only
movement does not upload geometry/material tables; relevant edits and residency
changes refresh both tables and history. Capture views and RT-off behavior pass.

### R4.7.6 — Optional interactive budget, separate from optimization

After the unchanged-quality track is measured, expose scene-independent
settings for samples per dispatch and maximum continuation bounces. Keep the
current 4-SPP/8-bounce profile available and use it as the comparison reference.
An optional 1-SPP interactive profile can reduce latency at the cost of fewer
samples per frame; report accumulated samples and convergence per second.
Do not automatically lower bounce depth or silently switch profiles by level.

If lower render resolution is later justified, use an explicit setting and
report actual PT extent; upscaling/denoising require their own design and visual
acceptance. They are not prerequisites for R4.7. Settings enter the history
signature and the profile manifest. RT enable and PT enable stay explicit.

**Gate:** equal-SPP and equal-wall-time images are compared separately. A faster
frame from fewer samples is recorded as a budget tradeoff, not equivalent work.

Use the [spec](../../../.spec/specs/render-r4-7-path-tracing-performance.md)

## Targets and decisions

The preliminary three-window RelWithDebInfo baseline (before residency was
reported) had a median PT GPU p50 of 33.318 ms. It is superseded by three
matched, fully resident windows: PT p50 values are 33.852, 34.548 and 34.729 ms
(median **34.548 ms**); p95 values are 37.229, 37.225 and 47.155 ms. The
unchanged-quality goal is **20% lower PT GPU p50 (about 27.64 ms)** with stable
or improved p95. This is a goal, not an estimated gain or a promise of 100 FPS.
Require improvement beyond observed run variation and no meaningful
raster/lifetime/visual regression.

Reject global validation disabling as an optimization, camera-only RT scene
culling, fake ambient/fill changes, level detection, always-on ray counters,
and a blanket renderer rewrite. Defer SER, wavefront tracing, asynchronous
queue migration, denoisers and light-sampling redesign until profiling shows
the simpler candidates are insufficient. Russian roulette and static AS
reuse already exist. Startup asset verification is a separate investigation.

Reference choices, inspected source and limitations are recorded in the
[review](../.review/R4.7.md#reference-comparison), with factual research/check
history in the [journal](../../../.spec/journal/2026-09-27-render-r4-7-performance-plan.md).
