# D1 — Light source, snapshot, and shadow ABI

Parent: [Deferred PBR plans](../PLANS.md) · Roadmap: [TODO](../TODO.md)

## Design

Gameplay publishes copied directional, point, and spot values through a narrow
source sink and retains only an opaque registration token. At
`RenderSystem::BeginFrame`, Render resolves source commands into private
generational `LightHandle` values and immutable `LightWorld` snapshots.

`LightDesc` carries shared radiance/enable/layer data plus a typed payload and
optional `ShadowHandle`. `ShadowJobDesc` describes `Directional2D`, `Spot2D`,
or `PointCube` work without allocating a target. The versioned bounded
`LightGpuData` frame binding encodes unavailable shadows as unshadowed.

## Acceptance

- Gameplay and Asset own no Render handles or GPU objects.
- Payload, source ordering, stale-handle, snapshot, ABI, bounded-count, and
  unshadowed-fallback tests pass.
- Every pass consumes one immutable Render-owned light snapshot.
