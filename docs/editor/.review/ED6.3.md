# ED6.3 — Splitter and docking interaction review

- Date: 2026-11-11. Baseline: HEAD `70ff69e05666c93f8d11115feb5b538057596ab8` plus the working-tree workspace and presentation-host changes.
- Scope: Audio Player's neutral workspace and SceneEditor's legacy dock, splitter, overlays and layout storage. [ED6.3 plan](../.plan/ED6.md#ed63--establish-explicit-workspace-composition), [related migration review](ED6.5.md).
- Status: implementation fixes applied; visual and interaction acceptance remains open. Audio uses `EditorWorkspaceLib` with neutral Canvas splitters and draggable tabs; SceneEditor still runs `EditorToolRowComponent` and `EditorSplitterHandles`. [Audio composition](../../../engine/module/audio/editor/audio_player_editor.cpp#L162), [SceneEditor frame](../../../engine/editor/ui/editor_ui.cpp#L1152).

## Findings

### P1 · Audio's Float action aborts the frame · Reproduced

`DrawPanelActions` clears the panel's region immediately on Float. The dock branch still draws the panel body, then the floating pass sees the same open panel and submits its `.float` button again. `UiContext` rejects the duplicate ID, and the presentation host rethrows. The same ordering problem affects Move to a region visited later in the frame: the destination can submit the already drawn panel again. Moving to a region visited earlier defers its destination drawing until the next frame. Close also changes the state before the current callback has finished. [Action mutation](../../../engine/editor/workspace/editor_workspace.cpp#L27), [dock and float passes](../../../engine/editor/workspace/editor_workspace.cpp#L82), [duplicate check](../../../engine/editor/ui/api/ui_backend.cpp#L438), [host error path](../../../engine/editor/ui/host/editor_ui_host.cpp#L136).

**Implemented:** queue placement/visibility intents and commit at the end of the workspace frame. Each panel stays in its original host for the complete traversal, and active-member replacement is selected when closing or moving the active tab. This removes the same-frame second submission path. The original recording-backend probe reproduced `duplicate UI node ID in frame: audio_library.float`; this fix has compiled but the interaction probe has not yet been rerun.

### P1 · SceneEditor splitter can grab through a floating window and corrupt its ratio on focus loss · Reproduced

The splitter checks hovered/active items, popups and one optional exclusion. Empty space in a hovered floating window has no item to stop the raw click. SceneEditor supplies only Asset Reference's bounds. Tool-row floaters are absent and Settings is submitted after the splitter. The seam is painted in the foreground list, which ImGui appends after windows. Submission order of Settings cannot hide it. [Start guard and drag](../../../engine/editor/ui/component/editor_splitter_handles.cpp#L95), [SceneEditor frame order](../../../engine/editor/ui/editor_ui.cpp#L1167), [ImGui draw order](../../../third_party/imgui/imgui.cpp#L5642).

After losing focus, the pinned ImGui revision clears mouse state and sets the position to an invalid sentinel without producing a normal release edge. The active splitter still applies the delta and waits for `IsMouseReleased`. In a headless ImGui frame sequence, clicking inside a hovered floating window started the underlying splitter. After a focus-loss event, the button was up with no release edge, the drag stayed active, and the fraction changed from 0.80 to 0.15. A later release can save that unwanted value. A degenerate seam also skips the release check, and intersecting hit areas can assign the same press to more than one candidate during traversal. [Splitter loop](../../../engine/editor/ui/component/editor_splitter_handles.cpp#L114), [input reset](../../../third_party/imgui/imgui.cpp#L1541), [release calculation](../../../third_party/imgui/imgui.cpp#L9776), [save trigger](../../../engine/editor/ui/editor_ui.cpp#L1187).

**Implemented:** choose one exposed splitter on press; subtract floating windows, Settings and Asset Reference from both visible and hit-test segments; cancel on Escape, focus loss, invalid pointer, lost release or seam disappearance. Scene layout persistence now retains a dirty latch until the write succeeds. These source changes compiled; the ImGui headless repro and visible interaction checks remain to be rerun.

### P1 · SceneEditor dock preview and drop ignore the topmost surface · Reproduced

Target highlighting calls `HitTestDock` on the layout rectangles. Release runs `ResolvePlacementDrop`, which checks the same underlying dock geometry without consulting floating windows, Settings, popups or modal ownership. A release over an unrelated window covering a dock can therefore move the panel into the dock behind it. The foreground preview also draws over windows. `None` suppresses the ghost but still floats the panel on release. The floating-title path adopts any left-button drag currently over the title after the threshold. It never records that the press began on that title and does not distinguish native window movement from redocking. Like the splitter, the panel drag latch has no focus-loss or invalid-pointer cancellation. [Floating title drag](../../../engine/editor/ui/component/editor_tool_row_component.cpp#L274), [target highlighting](../../../engine/editor/ui/component/editor_tool_row_component.cpp#L438), [drop and preview](../../../engine/editor/ui/component/editor_tool_row_component.cpp#L501), [geometric target resolver](../../../engine/editor/ui/component/editor_tool_row_model.cpp#L7).

The headless legacy host probe dragged a tab from Tool Row and released it over a separate window covering Viewport. ImGui reported that the covering window was hovered on release, and the model moved the tab to the Viewport dock.

**Implemented:** only an explicit tab press starts a move; the preview and release share a resolver that excludes floating windows, popups, Settings and Asset Reference. Releasing on exposed workspace background explicitly floats; releasing outside the work area or behind an occluder cancels. Escape, focus loss, invalid pointer and missing release cancel the gesture. Source changes compiled; the headless repro and visible cases remain to be rerun.

### P1 · Audio's neutral host has no direct splitter or docking gesture · Open

The only split interaction is a Slider in a separate Workspace window. `Resolve` exposes leaf bounds, with no parent or seam geometry to register a handle. Tabs use the standard backend tab bar with no reorder flag, tab drag source or dock target. Float, Close, Move to and Dock buttons sit in the panel content. This leaves direct seam dragging, cross-dock drag with preview and tab insertion undefined in the new host. A tab disappearing when the dock changes from two panels to one also changes the available chrome and interaction path. [Workspace actions](../../../engine/editor/workspace/editor_workspace.cpp#L27), [tabs and layout controls](../../../engine/editor/workspace/editor_workspace.cpp#L91), [model bounds](../../../engine/editor/workspace/editor_workspace_model.cpp#L123), [backend tabs](../../../engine/editor/ui/api/ui_imgui_backend.cpp#L139).

**Implemented:** resolved split bounds drive neutral Canvas splitters; tab press/move/release uses a drag threshold, shows a destination preview and commits after all hosts have been drawn. Drop into an occupied region selects the moved panel, and drop on empty workspace area floats it. Canvas capture cancels on Escape or loss of focus. Audio's direct interaction now compiles, but both axes, overlap behavior and live input still require acceptance.

### P2 · Audio's split limits can shrink descendants when there is room to satisfy them · Reproduced

The Audio root gives its right subtree a 400 px minimum even though the next horizontal split asks for 300 + 200 px. The resolver clamps each node against its own configured minimums and proportionally shrinks the children when they do not fit the resulting extent. At 700 logical px, the recorded 180/400 outer limits allow a Slider edit to leave 400 px for the right subtree. Its center/right widths fall from 320/200 to 240/160, even though a valid 180/300/200 arrangement fits. Sliders also use one 0.05–0.95 range independently of the current parent, so displayed changes can have no geometric effect after clamping. [Audio split preset](../../../engine/module/audio/editor/audio_player_editor.cpp#L44), [local clamping](../../../engine/editor/workspace/editor_workspace_model.cpp#L13), [recursive resolve](../../../engine/editor/workspace/editor_workspace_model.cpp#L129), [Slider range](../../../engine/editor/workspace/editor_workspace.cpp#L132).

**Implemented:** subtree minima are resolved bottom-up, the layout Slider uses the currently legal ratio range, and direct splitter updates are clamped through the same model. When the viewport is below the total minimum, the layout scales minima proportionally. The 700 px headless scenario and narrow-window visual case still need rerunning.

### P2 · Audio panel activation and floating-window identity do not belong to the workspace model yet · Open

`ShowPanel` only sets `open`. It cannot select an already-open inactive tab or focus a floater. Audio import calls this route for the playlist, so the Output Log tab can stay in front. A move into an occupied dock also has no explicit selection contract. The neutral model has no active member, order, float geometry or workspace namespace. The backend uses `window.id` to cache geometry but passes the visible label alone to `ImGui::Begin`. Two windows with equal labels therefore share a native window even with distinct neutral IDs. Fixed dock windows only set NoMove/NoResize, so they can collapse and take front focus. Floaters initially share one rectangle, and a viewport extent, origin or scale change forces them back to that rectangle. [Show and rendering](../../../engine/editor/workspace/editor_workspace.cpp#L22), [panel state](../../../engine/editor/workspace/editor_workspace_model.h#L39), [Audio queue request](../../../engine/module/audio/editor/audio_player_editor.cpp#L262), [native window mapping](../../../engine/editor/ui/api/ui_imgui_backend.cpp#L66).

**Partially implemented:** selected member is model state; Show and Move select the target panel; neutral window IDs are workspace-scoped while visible labels remain separate. Fixed dock surfaces disable collapse and front-taking, and floating windows retain their first-use geometry instead of resetting on viewport changes. Tab order persistence, explicit float recovery/clamping, duplicate-label multi-workspace interaction and resize/DPI visual checks remain open.

### P2 · Audio has no workspace round trip and SceneEditor only saves part of its state · Open

Audio constructs a fresh preset at initialization and destroys the workspace at shutdown. No workspace layout store restores split ratios, panel placement, visibility, active tabs or float geometry. The native backend forcibly applies default floating geometry on first submission, so incidental ImGui ini state cannot serve as a reliable restore path. SceneEditor already reads and atomically writes its legacy layout. The v3 payload captures split ratios, panel dock and lock, with no active tab, open state or floating rectangles; legacy floating windows use separate title-based ImGui settings for geometry. A failed splitter-only write has no pending dirty latch after the release flag is consumed. [Audio lifecycle](../../../engine/module/audio/editor/audio_player_editor.cpp#L159), [floating window defaults](../../../engine/editor/workspace/editor_workspace.cpp#L112), [legacy load and save](../../../engine/editor/ui/editor_ui.cpp#L1077), [legacy placement fields](../../../engine/editor/settings/editor_layout_settings.cpp#L297), [atomic writer](../../../engine/editor/settings/editor_layout_settings.cpp#L214).

**Partially implemented:** SceneEditor save failures retain a dirty latch and retry until a successful write. Audio workspace state is still in-memory plus backend first-use window settings: there is no versioned workspace store for split ratios, active tab, visibility, placements or floating geometry. Define and implement that round trip before accepting ED6.3.

## Validation and acceptance

- Headless C++20 probes compiled against current production sources. The recording backend reproduced Audio's duplicate ID, and the new layout model reproduced the 700 px minimum failure with a reduced Audio-shaped preset. Probes using pinned ImGui reproduced splitter grab through a hovered window, stale/corrupted drag state on focus loss, and a legacy dock move through a hovered window. These probes create no OS window and were kept outside the repository.
- Existing layout, placement and panel-lifecycle tests cover legacy model transitions and serialization, not neutral workspace rendering or live z-order. The ImGui scope checker reported a dynamic-count StyleColor mismatch in the legacy tab strip. Manual inspection verified both pushes increment the count passed to its pop. [Layout tests](../../../engine/test/unit/editor/editor_layout_model_test.cpp#L599), [placement tests](../../../engine/test/unit/editor/editor_tool_row_model_test.cpp#L731), [lifecycle tests](../../../engine/test/unit/editor/editor_ui_lifecycle_test.cpp#L410), [tab style scope](../../../engine/editor/ui/component/editor_tool_row_component.cpp#L356).
- Debug builds passed for `EditorUILib`, `EditorWorkspaceLib` and `AudioPlayerEditorUI` after the interaction changes. A visible Debug Vulkan launch confirmed Audio Player starts, and exposed that the Workspace utility window was submitted even after its close flag became false; it is now submitted only while `layout_open_` is true. The fix has compiled, but was not relaunched for visual confirmation. No CTest or headless interaction rerun was performed. Audio layout persistence, float recovery bounds, SceneEditor interaction, and Vulkan/OpenGL visual acceptance remain open.
