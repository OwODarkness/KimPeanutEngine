## Objective

A manga-style speech bubble for the character: one that hugs its text, carries a
tail aimed at the model, pops in when its text is set, and appears in the same
image as the model.

## 1. The bubble is drawn, its content is a display

The first design drew the bubble's shape into the same dot matrix as its text, as
a chunky pixel outline. Reviewed against the goal it was the wrong shape: the
bubble should read as *drawn*, and only its content should read as a display.

So the outline became a signed distance field — a rounded body unioned with a
tapering tail — and the dot matrix became the text's alone. That removed a change
that had already been planned: the bubble's fragment shape provides transparency
natively, so there is no need to distinguish *paper* from *transparent* per dot,
and the mask stays one bit per dot. The stamping, its merge modes, and the
byte-alignment invariant were all untouched.

## 2. The interior is a matrix, and that took three colours

The first SDF version filled the bubble with a flat colour and drew the text as
dark dots. Reviewed, that reads as ink on a page rather than as a display: no dot
has a boundary, and the background is not digital at all.

The interior now draws **every dot as a cell, lit or not**, with a bezel between
them. Three colours are needed to say it — the paper, the lit dot, and the gap —
and the grid's pitch is derived from the text's own dot count, so characters land
inside cells rather than straddling two.

Measured at 1:1, where `+` is the bezel, `.` a paper cell and `#` a lit one:

```
...++....++###+++###++###+++###++....++...++....++...+++...++...+++...++
...++####++###+++...++...+++###++####++...++....++...+++...++...+++###++
...++####++...+++...++...+++...++####++...++....++...+++...++...+++###++
```

## 3. A second pass erases the model

The exploration established this before any code was written, and it shaped the
whole composition: both backends re-apply the target's `load_op` clear on **every**
`BeginRenderTarget` (OpenGL `opengl_command_recorder.cpp:101-108`; Vulkan
`vulkan_render_target_manager.cpp:304-314`), and the Live2D output target is
created with `load_op = Clear`. `SubmissionPass` has no per-pass load override for
offscreen targets.

So the bubble's draws are appended to the model's pass. `Live2DRenderer::Record`
gained a generic extra-draws parameter and appends them to the pass the planner
pushes last, after the model's own so they paint over it. Nothing about the bubble
crosses into the renderer: it receives ordinary `render::RenderSubmission` draws.

A naive second pass validates cleanly, renders, and leaves an image containing only
the bubble. That is the failure this design exists to avoid, and it looks like
success.

## 4. Three defects, all in the host, which has no test

**The commands raced the render thread** — carried in from the panel stage and
fixed there; recorded here because the bubble's host work sat on the same seam.

**The bubble had no text.** The layout was sized from the text's *lit bounds* (24
by 16 dots) while the shader sampled the *full* 512 by 256 mask across that
region, squeezing "OvO" into the left 5% of the bubble. Fixed by measuring where
the ink sits inside the mask at upload time and telling the shader —
`MakeInkUv`, now a tested pure function.

**It segfaulted at exit.** `bubble_` was never reset in `CleanupGpu`, so its
destructor ran after `backend_.reset()` and called `WaitIdle` on a dangling
pointer. Diagnosing it was instructive: the capture landed, the process died, and
**no log file existed at all** — because the logger flushes at shutdown, which the
crash prevented. A crash that also destroys its own evidence.

That is now three defects in this feature to live in the host. The pattern is
consistent enough that "the host has no test" is the finding, not the individual
bugs: the fake-backend renderer test cannot see cleanup *ordering*, which is what
the third one was.

## 5. Two false alarms, both mine

**A cross-backend divergence that did not exist.** I measured 213,759 differing
samples with a maximum delta of 247 and reported it. It was a comparison against a
*stale* capture: the capture service suffixes rather than overwrites when a name
exists, so I had compared a new OpenGL image against a Vulkan one from before the
change. Same-code captures differ by **131 channel samples of 2,764,800, maximum
1/255** — alpha-blend rounding, not a divergence.

The tell was in the difference map: the model region was pixel-identical and only
the bubble differed, and the differing region spanned the *union of two bubble
positions*. That is what a moved object looks like, not a different one.

**A `target_aspect` bug that did not exist.** The new diagnostic logged
`target_aspect 1.0000` for a 720 by 960 target. It was the log firing on frame 1,
before the extent settles; the captures were byte-identical before and after the
"fix", which is what proved it. The aspect is now read from the frame's own extent
— unambiguously the thing being drawn into, rather than coincidentally right.

## 6. Placement took three tries

Centred at the top first, which put the bubble on the character's head and hid the
face — the one thing the viewer exists to show. Then upper right, then upper left:
smaller and beside the character rather than over it.

One thing changed by itself and correctly: moving the bubble to the left changed
the tail's lean to down-right, because the tail is aimed at the model's fitted
centre rather than at a fixed direction. No code touched, which is the
bounds-to-direction seam doing what it was built for.

## Remaining risks

1. **The host still has no test** (§4). Three defects in one feature, one of them
   a crash that destroyed its own log.
2. **A capture comparison can silently compare across runs** (§5). The capture
   service suffixes on collision, so a name-based comparison is not a version
   match. Worth a rule: compare only captures taken from the same build.
3. **The bubble is not attached to the model** — a fixed 2D position, needing hit
   areas to do better (L2D7).
4. **Its appearance is not settable at run time**, unlike the panel's.
5. **The shader's real compilation is only proved by a live run.** The
   fake backend mints pipeline handles without compiling GLSL, so tests 1-3 do not
   cover it; test 5 does.
