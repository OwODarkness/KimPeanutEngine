# L2D10.0 host decomposition — 2026-09-29

## Boundary and intent

The first pass reduces direct responsibilities in `Live2DViewerHost` without
changing frame order, GPU ownership, or the viewer command surface. The host
continues to own lifecycle, scheduling, render-thread cleanup, input routing,
and bubble GPU lifetime. New collaborators own editor presentation, command
registration, and semantic emotion orchestration.

## Implemented

- Added `engine/module/live2d/editor/` with a copied-state viewer editor and a
  command bridge. ImGui and command descriptors no longer live in the host.
- Added `engine/module/live2d/emotion/` with a UI/Cubism-free deterministic
  controller and callback-based orchestrator. A future decision model can be
  injected without changing the editor or renderer.
- Replaced product-independent `Live2DVector2` values with
  `kpengine::Vector2f`, retaining SDK-native `csmVector2` conversion only at
  the Cubism boundary and asserting the GPU upload layout.
- Kept the host's bubble timing and GPU cleanup intact while adapting emotion
  actions through the new orchestrator; this is the next safe seam for a later
  preview-session extraction.
- Corrected graphics-stage descriptors for Live2D and bubble uniform blocks;
  vertex+fragment visibility is now represented explicitly instead of being
  formed by arithmetic on sequential enum values.
- Added explicit render-submission target-usage declarations and transitions:
  the mask atlas becomes sampled between the mask and model passes, and the
  completed Live2D output becomes sampled before the Vulkan/ImGui presentation
  and readback consumers.
- Standalone Live2D frames now tick the log system, so viewer validation output
  is flushed to the current log rather than leaving only a previous session's
  file.
- Added `editor::Live2DViewerBubble` as the sole owner of panel glyphs, bubble
  appearance, layout/timing, and bubble GPU handles. The host now passes only
  frame extent and copied model bounds into this presentation seam.
- Added `Live2DEmotionRuntime` under `emotion/`. It owns the semantic
  orchestrator and deterministic replay evidence; the host supplies callbacks
  for renderer actions instead of owning emotion state directly.
- Relocated policy, resolver, replay, and runtime-facade sources from
  `runtime/` into `emotion/`. `Live2DProduct` now contains only immutable
  product serialization, while `Live2DEmotion` owns semantic emotion code.
- Reduced the host header to a coordinator-facing surface and converted the
  command bridge/system/emotion/bubble ownership to explicit pointer members.
- Added an out-of-line host-owned deleter for opaque collaborators, so the
  header now keeps only the application contract, launch/math value contracts,
  and forward declarations; renderer/RHI/editor implementation headers stay in
  the `.cpp` translation unit.
