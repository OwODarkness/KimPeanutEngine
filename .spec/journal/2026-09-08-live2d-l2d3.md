# L2D3 — Offline Live2D import command

## Objective

Connect the existing module-owned `.model3.json` provider to the offline asset
tool so a source closure becomes a deterministic `.live2d` product and native
Texture dependencies at an explicit output path.

## Design boundary

`KimPeanutAssetTool` owns command parsing, staging, collision checks, and
publication. `Live2DImport` remains database-free and supplies the typed
product. The runtime command harness is unchanged because it is not an asset
import host.

## Reference gate

The local `AssetImport` provider registry and existing texture publication path
are the primary precedent. Godot's command-line `--import` flow was inspected
as an external precedent: offline import is an explicit tool operation that
finishes before runtime execution. SakuraEngine was also checked for module
and tool layout; its current tree did not expose a directly reusable importer
transaction pattern. No external source was copied.

## Landed

- Added conditional `Live2DImport` linkage to `KimPeanutAssetTool`, preserving
  the SDK-off tool build.
- Added `import-live2d --source ... --output ...` with optional asset/archive
  roots.
- Staged provider output before copying content-addressed products.
- Rejected differing existing `.live2d` or Texture bytes and removed files
  created by a failed publication.
- Updated the Live2D roadmap, architecture plan, and project status.

## Validation

- `cmake --build build-live2d --config Debug --target KimPeanutAssetTool -- /m:2`
  passed.
- `cmake --build build-live2d --config Debug --target Live2DCoreTest -- /m:2`
  and `ctest --test-dir build-live2d/engine/test -C Debug -R Live2D
  --output-on-failure` passed all 6 tests.
- `cmake --build build-live2d-off --config Debug --target KimPeanutAssetTool --
  /m:2` passed with Live2D disabled.
- The Hiyori `import-live2d` command produced one `.live2d` root and two
  texture products; an identical second invocation passed without a collision.
