# Asset AX1.4 journal — extension hardening

Date: 2026-09-08

## Objective

Harden the generic runtime asset extension boundary after AX1.3 and document
the registration contract that future modules consume. AX1.4 is a correctness
and ownership stage: it does not turn the current shared-loader pipeline into a
parallel decoder.

## Design and reference gate

The local AX1 design keeps runtime registration in `AssetRuntime`, while
offline provider selection remains in the database-free `AssetImportRegistry`.
The existing lock table is authoritative: loader callbacks run under
`load_mutex_`, dependency requests are resolved after that lock is released,
and cache publication takes `state_mutex_` only after validation.

The AX1.3 reference gate remains applicable. Godot's
[`ResourceFormatLoader`](https://github.com/godotengine/godot/blob/master/core/io/resource_loader.h)
supports explicit loader registration and recognized suffixes; O3DE's
[`AssetBuilderDesc`](https://github.com/o3de/o3de/blob/development/Code/Framework/AzToolsFramework/AzToolsFramework/Asset/AssetBuilderSDK.h)
uses stable builder identity, patterns, versioning, and callbacks. KimPeanut
Engine adopts only the applicable composition ideas: stable descriptors,
explicit registration, and suffix dispatch. It retains its own typed payload,
AssetID/cache ownership, dependency transaction, and one-way registration seal.

## Landed changes

- Added `AssetExtensionHardeningTest` as an isolated `AssetRuntime` test target.
  Its fake external module registers one valid type plus malformed, throwing,
  dependency-failing, and concurrent-loader descriptors.
- Covered successful custom loading, payload/type mismatch rejection, loader
  exception rollback, missing dependency rollback, same-path async identity
  deduplication, serialized callback access, unload/stale handle behavior, and
  direct registration validation.
- Changed the observed `LoadAsync(path, session)` entry point to resolve the
  type through `AssetTypeRegistry`, so custom suffixes report their registered
  type instead of falling through the legacy built-in mapping.
- Documented that built-ins are registered by `AssetManager` itself, custom
  modules choose stable values in `0x1000..0xEFFF`, registration must precede
  the first load, and callbacks only fill `AssetRegisterInfo`.
- Kept Live2D out of Asset source and left the Live2D consumer handoff open for
  its own stage.

## Remaining risk

The current `load_mutex_` intentionally serializes all registered callbacks.
AX1.4 proves the safety/deduplication behavior but does not provide parallel
decode throughput. A future loader-pool or per-loader-instance change must
revisit the lock table and add separate performance evidence.
