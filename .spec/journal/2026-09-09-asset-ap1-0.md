# AP1.0 — Startup profiler first slice

Date: 2026-09-09

## Landed

- Added Asset observation attribution for cumulative dependency wait,
  per-AssetType totals, source/decoded bytes, and a completion-indexed startup
  ledger of completed operations. The profiler can sort that ledger by index,
  total time, source time, or memory; durations at or above one second are
  displayed in seconds.
- Added the loading-only `Startup Profiler` ImGui window. It reads copied
  `StartupSnapshot` values, samples peak process memory through the existing
  platform seam, and does not acquire Asset, Runtime, or Render locks.
- Kept the runtime validation fixture small: `level/performance_profile.level`
  contains the Stanford bunny and Cerberus. Sponza remains the fixed large-scene
  stress case for later AP1 stages.

## Validation

- Debug build: `EditorUILib`, `AssetUnitTest`, `EditorUILifecycleTest`, and
  `KimPeanutEngine` built successfully after the Visual Studio SDK probe was
  run with elevated access.
- Focused CTest: 19/19 passed, including the completion-ledger and UI coverage.
- Full Debug CTest: 439/439 passed.
- Runtime smoke: OpenGL launch with
  `--startup-level level/performance_profile.level --agent-port 37373` reached
  the ready workspace; the log reported 24 registered assets, 23 load
  operations, 3 cache hits, and 16.934 s of Asset loading with the bunny and
  Cerberus fixture.

## Follow-up shutdown presentation

- The existing loading panel now switches to `Closing engine` when the render
  thread begins RuntimeContext teardown. Runtime cleanup reports seven visible
  stages covering gameplay, level, reflection/scripting, renderer, prepared
  assets, input, and window release; each stage publishes copied progress before
  the corresponding release work begins.

## AP1.0 acceptance

- The fixed Debug Sponza baseline is 126 registered assets, 195 load
  operations, 74 cache hits, and 317,488.018 ms of Asset-phase loading. The
  corresponding profiler texture closure is 80 products and 1,789,607,680
  source bytes.
- The same 126-asset closure measured 158,746.199 ms after AP1.1's single
  verification path and 82,740.589 ms after AP1.2's single-profile BC startup
  path. The latter reports 80 textures and 447,432,640 source bytes.
- The Startup Profiler exposes the accepted attribution surface: every
  completed operation, completion index, exclusive timing fields, source and
  decoded bytes, sortable time/source/memory columns, cache-hit evidence, and
  sampled peak process memory. AP1.0 is accepted; AP1.3 remains the next
  implementation stage.

## AP1.1 — Product verification

### Landed

- Added `Sha256WithZeroedRange`, which computes the content hash and the
  embedded-digest hash from the loaded byte vector without allocating a second
  product-sized integrity input.
- Native Texture and Model loaders compute both hashes once, pass the content
  hash into archive filename verification, and pass the pair into structural
  deserialization. Direct deserializer callers retain a safe fallback that
  computes the same pair without the old full-product clone.
- Replaced native cook-time `BuildIntegrityInput` copies with the same
  zeroed-range hashing contract. Malformed products, truncated digests,
  filename mismatches, and embedded-digest mismatches remain rejected.

### Reference gate and boundary

- Distill's `loader/src/packfile_io.rs` was inspected for immutable
  buffer/mapped-byte lifetime during packfile decoding.
- O3DE's `Code/Tools/AssetProcessor/native/utilities/assetUtils.cpp` and
  Godot's `doc/classes/HashingContext.xml` were inspected for chunked hashing
  patterns.
- This stage keeps KimPeanutEngine's existing owned product vector and
  database-free AssetProduct boundary. It adopts no mmap or package layer;
  those belong to later AP1.4 work.

### Validation

- Elevated Debug build succeeded for `AssetProduct`, `AssetNative`,
  `AssetRuntime`, and `AssetUnitTest` after the non-elevated build was blocked
  by the Visual Studio SDK probe directory permission.
- Focused Asset tests: 15/15 passed for ModelArchive hash verification,
  native Model format/loader behavior, and Texture import/round-trip paths.

## AP1.2 — GPU-native Texture compression

### Landed

- Extended the common texture contract with BC4 UNORM, BC5 UNORM, BC3 UNORM,
  and BC3 sRGB. Native Texture V2 validates raw and block-compressed mip sizes
  from the directory metadata while retaining a V1-compatible reader path.
- Added deterministic offline BC cooking selected by semantic: BC3 sRGB for
  color/generic, BC3 UNORM for packed linear, BC5 UNORM for normals, and BC4
  UNORM for opacity masks. Portable RGBA8/RGBA16F cooking remains available.
- Added Vulkan mappings and OpenGL RGTC/S3TC mappings with compressed mip
  upload calls. Backend capabilities report sampled support for each BC format;
  Render refuses an unsupported compressed payload rather than expanding it or
  uploading it through an uncompressed path.
- Added `cook-texture --compression portable|bc`; model import settings accept
  the same compression policy for later profile-driven recooking.

### Validation

- Elevated Debug build passed for `Graphics`, `RuntimeLib`, `AssetImport`,
  `TextureImportTest`, and `GraphicsContractTest`.
- Focused Asset/import tests passed 9/9, including native compressed round-trip,
  semantic format selection, deterministic bytes/hashes, and model-import
  compatibility. Graphics contract tests passed 15/15.

### Remaining boundary

The Sponza <=550 MB closure measurement, package-level logical-texture variant
map, BC7/ASTC profiles, and the final cross-backend Sponza capture remain open.
Material startup profile selection is now implemented before Asset dependency
resolution, so a backend does not cause both portable and BC products to load.

## AP1.3 — Compact native Model profile

### Landed

- Bumped the current native Model product schema to V3 while retaining V1/V2
  deserialization. V3 uses a 24-byte vertex record: 16-bit position relative
  to model Bounds, signed 16-bit octahedral normal/tangent pairs, half UVs, and
  one bitangent-handedness byte. The runtime reconstructs the existing
  `data::Vertex` representation, including bitangent from the normal/tangent
  cross product.
- The offline serializer performs deterministic first-use vertex remapping,
  drops unreferenced vertices, and writes 16-bit indices when the compact
  vertex count fits; larger meshes retain 32-bit indices. Sections, material
  references, Bounds, integrity hashing, and archive identity remain explicit.
- The importer default and settings hash now select Model V3. Import-time
  round-trip validation checks topology and metadata while allowing the bounded
  attribute quantization error. No Graphics/RHI vertex ABI changes were made.

### Reference gate and boundary

- The local AP1 plan and `docs/engine-reference/README.md` identify
  meshoptimizer as the relevant precedent. Its public documentation was
  inspected directly: the recommended order is cache/fetch locality followed
  by quantization, and its lossless vertex/index codecs expect optimized input.
  KimPeanutEngine adopts the ordering and deterministic quantized representation
  idea without adding the third-party library or changing runtime ownership.
- The current slice deliberately stops before an external entropy codec or GPU
  vertex format. Runtime remains Asset-owned decode to the existing CPU mesh;
  Graphics/RHI continues to own upload and backend-specific resources.

### Validation

- Elevated Debug build passed for `AssetNative` and `NativeModelTest`.
- `NativeModelTest`: 11/11 passed, including deterministic V3 round-trip,
  24-byte vertex/16-bit index chunk assertions, corruption rejection, loader
  dependency behavior, rollback, concurrent deduplication, and runtime graph
  integration.
- Elevated Debug `ModelImportServiceTest` build and run passed 6/6, covering
  V3 import cache hits, reimport, publication, collision, and rollback paths.
- Sponza reimport byte/decode timing, retained-memory comparison, and Vulkan /
  OpenGL visual validation remain pending; AP1.3 is not yet marked accepted.

### AP1.3 repeatable Model measurement

- Extended `NativeModelProduct` with decoded format metadata and byte metrics:
  native version/features, vertex/index strides, product bytes, and a decoded
  CPU payload estimate. The estimate includes the runtime vertex, index,
  section, material-reference, and bounds payloads, but excludes allocator
  overhead and GPU residency.
- Extended `KimPeanutAssetTool inspect --model` to read and decode the resolved
  native product and report those metrics plus separate file-read and decode
  timings. The command is read-only and does not reimport or mutate the
  archive.
- The command was exercised against the existing bunny V2 product:
  34,834 vertices, 208,353 indices, 2,784,460 product bytes, and about 0.18 s
  decode time in Debug. This confirms the measurement path remains backward-compatible;
  it is not a V3 size result because the checked-in bunny product has not been
  reimported.
- Validation: elevated Debug build of `KimPeanutAssetTool` and
  `NativeModelTest` succeeded; `NativeModelTest` passed 11/11. The working
  archive was not modified. Sponza reimport and backend visual evidence remain
  the AP1.3 acceptance gate.

### AP1.3 acceptance

- User validation completed the reimport and comparison for all three Sponza
  Model products. The products report native Model V3, are approximately 45%
  smaller than the previous products, and decode faster.
- User visual validation reported no Vulkan/OpenGL rendering errors after the
  reimport. The Level continues to resolve the same logical Model paths; only
  the immutable content-addressed products changed.
- This acceptance note is superseded by the subsequent review correction
  below; AP1.3 remains pending until the serialization correctness issue is
  fixed and the affected validation is repeated.

### AP1 review correction

- AP1.2 was returned to pending acceptance because its exit gate was checked
  off before the Sponza closure measurement and final visual evidence were
  complete.
- Fixed BC4 opacity cooking to source the R channel, matching the documented
  native texture contract, and fixed the BC4 palette construction so all six
  interpolated entries are retained in the 8-alpha mode. Added a regression
  test covering both the source channel and the final interpolated entry.
- Fixed Model V3 position quantization to reject a vertex outside the stored
  model bounds instead of silently clamping it. Added a regression test for
  the invalid geometry case.
- AP1.3 remains pending until these fixes are validated and the Sponza V3
  products are rechecked for size, decode time, and Vulkan/OpenGL correctness.

### AP1.2/AP1.3 final acceptance

- User directed final acceptance of AP1.2 and AP1.3 after the review fixes.
