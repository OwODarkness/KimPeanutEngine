# AP1.5a — Loose-product scheduling baseline

Date: 2026-09-14
Status: landed; AP1.5b remains open

## Decision

AP1.4 package/TOC work is deferred until KimPeanutEngine has a
publish/shipping consumer. Editor and development startup continue to use the
loose products under `asset/.archive`. This keeps package storage out of the
current edit loop while allowing scheduling improvements to land against the
real path.

## Implementation

- Added `AssetLoaderConcurrency` to `AssetTypeDescriptor`.
- Marked native Texture, Shader, ShaderProgram, Material, and Level readers as
  parallel-safe; Model, Audio, and the default for custom types remain
  serialized.
- Added four bounded loader slots for parallel callbacks. The existing mutex
  remains the gate for serialized callbacks.
- Launched independent declared dependencies concurrently and appended their
  results in declaration order before parent publication.
- Added ordinary root in-flight result sharing. Observed session roots retain
  separate operation records by design.
- Added a custom parallel dependency regression and preserved the serialized
  custom-loader regression.

## Remaining risk

The four slots bound loader callback/decode concurrency, but AP1.5b still needs
an explicit transient-memory budget and a worker scheduler that avoids creating
one `std::async` thread per dependency branch. Low-mip readiness and GPU-safe
background mip upload are not implemented because the current Render and
Graphics contracts require a complete mip chain.
