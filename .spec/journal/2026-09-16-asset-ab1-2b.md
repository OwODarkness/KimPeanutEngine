# AB1.2b — Asset Browser Visual Tile Presentation

## Objective

Close the icon-first Asset Browser presentation milestone on top of the
AB1.2a imported-content snapshot boundary.

## Implemented

- The browser opens in `CompactTiles`; switching between Tiles and Table changes
  only presentation state and never recaptures the Asset catalog.
- Tile rows use stable catalog keys for ImGui IDs and selection, an adaptive
  fixed-width grid, and `ImGuiListClipper` so rendering scales with visible
  tile rows.
- Built-in model, material, texture, and level rows use configured raster icons
  from `resouce/icon/setting.json`, with deterministic primitive/document
  fallbacks for missing or custom mappings.
- The tile surface intentionally shows only the icon and readable name. Type,
  state, size, path, and diagnostics remain in Table mode and the details pane.
- Content folders remain available beside the tile grid, and the folder/content
  splitter preserves both child regions on the same ImGui row.

## Validation

- `cmake --build build --config Debug --target EditorUILib` — passed.
- `AssetBrowserModelTest` — 21/21 passed, including the Compact Tiles default
  and presentation-state regression.
- `git diff --check` — passed; Git only reported existing line-ending warnings.

## Runtime evidence

The test-level Vulkan editor launch and `engine_window` capture succeeded, but
the persisted workspace opened the Log tab rather than the Asset Browser tab.
The repository command transport has no mouse/tab activation command, and the
installed Windows UI helper failed with `Trusted RPC service is not configured:
sky`, so a fresh capture with the Asset Browser tab active could not be
automated in this environment. The component was compile-validated and the
model contract was unit-tested; manual activation of the Asset Browser remains
the final visual check.

Sponza was not used.
