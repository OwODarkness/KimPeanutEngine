## R4.7.11 — Inline ray-query visibility

Added `RayQueryVisibility = 6` and the `ray_query_visibility` Runtime probe.
`TraceVisibility` uses an opaque terminate-on-first-hit `rayQueryEXT` only in
that mode. The previous scalar-payload `traceRayEXT` route remains the default
Beauty behavior. The mode is represented in the path-history signature, so a
mode change starts a distinct accumulation.

Three windows per mode completed. Beauty versus ray-query means were 23.188 vs
21.940 ms PT GPU p50, and 27.903 vs 26.636 ms total GPU p50 (5.38% and 4.54%
lower). Mean total GPU p95 was 29.340 vs 27.727 ms. Both modes used 4 samples
per dispatch and 8 bounces. Captures at 1728 and 1700 accumulated samples were
visually similar; RGB8 MAE was 7.18/255. This is near-matched, not exact
equal-sample evidence. Raw data: `save/diagnostics/r471-query-ab-window-*.json`,
`r471-query-ab-window-summary.csv` and
`r471-query-ab-gpu-telemetry.csv`.

The Sponza result supports keeping the query path as an opt-in experiment.
Initially the Debug validation did not select the query probe mode; no Cornell,
non-query device, reordered/material-overridden scene or extended lifetime
comparison was performed. The default remains `traceRayEXT` visibility.

## R4.7.12 — Ray-cone base-color filtering

Added `RayConeFiltering = 7` and the `ray_cone_filtering` Runtime mode. Raygen
estimates angular spread from adjacent pixel directions. Closest-hit propagates
cone width using hit distance, estimates triangle world/UV area, and computes
an explicit base-color mip from texture dimensions. Other modes keep existing
sampling; metallic/roughness channels remain LOD 0.

The initial Beauty/ray-cone windows showed mean PT p50 22.554/23.168 ms, PT p95
24.109/24.573 ms, total GPU p50 27.256/27.878 ms and total p95
28.615/29.171 ms. Review then found the closest-hit shader was not assigning
the computed cone width back to the hit payload, so this first measurement is
superseded. Camera motion, texture detail, transformed thin UV triangles,
nonuniform/mirrored transforms, all-channel mip consistency and equal-wall-time
error were not evaluated.

## R4.7.13 — Guided one-SPP preview

Added `LowSppPreview = 8` and the `low_spp_preview` command mode. It selects one
sample per dispatch, preserves progressive history and eight continuation
bounces, and enables a 3x3 normal/view-depth edge-aware spatial reconstruction
in tone mapping. Raygen writes a primary world-normal/view-distance guide to a
new RGBA16F target. `RenderPassResource::PathTraceGuide` is imported into the
graph with path-trace storage-write and tone-map sampled-read uses. The target
is retained by DeferredRenderer, resized with history, and destroyed after
binding retirement/backend idle. Graphics owns the native image and barriers.

- Visible Debug Vulkan Sponza path tracing was active; the Beauty and preview
  `capture.screenshot` requests exported successfully. The latest Debug log
  contains no Vulkan validation errors or new `[Error]` entries.
- Screenshots: `save/screenshots/validation/r471-debug-guide-preview.png` and
  `r471-debug-low-spp-guide.png`.

Final RelWithDebInfo was rebuilt and relaunched visibly. Three windows per mode

This is a useful optional interactive preview, not a full denoiser. It has no

## R4.7.13 accumulated Beauty denoising follow-up — 2026-09-27

- Added the opt-in `beauty_denoise` path-trace mode. It preserves the normal
  four-SPP progressive Beauty estimator and leaves raw `beauty` unchanged.
- Ray generation merges centered luminance sample variance across dispatches
  and stores normalized sample variance in history alpha. This avoids a
  monotonically growing M2 value in the existing RGBA16F history target.
- Tone mapping applies one 5x5 à-trous spatial level at stride two, guided by
  variance, primary world normal, relative view depth and luminance difference.
  Render continues to own denoising policy and history; no new GPU target or
  RHI ownership was introduced.
- This is an SVGF-inspired spatial pass. Motion reprojection, disocclusion,
  multilevel filtering and diffuse/specular signals are absent; OIDN/NRD were
  not integrated because their runtime dependency or richer guide contracts
  exceed this first static-view experiment.
- Debug `KimPeanutEngine` build and direct `glslangValidator` compilation for
  the raygen and tone-map shaders passed. A Debug Vulkan run rendered the mode
  at 4 SPP/dispatch and roughly 5,000 samples; its log had no validation/VUID or
  `VK_ERROR` entry. The alpha encoding was then normalized to sample variance;
  both shaders recompiled and the final RelWithDebInfo executable rendered
  Sponza in the new mode.
- Runtime profile snapshot: 6,732 path samples at 4 SPP/dispatch, 28.89 ms
  total-GPU p50 and 0.085 ms tone-map p50. These are diagnostic current-mode
  values, not an isolated denoiser A/B. Denoised screenshot:
  `save/screenshots/validation/r478-relwithdebinfo-beauty-denoise-6k.png`.
  Raw Beauty screenshot at 4,136 samples:
  `save/screenshots/validation/r478-debug-beauty-raw-4k.png`.
- Visual review found reduced grain on dark stone/floor areas while preserving
  broad folds and tile layout. Counts/configurations are not exactly matched,
  and no numeric image-error metric was produced. Equal-count comparison,
  motion/edit, Cornell/another scene and extended history/resize validation
  remain open; keep this mode opt-in.
- Final raster-fallback change gates the filter on active path tracing. After
  rebuilding RelWithDebInfo and relaunching Sponza, same-configuration captures
  reached 5,228 raw Beauty samples and 6,148 denoised samples. The final
  denoised profile reports 27.56 ms total-GPU p50 and 0.085 ms tone-map p50.
  The second comparison remains near-matched rather than exact-count; captures
  are `save/screenshots/validation/r478-relwithdebinfo-beauty-raw-5k.png` and
  `save/screenshots/validation/r478-relwithdebinfo-beauty-denoise-6k-1.png`.
  The final RelWithDebInfo app is left running with `beauty_denoise` selected.
