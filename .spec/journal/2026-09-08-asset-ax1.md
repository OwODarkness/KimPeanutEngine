# Asset AX1.0 Baseline Characterization — 2026-09-08

- Status: complete
- Date: 2026-09-08
- Parent TODO: [Asset extensibility](../../docs/asset/TODO.md)
- Plan: [AX1 — Extensible Asset Types and Polymorphic Payloads](../../docs/asset/.plan/AX1.md)

## What was done

- Added focused baseline tests for all current built-in `AssetType` numeric
  values and one representative packed `AssetID` golden value.
- Pinned current built-in suffix routing, including the intentional rejection of
  compound `model3.json` as a runtime type.
- Pinned typed payload access, wrong-type rejection, and payload lifetime after
  the `Asset` wrapper is unregistered.
- Pinned dependency-protected unload and invalid owned-child rollback.
- Recorded the current loader/state lock and observation phase contracts in the
  AX1 plan. Existing observation tests remain the evidence for recursive,
  asynchronous, concurrent, cache-hit, and failure paths.
- Inventoried current top-level `AssetPayload` variant consumers: validity and
  typed access in `asset.h`; decoded-size measurement in `asset_manager.cpp`;
  model payload probing in `assimp_model_loader.cpp`; and direct loader/test
  access in the Asset unit tests. The Render-owned `PreparedRenderPayload` and
  other gameplay/render variants are separate contracts and are not part of
  AX1's top-level Asset payload migration.

## What changed

- Added `engine/test/unit/asset/asset_contract_baseline_test.cpp`.
- Added the test source to `AssetUnitTest` in
  `engine/test/unit/asset/CMakeLists.txt`.
- Marked AX1.0 as landed in the Asset plan and roadmap. AX1.1 and later remain

Architecture or ownership impact: none. This stage only characterizes the
existing closed enum, variant payload, hard-coded routing, and AssetManager
transaction behavior before migration.

## Remaining risks and unverified areas

- The current `std::variant` payload and hard-coded loader dispatch remain in
  production code by design.
- AX1.0 does not prove the future registry or `IAssetPayload` API; those are
  AX1.1–AX1.4 work.
- Other AssetImport/archive suites were not part of AX1.0 because this stage
  characterizes runtime Asset identity/payload/transaction behavior only.

## Remaining work

- AX1.1: migrate the top-level payload to `std::shared_ptr<IAssetPayload>`.
- AX1.2: add generic type/loader registration and adapt built-in loaders.
- AX1.3: add the independent offline importer registry.
- AX1.4: harden the extension path and hand it to Live2D.

## Documentation and follow-up

- Keep this baseline test set unchanged while AX1.1–AX1.4 land so compatibility
  regressions remain visible.
- Update this journal only with dated corrections if the characterized baseline
  is later found to be inaccurate.
