# Live2D L2D8.1 — Deterministic emotion resolver

- Status: complete
- Date: 2026-09-16
- Plan: [L2D8](../../docs/live2d/.plan/L2D8.md) · Roadmap:
  [TODO](../../docs/live2d/TODO.md)

## Objective

Translate a semantic `Live2DBehaviorIntent` into an authored motion/expression
binding without putting selection policy in shared Product data or coupling the
policy layer to Cubism, Render, or the viewer.

## Implementation

- Added `Live2DEmotionResolver`, an instance-local state machine built on the
  immutable L2D8.0 policy.
- Added explicit request controls for priority, force replacement, retrigger,
  and authored-fade versus immediate blending.
- Unknown intents resolve to the policy's idle fallback. Lower-priority
  transitions are rejected without mutating resolver state; force requests may
  replace the active state.
- Same-state requests are ignored by default and can be retriggered explicitly.
- Resolutions return copied authored motion/expression references, transition
  reason, previous state, priority, blend mode, fallback usage, and a monotonic
  per-instance transition sequence. L2D6 remains responsible for executing the
  returned motion/expression commands.
- Kept the resolver in the SDK-free `Live2DProduct` target so it is usable in
  SDK-off builds and does not add an Asset/Render/Graphics semantic branch.

- `git diff --check` — passed; only existing Git line-ending notices remain.

## Follow-up

L2D8.1 intentionally leaves observation storage to L2D8.2 and viewer rendering
to L2D8.3. The resolver remains the execution-policy boundary; L2D6 still
executes the copied authored references.
