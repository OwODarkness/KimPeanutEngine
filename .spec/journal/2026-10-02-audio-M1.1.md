# Audio M1.1 — offline import contract

## Outcome

Implemented the first M1 gate: AssetImport now exposes a typed Audio provider
and AssetTool `import`/`reimport` accepts an audio source plus an optional
explicit subtitle path and language. The importer validates Asset-root-relative
paths, decodes in fixed 2,048-frame blocks for duration and waveform analysis,
and publishes an immutable versioned `.audio` product containing the original
compressed source bytes, normalized 48 kHz stereo metadata, 384 min/max
waveform buckets, and optional frame-timed subtitles. Runtime playback was not
changed by M1.1.

The container serializer is deterministic and little-endian. Its parser checks
the digest, required chunks, bounds, overlaps, canonical spans, metadata,
waveform values, UTF-8, cue ordering, and cue ranges before allocating payload
copies. Invalid explicit subtitle data fails before product publication.
Importer CLI paths are converted from Windows Unicode arguments to UTF-8, so
non-ASCII source and subtitle names are supported.

SRT and WebVTT remain supported. The supplied music folder uses LRC, so M1.1
also accepts LRC. Recognized metadata tags are skipped; timestamp offsets are
applied; multiple translations sharing a timestamp remain overlapping cues;
each line ends at the next distinct timestamp. The M1 plan records this
extension.

## Remaining M1 work

M1.2 still owns Audio archive product identity, dependency/options recording,
no-op reimport, status, integrity/catalog handling, staging, and atomic archive
publication. M1.3 still owns the runtime native loader and seekable bounded
decode worker; the current raw-file playback path still decodes the whole track
to float PCM. M1.4 still migrates the player library and subtitle display.

The M1.1 importer holds the bounded encoded source and serialized product while
publishing, subject to the plan's 512 MiB source and product caps. Decoded
analysis itself uses fixed-size scratch memory and does not allocate a
duration-sized PCM buffer.
