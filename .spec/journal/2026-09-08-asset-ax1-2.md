# Asset AX1.2 Journal — Generic Type and Loader Registry

- Date: 2026-09-08
- Status: complete
- Plan: [AX1](../../docs/asset/.plan/AX1.md)
- Scope: move runtime Asset type/suffix dispatch behind an Asset-owned registry,
  preserve built-in IDs, and allow module-owned custom types without Asset
  source branches.

## Changes

- Added `AssetTypeDescriptor` and `AssetTypeRegistry` with normalized suffix
  lookup, type/name/suffix collision checks, explicit registration, and a
  one-way seal.
- Preserved built-in `AssetType` values and `AssetID` packing. Reserved
  `0x1000..0xEFFF` for module-owned custom type values; reserved values outside
  the exact built-in set and custom range are rejected.
- Added `AssetManager::RegisterAssetType`. Built-in model, texture, audio,
  shader, shader-program, material, and level loaders are registered through
  the same descriptor callback contract.
- Runtime suffix resolution now seals the registry on the first load and calls
  the selected descriptor callback while retaining the existing serialized
  loader window and dependency/cache transaction.
- Registration validates the descriptor, `AssetRegisterInfo::type`,
  `AssetID::type`, and `IAssetPayload::GetAssetType()` before cache publication.
- Added tests for custom-range registration, suffix collision, late
  registration rejection, custom loading through the ordinary Asset cache, and
  built-in compatibility.
- No Live2D type, suffix, include, or loader branch was added to Asset core.

## Ownership and synchronization impact

`AssetManager` owns the registry and its descriptor callbacks. Registration is
available only before the first load; sealing gives concurrent loads an
immutable descriptor/index view. Loader callbacks execute after registry/state
lookup and under the existing `load_mutex_`, but never while the registry or
Asset state mutex is held. Asset identity, dependency resolution, rollback,
observation, and unload remain owned by `AssetManager`.

## Follow-up

AX1.3 should define the independent database-free offline importer/provider
registry. Live2D should consume `RegisterAssetType` only after its native
payload/loader/importer design is ready; Asset core must remain feature-neutral.
