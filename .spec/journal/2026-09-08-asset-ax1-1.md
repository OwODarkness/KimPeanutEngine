# Asset AX1.1 Journal — Polymorphic Payload Core

- Date: 2026-09-08
- Status: complete
- Plan: [AX1](../../docs/asset/.plan/AX1.md)
- Scope: replace the top-level built-in resource variant with a polymorphic
  shared payload while preserving built-in identity, ownership, dependency,
  and cache behavior.

## Changes

- Added `engine/runtime/asset/asset_payload.h` with `IAssetPayload` and the
  `std::shared_ptr<IAssetPayload>` `AssetPayload` alias.
- Updated `Asset::IsValid` and `Asset::GetResource<T>()` to use shared-pointer
  null checks and `std::dynamic_pointer_cast<T>`.
- Made all built-in CPU resource payloads implement `GetAssetType()` without
  changing their existing `AssetType` values.
- Migrated AssetManager decoded-size accounting, native model loading, tests,
  and the graphics example away from top-level payload-variant access.
- Added a contract test proving an external concrete payload can satisfy the
  polymorphic boundary and that null payloads remain invalid.
- Kept the render-owned `PreparedRenderPayload` variant unchanged; it is a
  closed render preparation record, not the Asset module's top-level payload.

## Ownership impact

`AssetManager` still owns the `Asset` wrapper and cache identity. The wrapper
now owns one polymorphic shared payload, while typed callers retain independent
shared ownership after wrapper unload. Asset type values and loader dispatch
remain built-in-only; the generic registry and reserved custom type range are
explicitly deferred to AX1.2.

- `ctest --test-dir build -C Debug --output-on-failure` — 406/410 passed. Four

  and isolated reruns; their diagnostics concern default render texture
  preparation and actor/environment factory behavior, not Asset payload casts.

The first non-escalated build attempts were blocked by access to the Visual
Studio Windows SDK cache under the user profile. The successful validation used
the approved elevated build/test invocation; no source failure occurred from
that environment issue.

## Follow-up

AX1.2 must introduce the Asset-owned generic type/loader registry, define when
an additional type belongs in the built-in common set, and reserve a stable
custom type range for feature modules. AX1.3 remains the offline importer
registry stage; Live2D remains a consumer and does not add Live2D branches to
Asset core.
