# MODE1.3 — Standalone Live2D viewer

Date: 2026-09-11

## Objective

Run Hiyori through a standalone `Live2DViewerHost` without constructing the
traditional scene composition, while preserving the existing scene/deferred
renderer path.

## Landed changes

- Made `RuntimeContext` scene services lazy. Scene mode initializes them through
  `Scene3DHost`; viewer mode leaves them unconstructed.
- Added `Live2DViewerHost` in the Live2D module. It owns the viewer window,
  backend, frame contexts, Cubism lifetime, model asset, and renderer.
- Changed viewer startup to initialize the host on the render thread and skip
  editor, startup-level, Gameplay, RenderWorld, and DeferredRenderer work.
- Added an API-neutral presentation pass to generic render submissions. The
  OpenGL recorder targets the default framebuffer; Vulkan uses the existing
  backend-owned swapchain bridge.
- Configured standalone Live2D output to use the presentation pass while
  retaining the offscreen mask atlas path.
- Kept `Live2DModule` and its scene extension compiled for migration, but the
  composition root no longer registers it for viewer mode.

## Validation

- `cmake --build build --config Debug --target KimPeanutEngine` — passed.
- Focused `RuntimeLaunchOptionsTest` — 9/9 passed.
- Focused `RenderSystemTest` — 21/21 passed.
- Focused `RuntimeStartupTest` — 14/14 passed.
- Standalone OpenGL launch with `--mode live2d-viewer` — window created,
  Hiyori product loaded, Cubism initialized, and viewer reached the ready
  state without frame submission errors during the smoke interval.

## Remaining validation

MODE1.4 should add explicit Vulkan viewer capture/resize evidence and a
negative construction assertion for scene services. Viewer capture is not yet
exposed through the Runtime command transport because viewer mode intentionally
does not create the scene command registry.
