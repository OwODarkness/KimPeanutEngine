# L2D8.3 — viewer validation

Date: 2026-09-16
Status: complete

## Objective

Close L2D8 by making the semantic emotion state machine inspectable in the
viewer and by proving a deterministic fallback, transition, interruption, and
recovery sequence without moving UI or Cubism types into Runtime.

## Implementation

- Added `Live2DEmotionReplay`, an SDK-free deterministic replay over Product V2
  motion/expression references. It copies snapshots and bounded transition
  records into a result value and compares two identical runs before reporting
  pass/deterministic status.
- Added an Emotion tab to the Live2D viewer control panel. It renders the copied
  state sequence, current terminal state, transition reason, and bounded history;
  it does not retain a resolver or model pointer.
- Extended `live2d.model_report` with replay availability, pass/determinism,
  current semantic state, sequence, history size, and diagnostic text.
- Kept the replay in the Live2D product/runtime boundary. It validates policy
  and observability; authored Cubism timing and GPU execution remain the L2D6
  renderer boundary.

## Validation

- `ctest --test-dir build -C Debug -R 'Live2D' --output-on-failure` — **67/67**.
- SDK-off `Live2DEmotionPolicyTest` build and direct execution — **11/11**;
  `Live2DProduct` is intentionally not generated in SDK-off configuration.
- `cmake --build build --config Debug --target KimPeanutEngine --parallel 1` —
  **pass**.
- Live viewer command transport on OpenGL and Vulkan — `commands.list` exposed
  `live2d.model_report`; the report returned
  `behavior_replay_available=true`, `behavior_replay_passed=true`,
  `behavior_replay_deterministic=true`, `behavior_history_count=3`, and
  `behavior_state=neutral_recovery` on both backends.
- `capture.screenshot` exported validation PNGs for both backends under
  `save/screenshots/validation/` (`l2d8-3-opengl-1.png` and
  `l2d8-3-vulkan.png`); the OpenGL capture was inspected and showed the full
  model with eyes visible.

## Follow-up correction

The viewer sampler previously clamped `max_lod` to zero and selected the
nearest mip level, forcing base-level sampling during model minification. The
Live2D sampler now uses explicit linear min/mag filtering, linear mip
interpolation, and a bounded mip range. The single-level mask atlas naturally
clamps to level zero. OpenGL and Vulkan startup captures both exit cleanly after
the correction.

## Viewer preset controls

The diagnostic graph was simplified into four direct viewer buttons: Normal,
Sad, Angry, and Happy. Each button clears the previous expression, starts the
closest authored motion, and applies known Mao expression clips when present;
models such as Hiyori, which have no expression clips, still receive body
language through their authored motion groups.

The bubble uses built-in ASCII dot glyphs, so clicking a preset does not require
the optional panel glyph-product command-line inputs. It pops in, remains visible
for 2.5 seconds, and then disables its draw while keeping the selected emotion
active.

## Follow-up

L2D9 remains the next Live2D stage. Speech bubbles remain presentation-only;
audio/TTS and lip-sync are intentionally outside this stage.
