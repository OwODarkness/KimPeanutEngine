# AP1.5b — Low-mip residency slice

Date: 2026-09-14
Status: implemented; range-aware I/O and in-place upload remain open

## Decision

Keep the native texture product complete and immutable. Startup may publish a
tail-mip `TextureData` view, but the product is still hash-verified as a whole
and a background read produces the canonical full-resolution view. This keeps
Asset identity and the loose development path stable while giving Render an
explicit residency transition.

## Implementation

- Added transient `first_resident_mip` metadata to `TextureData`; it is not
  serialized.
- Extended native texture deserialization to validate every directory entry
  while copying only a selected mip tail.
- Added a Runtime-configured six-level initial policy. RGBA16F textures remain
  complete because the current environment/IBL preparation consumes them.
- Added a two-slot background full-resolution decode gate to
  `NativeTextureLoader` and an immutable future on `TextureResource`.
- Added Render polling, residency-aware texture cache keys, material rebinding,
  and frame-delayed texture retirement for both backend implementations.

## Remaining risk

The current loose loader still reads and hashes the complete file before the
tail is copied, so AP1.5b reduces decoded/uploaded startup payload but not all
disk I/O. The background path creates full CPU data and re-reads the product;
AP1.5 should later add range-aware reads or a package backend before claiming
the final startup budget.

## Startup contention correction

The first implementation started the background full-resolution future inside
the Asset loader. That caused every partial texture to read and hash its full
product again while startup dependencies were still loading. On the local
Sponza measurement this reported 44.951 seconds. The loader now publishes a
lazy callback instead; Render starts it after the initial material bindings are
committed. The same measurement then reported 34.649 seconds, with the same
195 load operations and 126 registered assets. This removes startup contention,
but does not yet provide range-aware disk I/O.

## AP1.5c range-aware initial read

The loose native texture loader now reads the fixed header and complete mip
directory first, validates the product size and directory layout, then reads
only the contiguous payload range beginning at the selected resident mip.
Initial deserialization validates the selected range and native dimensions but
does not claim full-product integrity. The existing lazy full-resolution
future remains responsible for the complete read, content hash, archive-path
verification, and full-resolution promotion after the initial scene view is
available.

`TextureImportTest.NativeTextureRangeDecodeUsesOnlyResidentPayload` covers
decoding from header/directory plus a tail range. The native format and AssetID
identity are unchanged.
