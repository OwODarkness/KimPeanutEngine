# AP1.5b — Low-mip residency slice

Date: 2026-09-14
Status: implemented; range-aware I/O and in-place upload remain open

## Decision

Keep the native texture product complete and immutable. Startup may publish a
tail-mip `TextureData` view, but the product is still hash-verified as a whole
and a background read produces the canonical full-resolution view. This keeps
Asset identity and the loose development path stable while giving Render an
explicit residency transition.

## Implementation

- Added transient `first_resident_mip` metadata to `TextureData`; it is not
  serialized.
- Extended native texture deserialization to validate every directory entry
  while copying only a selected mip tail.
- Added a Runtime-configured six-level initial policy. RGBA16F textures remain
  complete because the current environment/IBL preparation consumes them.
- Added a two-slot background full-resolution decode gate to
  `NativeTextureLoader` and an immutable future on `TextureResource`.
- Added Render polling, residency-aware texture cache keys, material rebinding,
  and frame-delayed texture retirement for both backend implementations.

## Validation

- `cmake --build build --config Debug --target AssetExtensionHardeningTest KimPeanutEngine -j 1`
  passed after the implementation; the first combined build exposed and then
  corrected only the constness of the prepared texture pointer.
- `TextureImportTest` passes 11/11, including the tail-mip commit and invalid
  initial-level regression.
- The rebuilt Runtime starts the checked-in `level/performance_profile.level`
  through Vulkan, reports 23 startup operations, and exports
  `save/screenshots/validation/ap1-5b-test-level-vulkan.png`. The capture shows
  the bunny scene and editor UI; this small fixture does not exercise a texture
  with more than six mips, so it validates startup safety rather than a visible
  low-to-full promotion.

## Remaining risk

The current loose loader still reads and hashes the complete file before the
tail is copied, so AP1.5b reduces decoded/uploaded startup payload but not all
disk I/O. The background path creates full CPU data and re-reads the product;
AP1.5 should later add range-aware reads or a package backend before claiming
the final startup budget.
