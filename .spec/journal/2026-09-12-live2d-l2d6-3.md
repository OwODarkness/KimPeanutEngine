# L2D6.3 implementation journal — 2026-09-12

## Objective

Implement the SDK-free Live2D playback control surface on top of the instance-local
Cubism clips/managers created by L2D6.2, without changing Render, Graphics, Asset,
Editor, or the existing static snapshot path.

## Changed

- Added public playback values and controls to `Live2DModelInstance`:
  `Live2DPlaybackToken`, start/stop modes, event kinds, update results,
  `PlayMotion`, `StopMotion`, `StopAllMotions`, `SetExpression`,
  `ClearExpression`, and `AdvancePlayback`.
- Added instance-local token sequencing, motion queue records, bounded pending and
  callback event storage, fixed pending parameter-write storage, expression state,
  and caller-supplied playback time.
- Installed a noexcept Cubism event adapter. Authored user events are copied into
  owned values with an invalid public token; lifecycle events are inferred from
  queue-entry disappearance and carry the engine token.
- Implemented the canonical update order:
  `LoadParameters -> pending writes -> motion -> SaveParameters -> expression ->
  CubismModel::Update`.
- Kept legacy `Update()` as the no-playback path and made it reject active
  playback so returned events cannot be silently discarded.

## Validation

- `cmake --build build --config RelWithDebInfo --target Live2DCoreTest --parallel 1`
  passed.
- `build/engine/test/unit/live2d/RelWithDebInfo/Live2DCoreTest.exe
  --gtest_color=no --gtest_filter=Live2DAssetTest.LoadsImportedProductThroughAssetManagerDependencies`
  passed. The test starts Hiyori's `Idle/0`, advances caller time, observes one
  token-associated completion event, rejects the stale token, and verifies the
  legacy update path after completion.
- The pre-change 19-test Live2D core suite passed before the new focused test was
  added.
- `git diff --check` reports no whitespace errors; Git's line-ending warnings
  concern existing Windows working-tree normalization only.

## Viewer completion

- The standalone `live2d-viewer` now selects Hiyori's authored `Idle/0` motion
  after renderer initialization. `Live2DRenderer::Record` advances the instance
  with the frame delta and restarts the selected clip after a natural completion,
  so the preview does not freeze after one loop. Products without that motion keep
  the existing static fallback and log the reason.
- The default local Hiyori product was regenerated with the V2-aware asset tool;
  the previous V1 product is preserved at `save/live2d-backup/hiyori-v1.live2d`.
  This product refresh is local generated content under the ignored `asset/` tree.
- Added a regression assertion that Hiyori `Idle/0` changes at least one runtime
  parameter after a zero-delta initialization update and a 0.5 second advance.
- The full 19-test Live2D suite passed. The standalone viewer exited successfully
  with startup captures on both OpenGL and Vulkan, and both runs reached Cubism
  disposal without a preview-motion warning.
## Rendering correction

- Review found that `Live2DDrawConstants` placed the GLSL `vec3 padding` at the
  wrong C++ offset. Masked draw constants therefore uploaded
  `model_to_atlas_sample` 12 bytes too early, so mask UVs were invalid; this
  explained missing eyes and malformed masked layers. Added an explicit std140
  gap, a 128-byte draw block, and compile-time offset checks.
- After the correction, the full 19-test Live2D suite passed and the default
  Hiyori viewer exited successfully with captures on OpenGL and Vulkan.
## Remaining gate

L2D6.3 still needs the full deterministic matrix before its checkbox can close:
synthetic parameter-changing motions, expression Add/Multiply/Overwrite numeric
goldens, replacement/cancellation fade cases, authored user-event fixtures,
capacity/exhaustion tests, invalid-delta atomicity, and SDK-off validation. Those
are hardening evidence, not a reason to add a second playback path or change
Render/Graphics ownership.
## Pose correction

- Runtime instances now load the authored Cubism Pose chunk and apply pose fading after motion/expression evaluation, so mutually exclusive arm variants do not render simultaneously.
- The Cubism Pose implementation is linked into the existing framework target; no deferred/PBR render path is changed.
- Hiyori pose visibility regression coverage passed with the full 19-test Live2D suite and OpenGL/Vulkan viewer captures.
