## Operation, candidates and chosen placement

Operation and acceptance: specify the neutral feature/UI/backend boundary,
actual independent build/link tests, recording semantics, production pilot,
legacy delegation and runtime gates before implementing a large reconstruction.

Candidates inspected: EditorPanelContent and window host lifecycle; EditorUI
initialization/frame/config/loading paths; public renderer/WSI types; GL/Vulkan
adapters/RHI packet/cache/retirement; Graphics presentation bridge and expiring
RenderTargetView; five InitializeViewer hosts; Settings scalar/enum helper;
Window/Graphics/Core/ImageIO target relationships; ED6.0 source/owner inventory.

Decision: UIWidgets owns typed UI contracts, UIPresentation owns a neutral
session, UIBackendImGui owns all toolkit implementation and rendering adaptation.
Keep domain behavior/lifetime with existing owners. Quarantine legacy callbacks
as a one-way compatibility consumer. Use a real Settings fields subview to
prove the interface without pretending all Settings ownership has migrated.

AI preparation: stable scoped IDs, semantic descriptors and typed results plus
an optional bounded C++ frame observation/recording interface. Separate actual
layout from simulated geometry and domain source state. No JSON schema, agent
endpoint, external action protocol or retained UI editor is implemented/planned
inside this stage's scope.

## Typed control API follow-up — 2026-11-10

The user identified that a single role-based `Control()` call was too low-level
for feature views and supplied a desired typed declaration style. They also
reviewed the extension boundary: shared frame/ID/backend rules belong in
UiContext; control-specific protocol rules belong with standard controls; complex
views should use bounded canvas/layout/input capabilities rather than growing
UiValue or introducing a plugin registry.

- Added stable-string-ID Button, Checkbox, Selectable, Combo, NumericInput and
  TextInput methods. Checkbox/Selectable/Combo/numeric/text return typed results;
  e.g. `draft.enabled = edit.value` remains a bool assignment. The API hashes
  explicit ID strings, not labels, to backend IDs and checks duplicate/hash
  collisions within a frame.
- Retained public generic `Control()` as a validated submission path. Moved
  standard-control input/result rules to `ui_control_validation.cpp`; UiContext
  retains common frame/thread/identity checks and backend dispatch. Result rules
  cover action declaration, disabled controls, typed values, numeric ranges,
  cancellation semantics and Combo membership on selection.
- Validation runs before ID registration. An invalid numeric value can be
  corrected and submitted with the same ID in the same frame. A malformed
  backend Combo result aborts the incomplete frame.
- Extended the ImGui and recording adapters for Selectable/typed control
  semantics. Migrated the Settings fields pilot to the typed methods.
- Updated `engine/editor/README.md` and ED6.2 contract text with the call style
  and extension boundary. No general widget plugin system or unbounded value
  union was added.
- Debug target build succeeded. Targeted CTest run passed 19/19 cases covering
  UI contracts, Settings fields and EditorPanelContent; direct
  `EditorUILifecycleTest.exe` passed 6/6. This does not close the outstanding
  independent smoke, host/backend matrix, graphics and performance gates listed
  above.

## Audio Player workspace composition follow-up — 2026-11-11

The user supplied the previous Audio Player screenshot and clarified that all
major regions should remain visible together. The initial neutral-API migration
had collapsed them into one page-switched window, losing the Library,
Now Playing, Info, Playlists, Queue/Output Log and Spectrum workbench layout.

- Operation and acceptance: compose independent Audio Player windows in the
  feature-owned editor view, using the existing neutral `UiContext::Window`
  containers and filling the host viewport without a page selector or legacy
  component/window hosts.
- Candidates inspected: `UiContext::Window` and the ImGui inline backend's
  first-use geometry; `EditorUI::BeginDraw` as the current host-frame owner;
  `AudioPlayerEditor::RenderWorkspace` and its existing feature-owned pane
  renderers. The UI backend already accepts multiple sequential root windows;
  only the content callback lacked viewport information.
- Placement: expose the frame's neutral `UiViewportInfo` through `UiContext`,
  populate it in `EditorUI` from its host viewport, and calculate initial pane
  rectangles inside Audio Player. `EditorUI` retains native ImGui/viewport
  ownership; Audio continues to own audio presentation and does not add an
  Editor module dependency beyond its current UI viewer target.
- Composition: Library and Playlists at left; Now Playing above Queue and
  Output Log in the center; Info above Spectrum at right. Existing
  feature-specific render methods are reused without duplicating controls.
- Validation: `cmake --build build --config Debug --target KimPeanutEngine -- /m:1`
  passed after the composition change and again after adding viewport-change
  relayout. The visible Vulkan Audio Player launched on the Default desktop.
  At 1280x720 the seven windows appeared in their proportional grid; after
  maximizing, the geometry was recomputed to fill the larger viewport, leaving
  no blank right/bottom region. The user can still move and resize panes after
  the host viewport settles. The screen check had an empty queue and no selected
  track, so playback waveform/subtitle and nonzero spectrum appearance remain
  unverified. No tests were run.

## Shared 2D Plot follow-up — 2026-11-11

- Operation and acceptance: provide a neutral 2D Plot capability over Canvas
  usable by both Audio and Signal Lab, with axes, line/bar/point series, explicit
  linear/log scales, module-owned style tokens and pointer-to-data values.
- Candidates inspected: `UiContext::Canvas` and its recording/ImGui backends;
  Audio's private Canvas primitive builder and spectrum renderer; Signal Lab's
  scope/spectrum draw-list renderers and host callback. Placement evidence was
  recorded by `tools/agent/placement.ps1` for the Editor UI API and both feature
  editor directories.
- Placement: `UIWidgets::Plot` converts series/axes to neutral Canvas primitives
  and delegates pointer input through the existing backend. Audio keeps radial
  scope, waveform semantics and its palette. Signal Lab supplies its own palette;
  its scope/spectrum callbacks receive `UiContext`. The rest of the legacy Signal
  Lab editor is not migrated by this focused change.
- Validation: Debug `KimPeanutEngine` build passed. The visible Vulkan Signal Lab
  showed scope and spectrum with vertical axes increasing bottom-to-top; the
  visible Audio Player showed its logarithmic frequency ticks and module-owned
  colors. No tests were run. Audio playback waveform data, log-axis pointer
  readout, overlay/pair charts and the full Signal Lab ImGui boundary remain
  unverified/follow-up.
