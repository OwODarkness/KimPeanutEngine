# L2D6.2 instance-local clip library — 2026-09-12

## Investigation

Product V2 already carried immutable motion and expression bytes, but runtime
instances only constructed the MOC/model/static-data closure. The pinned
Cubism R5 framework stores mutable fade, callback, queue, and event state on
parsed motion objects, so those objects cannot be shared through
Live2DModelResource.

## Implementation

- Linked the pinned Cubism R5 motion, expression, queue, and manager sources
  into the Live2D framework runtime target.
- Added instance-local CubismMotion and CubismExpressionMotion ownership behind
  private RAII deleters.
- Preloaded every Product V2 clip during instance construction with motion
  consistency checking, authored fade overrides, and model3 EyeBlink/LipSync
  effect IDs.
- Added SDK-free exact motion-key and expression-name lookup APIs plus clip
  counts.
- Added monotonically allocated non-zero instance serials that consume the
  terminal value and reject subsequent allocation instead of wrapping.
- Preserved the immutable resource and existing static render/snapshot boundary;
  no Render, Graphics, Asset, or Editor dependency was added.

## Validation

- cmake --build build --config RelWithDebInfo --target Live2DCoreTest --parallel 1
- build/engine/test/unit/live2d/RelWithDebInfo/Live2DCoreTest.exe --gtest_filter=Live2DAssetTest.LoadsImportedProductThroughAssetManagerDependencies
- Result: build passed and the Hiyori two-instance test passed. Each instance
  preloaded 10 motions, shared the same immutable resource, exposed exact
  lookup, and received a distinct non-zero serial.
- The prior focused L2D6.1 tests remain green after linking the motion framework.

## Remaining scope

L2D6.2 intentionally does not start or advance clips. Priority, transitions,
tokens, expression selection, cancellation, events, and the canonical parameter
update transaction remain L2D6.3.
