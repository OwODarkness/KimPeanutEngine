## Objective

Close V1 acceptance item 8 by removing the module name from Render's generic
capture contract: `CaptureView::Live2D` was a Live2D semantic value inside
Render's own capture enum, which is the exact thing that criterion excludes.

### Why the predicate is named for the pass, not for "deferred"

The first draft in the plans called this `IsDeferredCaptureView` and described it
as covering `SceneColor` plus every diagnostic view. That was wrong and the code
contradicted it: the predicate it replaces is
`view != SceneColor && view != Live2D`, so `SceneColor` classified as **false**
— it is read back directly and needs no conversion pass. A name of
`IsDeferredCaptureView` returning false for the scene color view would have been
actively misleading, so the implemented name states the actual semantics:
`RequiresCaptureViewConversionPass`. The plan and freeze journal were corrected
to match rather than left describing an unimplemented shape.

## Behavior preservation

The change is behavior-preserving, and this was argued from source rather than
assumed:

- **`SceneColor` and the ten diagnostic views**: same classification as before —
  false and true respectively.
- **`HostOutput` (formerly `Live2D`)**: was false, stays false. A `Live2D`
  request in Scene3D already reached `FixedRenderPassId::CaptureView` with
  `active_pending_capture_` empty, so the pass returned `false`
  (`deferred_renderer.cpp:713-714`), `capture_target_ready` stayed false
  (`:641-645`), and `RejectPendingCapture` ran. Unchanged.
- **`EngineWindow`**: classifies **false** now, where the negative test made it
  **true**. This is not reachable, so nothing changes: `pending_capture` comes
  from `RenderCaptureService::GetPendingView()`, which returns `nullopt` for
  `EngineWindow` (`render_capture_service.cpp:90`); and `debug_view` cannot be
  `EngineWindow` either, because `RenderSystem::SetDebugView()` refuses it
  (`render_system.cpp:582-584`). Both possible sources are therefore excluded
  before the predicate is reached.

This is the one place where the classification changed rather than being
renamed, so it is recorded here explicitly: the new value is the semantically
correct one, and the old one was unreachable.

## Tests

`RenderCaptureServiceTest.ClassifiesEveryCaptureViewExplicitly` pins every
enumerator's classification so a new view cannot silently inherit deferred
behavior, and asserts the dense range
(`EngineWindow == size - 1`) so inserting a view forces an explicit decision.
Its stated limit: appending a view after `EngineWindow` is not detectable,
because nothing exposes the enumerator count.

`RenderCaptureServiceTest.ResolvesHostOutputThroughTheCaptureTargetResolver`
proves the renamed value is still satisfied by the host's resolver rather than
by a render pass.

### Not yet evidenced

No viewer run has been performed since the rename. Item 8's criterion is a
static one and the unit coverage above pins the contract, but "the viewer still
captures correctly" is a runtime claim that this stage has not tested. It is
L2D5.2's runtime evidence and is not claimed here.

## Remaining risks

1. **The `"live2d"` tooling alias survives deliberately.** Generic runtime
   tooling still contains the string `"live2d"` as a launch-time alias for
   `host_output`. The V1 criterion names Render and Graphics, so the letter is
   satisfied and Render is genuinely clean. The spirit is only partly satisfied,
   and the alias is kept because recorded L2D4.5 validation procedures use it.
2. **`EngineWindow`'s reclassification rests on reachability, not on a test.**
   The argument above is a source-reading argument over two guards. If either
   guard is removed later, `EngineWindow` would classify as a host view and the
   deferred renderer would skip its conversion pass for an engine-window
   request. A test that drives `EngineWindow` through the deferred renderer
   would pin this; none exists, and constructing one needs a renderer harness.
3. **The string mapping is not exhaustively tested.** Checked:
   `ScreenshotCommandProviderTest` covers `scene_color`, `shadow_visibility`,
   the spot/point shadow names, `selection_mask`, and `engine_window`, but
   neither `host_output` nor `live2d`. Because `host_output` is a string this
   stage introduced, a case covering both was added rather than left to a
   runtime run:
   `ScreenshotCommandProviderTest.MapsHostOutputViewNamesToTheHostCaptureView`.
