# Live2D L2D1 SDK Integration — 2026-09-08

## Objective

Implement [L2D1](../../docs/live2d/.plan/L2D1.md): integrate Cubism SDK for
Native R5 as an optional, version-pinned module without adding Cubism
dependencies to Asset, Render, or Graphics. The module is enabled by default
for engine development and can be explicitly disabled for SDK-free builds.

## Changes

- Added `cmake/FindLive2DCubism.cmake`, validating the local SDK metadata,
  required license files, Core header, and VS2022 x64 static Core libraries.
- Added the optional `engine/module/live2d` targets:
  `Live2DCubismFrameworkRuntime`, `Live2DRuntime`, and `Live2D`.
- Compiled an audited backend-neutral Framework source subset from the external
  SDK. Official OpenGL, Vulkan, and other native renderer sources are not part
  of the target. The Framework static-release hook is a module-owned no-op
  because production rendering will use KimPeanutEngine's RHI.
- Added `CubismLifecycle` with explicit startup/shutdown state, aligned
  allocator, no-throw Core log bridge, version diagnostics, process ownership,
  repeated lifecycle support, and model-instance leases that refuse shutdown
  while instances are live.
- Added `Live2DCoreTest` for repeated initialization, shutdown protection, and
  two independent models created from one MOC definition.

## Skipped and remaining risk

- `ctest --test-dir build-live2d` was not used for the final result because this
  repository enables CTest in the `engine/test` subdirectory; the correct test
  root is `build-live2d/engine/test`.
- No rendering, Asset importer, viewer, OpenGL/Vulkan visual capture, or
  runtime DLL staging was attempted; those belong to L2D2–L2D5.
- The initial non-elevated SDK-off configure hit the known machine permission
  failure while MSBuild evaluated the local Windows SDK cache. The elevated
  retry passed.

## Editor placeholder follow-up

- Added `Live2DEditor` under `engine/module/live2d/editor`; it registers its
  editor component through the generic editor extension registry only when the
  Live2D module is linked.
- The first viewer surface is an ImGui placeholder with a lightweight animated
  character, a centered 9:16 aspect-fit canvas, and no Cubism model or GPU
  render-proxy dependency yet.
- The existing Debug Viewer was moved to the lower half of the right editor
  column so the two panels do not overlap at their first-use positions.
- Focused `Live2DEditor` compilation, the full `KimPeanutEngine` link, and the
  combined `EditorUILifecycle`/`Live2DCore` test set passed. The executable link
  still reports the existing MSVC `LNK4098` CRT warning; all generated targets
  use `/MD` and the selected Cubism Debug Core reports `MSVCRTD` directives.

## Editor registration boundary correction

- Removed the feature-specific Live2D include, compile definition, and viewer
  builder from `EditorUILib`.
- Added the generic `EditorExtensionRegistry` to `EditorUILib`; workspace
  promotion consumes registered component factories without naming Live2D.
- `Live2DEditor` owns `RegisterEditorExtensions`, which registers the
  placeholder viewer factory. The application composition root calls
  `module::RegisterModules`; that bootstrap creates `Live2DModule`, transfers
  ownership to `Engine`, and invokes the enabled module's editor registration
  explicitly. No static initializer or `/WHOLEARCHIVE` dependency is used for
  module or editor registration.
- Reconfigured and rebuilt `KimPeanutEngine` successfully after the correction.

## Engine module lifecycle follow-up

- Added the generic `EngineModule` contract with `OnRegister`, `Initialize`,
  `Tick`, and `Shutdown` callbacks.
- `Engine::RegisterModule` accepts ownership before initialization, invokes
  `OnRegister`, and schedules initialization, game-thread ticks, and
  reverse-order shutdown. Partial startup failures also shut down only the
  successfully initialized prefix.
- Added `Live2DModule` and `Live2DSystem`; the module owns the system and the
  system owns `CubismLifecycle`. `main` is the current composition root through
  `module::RegisterModules`, leaving a future dynamic loader as a replacement
  for the bootstrap function rather than an Engine API change.

## Development-default follow-up

After L2D1 validation, the Live2D CMake option was changed from `OFF` to `ON`
as the engine-development default. SDK-free configurations remain available
by explicitly passing `-DKPENGINE_ENABLE_LIVE2D=OFF`; the SDK root remains a
local cache input and no machine-specific path is stored in the repository.
