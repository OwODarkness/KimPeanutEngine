# AB1.3 — Asset Reference Viewer

## Objective

Implement the Editor-only dependency/reference viewer over the AB1.0 immutable
catalog graph, using the requested connected-card tree presentation.

## Completed

- Added `AssetReferenceViewModel` with copied node records, deterministic forward
  and reverse adjacency, stable-key roots, per-direction expansion, selection,
  bounded traversal, and deterministic Text export.
- Added explicit row kinds for shared, cycle, missing, unknown-coverage, and
  truncation facts. Runtime-only and archive-only states remain readable through
  the copied catalog labels.
- Added `EditorAssetReferenceComponent` as a separate closable floating window.
  Tree mode renders a horizontal connected-card tree with depth columns,
  parent-centered placement, elbow connectors, status dots, and annotations;
  Text mode renders the exact model export with horizontal scrolling and Copy.
- Bound browser double-click and **Open References** to the viewer root without
  loading or mutating Asset state. Locate in Browser selects the stable key and
  reopens the browser tab.
- Added **View > Asset Reference Viewer** and exposed the standalone viewer to
  the existing panel command API as `asset_reference_viewer` for deterministic
  debugging.

## Validation

- `cmake -S . -B build` passed.
- Debug `KimPeanutEngine` build passed using a clean MSBuild environment to avoid
  the host's duplicate Windows `PATH`/`Path` environment entries.
- `AssetReferenceViewModelTest` passed 8/8, including dependency ordering,
  referencer inversion, shared/cycle/unknown facts, missing-root recovery,
  limits, and deterministic text export.
- Test-level Vulkan startup used `level/performance_profile.level`; the panel
  command opened `asset_reference_viewer`, panel listing reported it open and
  floating, and `engine_window` capture completed successfully. The viewer now
  resolves its default root from Runtime's loaded level AssetID through the
  captured catalog, producing the level's actual model/material/texture tree;
  it no longer falls back to an arbitrary name-sorted material.
- The same test-level Vulkan capture verified the screenshot-style horizontal
  root-to-child tree presentation.
- `git diff --check` remains required after the final documentation edits.
