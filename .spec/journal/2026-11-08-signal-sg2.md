# Signal Lab SG2 implementation

## Ownership and operation

**Operation and acceptance:** Simulate a fixed-rate sampled source, preserve
bounded history, identify trigger crossings by absolute sample index, publish a
complete scope capture and measurements. Confirm analytic default-sine values,
trigger modes, block-boundary behavior, bounded wrap and sample-clock invariance
across presentation rates.

**Existing candidates inspected:** Runtime `SignalGenerator` owns deterministic
source samples and phase; `Measure` owns sample-block statistics. Runtime
`IApplicationHost::Tick` and `RenderPresentation` already separate game-thread
simulation from the UI. The previous SG2 plan's fixed-mode-table instructions
were stale after the global host registry work.

**Placement and reason:** New `SignalScopeSession` lives in
`engine/module/signal/tools`. Triggering, ring history, capture publication and
transport are oscilloscope policy used only by Signal Lab, not generic sample
data. The host owns the session lifetime; Runtime continues to provide only
reusable signal data operations and generic host hooks.

**Consumers, ownership/lifetime, and validation:** Host `Tick` advances the
sample accumulator and generator in 256-sample blocks. UI and host commands call
the same mutex-guarded session. The 65,536-sample ring remains private; render
loads an atomic `shared_ptr<const SignalScopeSnapshot>` whose capture storage is
immutable and independent of later ring writes. No worker or new dependency was
added.

## Implemented

- Rising/falling trigger with re-arm hysteresis, absolute sample indices,
  cross-block edge continuity and pre-trigger capture.
- Auto timeout publishes an explicitly untriggered latest window. Normal keeps
  the previous capture marked stale while waiting; Single stops at capture
  completion and requires explicit re-arm. Trigger controls include hysteresis
  and integer-sample holdoff.
- Run/Pause/Step/Reset, source controls, sample-rate control, adjustable timebase,
  trigger controls, plotted sample markers, numeric voltage/time axes, capture
  statistics, frequency with one-sample timing uncertainty and stale-state
  labels.
- Preserved the earlier generated-signal list, eye visibility and overlay/
  composite preview. Selecting a listed source also configures the scope input.
- `signal.configure`, `signal.run`, `signal.pause`, `signal.reset`,
  `signal.step`, `signal.arm` and `signal.status` use the existing host command
  registry and game-thread lane.

## Reproducible composite signal source

**Operation and acceptance:** Generate a periodic fundamental with normalized second/third harmonics and fixed-seed additive uniform noise. The generated SampleBlock and Scope acquisition must consume the same configuration; the Ideal profile must retain the pure-source path.

**Existing candidates inspected:** Runtime `SignalGenerator` already owns waveform phase, uniform-noise PRNG state, block partitioning and reset replay. Signal Lab `GenerateSignal` and `SignalScopeSession::SetSource` already pass the same `SignalGeneratorConfig` to the sample list and acquisition session.

**Placement and reason:** Extend Runtime `SignalGeneratorConfig` and `SignalGenerator` because harmonic composition and sample-noise generation are reusable sampled-signal operations. Keep profile selection and user-facing controls in `SignalLabEditor`. The host command accepts optional distortion/noise/seed settings and reports active values. No new target or dependency was introduced.

**Validation:** Debug `KimPeanutEngine` build passed. ImGui stack check, placement check and `git diff --check` passed. Unit tests and runtime visual capture were not run for this change; numeric noise/harmonic acceptance remains unverified.
