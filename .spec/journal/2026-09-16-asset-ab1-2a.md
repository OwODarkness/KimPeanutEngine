# AB1.2a — Imported Content Metadata and Catalog Boundary

## Objective

Complete the Asset-owned imported-content boundary so the browser can consume
logical metadata records without enumerating raw source files or exposing
hash-named archive products as normal rows.

## Implemented

- Extended content metadata with an optional numeric `AssetType` value and a
  registry snapshot flag for content-root ownership.
- Added a pure content-to-catalog builder that publishes visible, ready
  records with persistent `ContentID` keys, product facts, and ContentID
  dependency edges.
- Filtered internal and shader records, rejected invalid or missing product
  closures, and emitted validated missing-reference diagnostic leaves.
- Wired the provider to capture content metadata only during explicit catalog
  capture. An existing `content/` directory is authoritative, including when
  empty; repositories without it use the AB1.1 projection as a migration
  fallback.
- Kept the Runtime boundary unchanged: no content registry or browser capture
  is constructed during Runtime startup.
