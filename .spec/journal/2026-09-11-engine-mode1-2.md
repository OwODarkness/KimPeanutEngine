# Engine MODE1.2 — scene-host isolation

## Objective

Make the traditional scene path explicit as the Runtime-owned `Scene3DHost`
composition and ensure `scene3d` does not register or render the Live2D viewer.
Preserve the existing deferred/PBR behavior while the deeper
`RuntimeContext` ownership extraction remains incremental.

## Landed

- Added `Scene3DHost` under `engine/runtime/host/` as the built-in
  `IApplicationHost` for `ApplicationMode::Scene3D`.
- Engine creates the built-in host, drives its lifecycle, and shuts it down
  through the existing startup/Run/Clear paths.
- `ModuleBootstrap` registers `Live2DModule` and the Live2D editor viewer
  extension only for `ApplicationMode::Live2DViewer`. Scene mode therefore
  cannot install the Live2D `IRenderExtension` into `RenderSystem`.
- Kept `RuntimeContext`, `RenderSystem`, Gameplay ticking, deferred/PBR
  recording, and scene editor presentation unchanged behind the compatibility
  host shell. No Live2D code was added to Runtime.
- Added positive scene-host lifecycle and negative viewer-mode unit coverage.

## Validation

- `cmake --build build --config Debug --target RuntimeLaunchOptionsTest`
  passed after CMake regeneration.
- `RuntimeLaunchOptionsTest.exe` passed all 9 tests.
- `cmake --build build --config Debug --target KimPeanutEngine` passed.
- `GraphicsSmoke.exe` passed `Graphics smoke (6 frames/API): passed` on both
  Vulkan and OpenGL. Its existing geometry-view/depth-format diagnostics remain
  pre-existing smoke output and did not change the final pass result.
- A direct `scene3d` engine launch reached the running process with the checked-in
  `sponza.level`; the earlier `point_shadow_validation.level` attempt was not
  used as evidence because its current asset archive is incomplete.

## Remaining limitation

`Scene3DHost` is currently the explicit lifecycle shell; the concrete
`RuntimeContext` members and full scene render-thread recording are still
physically stored in `Engine`/`global_runtime_context`. Moving those members is
the next safe extraction step after the standalone Live2D host has a shared
service view.
