# Live2D L2D2 Asset Integration — 2026-09-08

## Objective

Implement the Live2D-specific consumer side of AX1 using the source package at
`asset/live2d/hiyori_pro/runtime`, while keeping Asset generic and preserving
AssetManager transaction ownership.

## Changes

- Added `Live2DModelResource : asset::IAssetPayload` with immutable `.moc3`
  bytes, ordered texture paths, and named optional source chunks.
- Assigned the stable custom Asset value `0x1000`, registered the `live2d`
  native suffix and loader through `AssetManager::RegisterAssetType`, and
  registered the `model3.json` provider through `ImportProviderRegistry`.
- Added a bounded version-1 little-endian `.live2d` product codec. The loader
  only fills `AssetRegisterInfo` and declares texture dependencies; it does not
  allocate IDs, recurse into AssetManager, or create Cubism objects.
- Added a database-free source provider that validates the model3 document,
  keeps texture order, reads the MOC and optional referenced files, rejects
  root escapes/missing files, and emits deterministic product bytes.
- Composed runtime registration in `Live2DModule::OnRegister`; Asset source
  remains free of Live2D names and branches.
- Split CMake ownership into `Live2DProduct`, `Live2DImport`,
  `Live2DRuntime`, and `Live2DRegistration`; the aggregate `Live2D` target
  preserves the existing consumer seam while the importer no longer belongs
  to the Cubism lifecycle target.
- Added `Live2DSystem::CreateInstance(AssetID)` and the opaque
  `Live2DModelInstance`. Each instance owns its Cubism MOC/model and lifecycle
  lease while retaining the shared immutable `Live2DModelResource`.

## Reference gate

- Local reference index: Piccolo is the closest Asset → resource precedent;
  Sakura's Live2D resource header was inspected for its resource/renderer
  split.
- GitHub sources inspected: `BoomingTech/Piccolo` `asset_manager.h` at the
  current main snapshot, and `SakuraEngine/SakuraEngine` `l2d_model_resource.h`
  plus `l2d_model_resource.cpp` at commit
  `c0fdb2bb30074058cb98df98b8134559d13d67b0`.
- Applicable conclusion: retain immutable model data in the resource boundary
  and keep model/render state in the Live2D module. KimPeanutEngine therefore
  does not copy Sakura's framework-owned mutable model pointers into Asset.
