## What was done

### 1. Generic submission execution seam

- Added [`render_submission_frame.h`](../../engine/runtime/render/render_submission_frame.h):
  `UniformAllocation` moved here from `frame_context.h` plus the
  `RenderSubmissionFrame` interface (uniform allocation, sampled-texture
  binding, buffer writes, frame-active state). This is what makes submission
  execution testable without a graphics backend.
- `FrameContext` is the production implementation
  ([`render_submission_frame_context.cpp`](../../engine/runtime/render/render_submission_frame_context.cpp)).
- `RenderSubmissionExecutor` gained `ExecuteOn(submission, RenderSubmissionFrame&, CommandRecorder&)`
  alongside `Execute(submission, FrameContext&, CommandRecorder&)`, and a
  `RenderSubmissionExecutionResult { succeeded, diagnostic, pass_count, draw_count,
  upload_bytes, uniform_bytes, binding_count, partial_output }`.

### 2. Failure semantics (executor)

Every failure path now fails **before** publishing work rather than midway:

- structurally invalid work is rejected before preparation;
- uniform/binding/upload exhaustion records **zero** passes;
- a rejected bind or target begin closes the active target and sets
  `partial_output`, so a caller never presents a partially recorded frame.

### 3. Live2DRenderer hardening

- `ResizeOutput` is transactional: the replacement target and its view are
  created and validated first, the old handle is released only after the safe
  wait, and a failed create leaves the previous target usable.
- Topology/revision guards reject a submission whose snapshot revision,
  topology revision, or frame sequence does not match the proxy the renderer
  owns.
- Mask over-capacity and missing-atlas resource sets produce a stable
  unsupported diagnostic with zero GPU publication.

### 4. Colour-space and readback correctness (the parity fix)

The two backends stored different bytes for identical input. Root cause chain,
in the order it was found:

1. `live2d_color.frag` / `live2d_masked.frag` hand-applied an sRGB encode under
   `#if KP_GRAPHICS_API_VULKAN`, while the OpenGL product target was
   `RGBA8_UNORM`. Measured divergence: **max 74/255, mean 18.45/255**, with
   OpenGL numerically equal to `srgb_to_linear(Vulkan)`. Live2D textures are
   `RGBA8_SRGB`/`BC3_SRGB`, so the Vulkan look was correct — the shader encode
   was removed and the product target made `RGBA8_SRGB` on both backends.
2. Residual **max 23/255 confined to the background** (OpenGL corner `3,3,3`
   vs Vulkan `26,26,26`): `EndRenderTarget` leaves `GL_FRAMEBUFFER_SRGB`
   disabled, so the clear bypassed the encode while `OpenglPipeline::Bind()`
   re-enabled it for draws. Fixed by enabling it in `BeginRenderTarget` when
   colour attachment 0 is an sRGB format.
3. Vulkan product readback failed outright ("render-target readback source is
   invalid") because `VulkanRenderTargetManager::CanReadback`/`GetReadbackSource`
   hardcoded `TEXTURE_FORMAT_RGBA8_SRGB` while the product target was
   `RGBA8_UNORM`, and OpenGL's readback had no format check at all. The copy
   path is format-agnostic, so the SRGB-only lock was unjustified; both now
   gate on `IsRgba8TextureFormat`.
4. Captures with a transparent clear had alpha 0 on every pixel, making blend
   coverage unobservable. `BlendFor` emitted `(ZERO, ONE)` alpha factors for all
   modes, leaving destination alpha at the clear value;
   `NormalizeLive2DBlend` documents `a = src.a + dst.a*(1-src.a)` for Normal
   (Additive/Multiplicative document `a = destination.a`). Only Normal was
   wrong. Fixed to `(ONE, ONE_MINUS_SRC_ALPHA)`.

New predicates `IsRgba8TextureFormat` / `IsSrgbTextureFormat` in
[`core/base/graphics_type.h`](../../engine/runtime/core/base/graphics_type.h)
let both backends derive the transfer from the format.

### 5. Shutdown crash — a dangling SDK option pointer

Finding a real defect, not just a missing measurement. The plan's matrix row
"Shutdown after submitted frame" had no evidence because every previous viewer
run was killed by `timeout`, so the shutdown path had *never executed*. Adding
`--exit-after-capture` to make the viewer stop on its own produced a segfault
(exit 139) after a successful capture, with stdout entirely lost (block-buffered
output is not flushed by a hard fault).

`cdb` gave the stack:

```
CubismFramework::GetLoggingLevel+0x13      <-- fault: reads [rax+8], rax stale
CubismDebug::Print+0x4a
CubismFramework::Dispose+0x70              <-- the trailing CubismLogInfo
CubismLifecycle::Shutdown
Live2DSystem::Shutdown
Live2DViewerHost::Shutdown
Engine::ShutdownApplicationHost / Engine::Clear / main
```

Root cause, in the SDK's contract: `CubismFramework::StartUp(allocator, option)`
stores the **address** of the caller's `Option`
(`s_option = option;`, `CubismFramework.cpp:61`) and every later SDK log call
reads `s_option->LoggingLevel` back through it — including the
`CubismLogInfo("CubismFramework::Dispose() is complete.")` at the *end* of
`Dispose()`. `CubismLifecycle::Initialize()` passed a stack local
(`auto option = MakeFrameworkOption();`), so the pointer dangled the moment
`Initialize()` returned. The unit tests never caught it — they passed both
before and after the fix — and the likely reason is that their call chain was
shallow enough for the stale stack region to stay mapped and unmodified, so the
read returned old bytes instead of faulting. The viewer's deeper
`Engine::Clear → Shutdown → …` chain reused that memory, turning the read into
an access violation. That difference is exactly why the unit suite is not
evidence that this path is safe.

Fix: give the option static lifetime (`static const auto option =
MakeFrameworkOption();`), matching what the same file already does for the
allocator (`GetAllocator()` returns a function-local static — the lifetime
hazard was recognized for the allocator but not for the option).

This is undefined behaviour on every `Shutdown()`, not viewer-specific; the
viewer is just where it became observable.

### 6. Capture tooling

- New launch options `--capture-view window|live2d`,
  `--capture-alpha opaque|transparent`, and `--exit-after-capture` (viewer mode
  only, all three requiring `--capture`).
- [`tools/compare_capture_regions.py`](../../tools/compare_capture_regions.py)
  reports sha256, dimensions, and per-region statistics for non-edge opaque,
  partial alpha, transparent background, and filtered edge.

## What changed

- **Architecture:** submission execution is now split from frame services —
  `RenderSubmissionExecutor` talks to `RenderSubmissionFrame`, and `FrameContext`
  is one implementation of it. Failure is pre-publication, with `partial_output`
  telling the caller whether a frame bracket needs discarding.
- **Ownership:** `Live2DRenderer` owns the output target transactionally; a
  failed resize keeps the previous target alive. No Live2D handle crosses into
  Render or Graphics.
- **Lifetime:** the Cubism framework `Option` now has static lifetime, so the
  pointer `CubismFramework::StartUp()` retains stays valid through
  `Dispose()`'s trailing log call. Previously the SDK held a pointer into a
  returned stack frame — undefined behaviour on every shutdown, fatal in the
  viewer.
- **Public API:** `RenderSubmissionExecutor::Execute` now returns
  `RenderSubmissionExecutionResult` rather than a bare bool;
  `UniformAllocation` moved from `frame_context.h` to `render_submission_frame.h`
  (breaking for a translation unit that included only the former — nothing in
  the tree did); `engine::Runtime` gained
  `Set/GetStartupCaptureView`, `Set/GetStartupCaptureTransparentClear`,
  `Set/GetStartupExitAfterCapture`; `RuntimeLaunchOptions` gained
  `startup_capture_view`, `startup_capture_transparent_clear`, and
  `startup_exit_after_capture`.
- **Important files:** `engine/runtime/render/render_submission_frame.h`,
  `render_submission_frame_context.cpp`, `render_submission_executor.{h,cpp}`,
  `frame_context.h`, `engine/module/live2d/render/live2d_renderer.{h,cpp}`,
  `engine/module/live2d/live2d_viewer_host.{h,cpp}`,
  `engine/module/live2d/runtime/live2d_cubism_lifecycle.cpp`,
  `engine/runtime/launch_options.{h,cpp}`, `engine/runtime/engine.h`,
  `engine/editor/main.cpp`, `asset/shader/live2d_{color,masked}.frag`,
  `engine/runtime/graphics/backend/common/buffer_types.cpp`,
  `engine/runtime/graphics/backend/opengl/{opengl_command_recorder,opengl_pipeline}.cpp`,
  `engine/runtime/graphics/backend/vulkan/vulkan_render_target_manager.cpp`,
  `engine/editor/log/editor_log_component.cpp`.

### Cross-backend region comparison

Opaque product capture (tolerance 2/255):

| Region | Pixels | max abs | mean abs | over tolerance |
|---|---|---|---|---|
| non-edge opaque | 691200 | 2 | 0.0001 | 0 |
| partial alpha | no pixels | — | — | no such pixels under an opaque clear |
| transparent background | no pixels | — | — | no such pixels under an opaque clear |
| filtered edge | no pixels | — | — | no such pixels under an opaque clear |

The comparator prints `no pixels` for a region the clear makes unreachable —
an opaque clear has no partial, transparent, or edge coverage to compare. Only
114 of the 691200 pixels differ at all (0.02%), none by more than 2/255, and
`channels_over_tolerance=0`.

Transparent-alpha capture (tolerance 2/255, edge tolerance 4/255):

| Region | Pixels | max abs | mean abs | over tolerance |
|---|---|---|---|---|
| non-edge opaque | 95140 | 2 | 0.0004 | 0 |
| partial alpha | 2292 | 1 | 0.0022 | 0 |
| transparent background | 589771 | 0 | 0.0000 | 0 |
| filtered edge | 6289 | 1 | 0.0010 | 0 |

Region coverage sums to the full 691200 pixels (`transparent=589771 partial=2292
opaque=95140 edge=6289`), so the regions partition the image rather than
sampling it — a disagreement cannot hide in an unclassified pixel. 117 pixels
differ overall (0.02%), max 2/255.

Every region is inside the frozen L2D4.0 tolerances
(`kLive2DRenderCpuTolerance = 1.0e-5f`,
`kLive2DRenderBackendTolerance = 2.0f/255.0f`,
`kLive2DRenderMaskEdgeTolerance = 4.0f/255.0f`). The residual 1–2/255 spread is
ordinary rasterization-order difference in sources-sampled-alpha blending, not
a coordinate, gamma, blend, or mask-polarity disagreement — the transparent
background matches at exactly 0, which a gamma or blend error could not produce.

## Remaining risks and unverified areas

1. **`LevelLoaderTest.LoadsCheckedInGameplayLevelFixtures` fails in the full
   run** (508/509). The error is
   `objects[0].model (logical model is not present in the archive: model/rock1-bl/rock2)`.
   `asset/.archive/archive.sqlite3` (gitignored) contains three Sponza sources;
   no CMake step generates that archive — it is produced by `KimPeanutAssetTool`.
   This change touches no asset, archive, or importer code. It is a pre-existing
   content gap from the AT1.x Sponza re-imports and needs an
   `model/rock1-bl/rock2` asset-tool import to close.
2. **`CaptureView::Live2D` remains in the generic capture enum**
   ([`render_capture_service.h`](../../engine/runtime/render/render_capture_service.h),
   referenced at `deferred_renderer.cpp:613`). Generic Render capture code
   therefore still names a module. Already flagged in the MODE1.5 journal;
   removing it is a Render-side follow-up, not an L2D4.5 edit.
3. **The presentation-view capture path is unreachable in the standalone
   viewer.** `SetPresentationTarget` is only ever called with `false`
   (`live2d_viewer_host.cpp:127`), so `proxy_.output_to_presentation` and the
   `output_color_format_` presentation branch are constant. Validation used the
   Product view. The `--capture-view window` path is written and parsed but not
   exercised end to end.
4. **Target resize has no evidence at all, and shutdown accounting has no
   automated test.** `Live2DRenderer::ResizeOutput` is the weaker of the two:
   no test calls it and no run resizes the target, so the plan's "old target
   released only after safe wait" claim rests purely on reading the code. This
   is the one hardening-matrix scenario that did not reach its required evidence
   level. Shutdown is better off — four runs exit 0 reaching
   `CubismFramework::Dispose() is complete.` with no `... module GPU handles
   still live` warning — but a clean log is an observation, not an assertion
   that would fail a build.
5. The `--capture-alpha` transparent path required the blend-factor fix above;
   without it the exported image carries no coverage information. There is no
   test that would catch a regression of that factor.
6. **The comparison does not prove all three blend modes are exercised.** The
   plan asks for partial-alpha overlap "for all blend modes". The partial-alpha
   region passes (2292 pixels, max 1/255), but nothing in the fixture or the
   comparator asserts that Hiyori's configured drawables actually use Additive
   and Multiplicative — the counters report draw count, not blend distribution.
   A synthetic fixture covering all three modes is the way to close this.
7. **Cross-backend agreement is not official-reference agreement.** Every
   capture here compares OpenGL against Vulkan. The official-R5 comparison
   remains blocked on a licensed fixture with no built sample executable, and is
   not recorded as passing.

## Remaining work

- Cover `Live2DRenderer::ResizeOutput`: a test for the transactional create and
  the keep-the-old-target-on-failure path, plus a viewer run that actually
  resizes. This is the only hardening-matrix scenario with no evidence.
- Assert the shutdown handle count is zero in a test, rather than inferring it
  from the absence of a warning line. The self-terminating half of the original
  item landed as `--exit-after-capture`.
- Import the missing `model/rock1-bl/rock2` asset so the LevelLoader fixture
  passes.
