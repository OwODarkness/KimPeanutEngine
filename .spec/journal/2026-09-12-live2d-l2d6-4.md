# L2D6.4 Playback Hardening and L2D7 Handoff — 2026-09-12

- Status: implementation baseline; acceptance gate remains open for the missing synthetic/SDK-off evidence.
- Scope: harden the instance-local playback adapter without changing Render,
  Graphics, Editor, Asset core, or the standalone viewer host boundary.

## What landed

- Split `AdvancePlayback` into named internal phases:
  `LoadParameterCheckpoint`, `ApplyPendingParameterWrites`,
  `UpdatePrimaryMotion`, `SavePrimaryCheckpoint`,
  `UpdateExpressionContribution`, `ApplyLateUpdateContributors`, and
  `UpdateModel`.
- Kept the persistent checkpoint after primary motion and before expression and
  late contributors. The late-update method is the L2D7 insertion point.
- Rejected invalid delta time before moving pending events or touching Cubism;
  negative delta coverage verifies parameter values remain unchanged.
- Added explicit bounded event-storage reservation and callback-overflow checks.
- Made immediate `StopMotion` token-local by finishing only the selected SDK
  queue entry. It no longer replaces the whole motion manager, so overlapping
  replacement fades remain cancellable independently.
- Kept `StopAllMotions` on the existing manager and added stable Product V1
  reimport-required diagnostics for typed motion/expression lookup misses.
- Added regression coverage for invalid delta atomicity and two simultaneous
  immediate cancellations.

## Remaining gate items

- No deterministic synthetic motion fixture yet covers the full priority/fade/
  expression numeric matrix described by L2D6.3.
- Product V1 instance-level reimport-required behavior and an SDK-off build still
  need explicit evidence.
- The one-shot viewer capture proves initialization, submission, and shutdown;
  a controlled full-duration authored-motion capture still needs a fixture or
  runtime command that waits for completion before capture.
- No Render or Graphics source was changed by this stage.

assets. Runtime playback remains instance-owned; immutable product data remains
