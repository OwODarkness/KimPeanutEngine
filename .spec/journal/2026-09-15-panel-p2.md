## Objective

Make the panel visible for the first time. P0 and P1 produced a representation
and real baked glyphs, but nothing drew them: `ToAsciiArt` was the only way to
see any output, and both panel libraries were linked by tests alone.

## 1. Core: single-channel payloads

`BytesPerPixel` returned 0 for `R8_UNORM`, so `IsTextureMipChainValid` demanded
empty pixels and `TextureManager::CreateTexture` rejected any R8 texture that
carried a payload.

Before changing it, the allocation-only path was checked, because it is what
makes the G-buffer object-mask attachment legal: `CreateTexture` tests
`IsGpuAllocationOnlyTexture` **first** and skips validation entirely, so an
empty-pixel R8 texture is unaffected. `LeavesAllocationOnlyR8ToTheTextureManagerGuard`
pins that boundary explicitly — the validator still rejects an empty R8 payload,
because it is not the thing that makes allocation-only textures legal.

The change is deliberately not exhaustive: the other uncompressed formats still
return 0, and the comment says so, so a reader does not mistake the function for
a complete table.

## 2. Planner and renderer

The planner is CPU-only and compiles without Render or a backend, in the same
shape as `Live2DRenderPlannerTest`. Seven tests assert the pass is a target (never
presentation), that both descriptors sit at set zero, that the viewport covers
the output, that no scissor is set, and that a missing pipeline, mask, sampler,
target, vertex buffer, index buffer, index count, or output extent each produce a
failed plan with **no** published work.

The renderer test reuses `engine/test/support/fake_render_backend.h`, extracted
during L2D5.2. Ten tests cover handle minting, the recreate-and-release mask swap,
transactional resize, failed-create paths, and cleanup.

Two problems surfaced while writing it:

- **The probe has no texture-destroy event.** So "the previous mask was released"
  cannot be asserted directly. It is asserted indirectly and more strongly: the
  live handle count must be *unchanged* across an upload, which a leak would
  grow.
- **`Record` needs an active frame.** Four tests failed with "render submission
  requires an active frame context" until the harness bracketed the call with
  `frame.Begin`/`frame.End`, as the Live2D harness does. The bracket is part of
  the production sequence, not test scaffolding.

`panel_renderer_test.cpp` also needed `copy_runtime_dependencies`, because
linking Render pulls a runtime DLL and the executable could not start at all —
gtest reported a *discovery* failure rather than a build error, and the raw
process exit was 127 with the reason only visible outside the pipe.

## 3. Hosting

The panel gets its own application mode rather than being loaded by the Live2D
viewer, because that would make one module depend on the other.

**The first run crashed**: `Assertion failed: global_editor_context.window_system_`
at `engine/editor/editor.cpp:49`. `Engine::Initialize` branches on the application
mode, and only `Live2DViewer` was enumerated as a standalone viewer. Rather than
add `PanelViewer` to each check — and leave the same trap for the next mode —
the concept was named once as `Engine::IsStandaloneViewerMode()` and all three
branches now use it. `Engine::SetStartupCaptureOverride` had the same problem and
was generalized the same way.

Two build errors were mechanical: `CommandRegistration` is move-only, so the
command provider's results could not be `const`; and `PanelRenderer` had to be
included rather than forward-declared, because the host owns a `unique_ptr` to it.

## 4. The captures

Both backends, `--capture-view live2d` (the product view), `--exit-after-capture`:

```
opengl   panel-p2-opengl.png        21291 bytes  md5 dd34f4419f5e0ae821f1745ab45db5e9
vulkan   panel-p2-vulkan.png        21291 bytes  md5 dd34f4419f5e0ae821f1745ab45db5e9
```

At 512x256 dots with a 1024x512 target, one dot is two pixels. The capture was
decoded back to its dot grid, independently of the engine:

```
.........................
..####............####...
.##..##..........##..##..
.#....#..........#....#..
.#....#..........#....#..
.#....#..#....#..#....#..
##....#..##..##.##....#..
.#....#...#..#...#....#..
.#....#...#..#...#....#..
.#...##...###....#...##..
.#####.....##....#####...
...##......##......##....
.........................
```

Two identical `O`s, a distinct `v`, ink at dot columns 0-22 and rows 3-13, and
79 lit dots — matching the host's own logged `lit 79` exactly. It is upright, not
mirrored, which also confirms the vertex shader's V flip was the right way round.

Mixed content, both backends:

```
opengl   panel-p2-cjk-opengl.png  md5 16996c79c16845e3bcbda9ca204c6f1c  lit 193
vulkan   panel-p2-cjk-vulkan.png  md5 16996c79c16845e3bcbda9ca204c6f1c  lit 193
```

Decoded, `OvO 中文` renders as `OvO` (halfwidth, 24 dots) followed by `中` and `文`
(fullwidth, 16 dots each), 63 dots wide in total.

**The two backends agree byte-for-byte**, not merely within the frozen tolerances.
That is a stronger result than Live2D ever produced and is expected here: a flat
colour, NEAREST sampling, and no filtering leaves nothing for the backends to
disagree about. `live_gpu_handles 6` in every run — pipeline, sampler, two
buffers, dot mask, output target.

Captures are under `save/screenshots/validation/`, which is git-ignored.

## 5. Corrections to earlier claims

- **`--capture-view live2d` now means the product view for the panel too.** The
  option is owned by whichever standalone host runs; only the options naming one
  host's own content are exclusive to it. The spelling is a misnomer for a panel
  run and is recorded as an open decision rather than changed, since a neutral
  spelling would touch Live2D's documented surface.
- **Error messages changed** from "only valid in live2d-viewer mode" to "only
  valid in a viewer mode" for the capture, resize, and exit options. No test
  pinned those strings; the checks were made before changing them.

## Remaining risks

1. **Outline rasterisation at 16x16** is legible but coarsens ASCII strokes. A
   bitmapped CJK font would be crisper; the product format does not change.
2. **The glyph product is local and non-redistributable**, so the captures above
   are reproducible only on a machine with a CJK face at the configured path.
3. **`R8_UNORM` is now payload-valid.** Other uncompressed formats still return
   zero bytes per pixel from `BytesPerPixel` and are accepted only as
   allocation-only textures. That is recorded in the code, not fixed.
4. **No Asset-system registration.** The host reads the product directly, so the
   panel is not yet part of the asset dependency graph.
5. **`.gitignore` carries both this stage's shader exceptions and an unrelated
   uncommitted change of the user's.** They will be in the same file until the
   user's change is committed separately.
