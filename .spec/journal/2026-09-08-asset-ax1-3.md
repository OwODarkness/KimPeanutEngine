# AX1.3 — Offline importer registry journal

Date: 2026-09-08

## Objective

Add the offline provider composition boundary described by AX1.3 without
coupling AssetRuntime to importer selection, product publication, or archive
transactions.

## Design and reference gate

The local design review confirmed that `ModelImportService` already owns model
publication and SQLite transactions, while `TextureImporter`/`TextureCooker`
are database-free typed stages. Native material conversion consumes an
`ImportedModelDocument`, so it is not a standalone source-path importer and
remains a model-stage operation.

The reference-repository gate inspected:

- Godot `ResourceFormatLoader` in
  `core/io/resource_loader.h`: format loaders expose recognized extensions,
  path recognition, type handling, and loading callbacks through a composable
  interface.
- O3DE `AssetBuilderSDK.h`: builder descriptors combine a stable name/version,
  source patterns, create/process callbacks, and explicit product/dependency
  outputs.

KimPeanutEngine adopts only the applicable composition pattern. It keeps the
AX1.3 contract smaller and database-free: source suffixes, stable provider ID
and version, provider kind, and one callback. It does not adopt either
reference engine's global object database, job scheduler, platform model, or
runtime loader behavior.

## Landed changes

- Added the standalone `AssetImportRegistry` target and its
  `ImportProviderRegistry` contract. It has no AssetRuntime, SQLite, or archive
  link.
- Added normalized provider registration and one-way sealing. Explicit IDs
  bypass automatic matching; automatic matching chooses the longest compound
  suffix and rejects equal-length ambiguity.
- Added `IImportProduct`/`TypedImportProduct` so provider results remain
  extensible without a closed result variant.
- Added model and texture adapters. Model adapters preserve the typed model
  service and progress callback. Texture adapters decode, cook, and publish
  immutable products through AssetImport-owned code.
- Routed `KimPeanutAssetTool import` and `cook-texture` through the provider
  registry. Runtime loading was not changed.
- Added focused registry tests for compound suffix precedence, explicit
  selection, ambiguity, execution, and late-registration rejection.
- Added an adapter integration test that registers the existing model and
  texture services and verifies texture publication through AssetImport.
